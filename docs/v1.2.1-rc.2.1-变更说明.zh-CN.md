# FeatherAgent 1.2.1-rc.2.1 变更说明

> 日期：2026-11-24 ｜ 基线：`v1.2.1-rc.2` ｜ 类型：Windows 复测补丁 / 回归修复

本版处理 `v1.2.1-rc.2` 真机复测后确认的两项回归，以及同一份报告中的 review-gate 质量问题 G1–G3。R1 门禁阈值、provider 端点与发布资产布局均不变。

## 修复

### R-01 · Ollama 模型列表 404（自 rc.1 起的回归）

- 现象：原生 Ollama 下 `provider.models` 返回空列表，TUI `/settings` 与 WebUI 设置页都没有模型可选。
- 根因：`provider_http("ollama", "probe", ...)` 对所有 base URL 都请求 `{base}/models`；原生 Ollama 的列表端点是 `GET /api/tags`，`/models` 是 OpenAI 兼容路径，会 404。
- 修法：provider 为 `ollama` 且 base URL 不是 `/v1` 兼容形式时，probe 改走 `{base}/api/tags`；OpenAI 兼容 base 继续用 `{base}/models`。原生 `models[].name` 解析不变。
- 覆盖：单测断言请求行是 `GET /api/tags` 并解析出模型名；集成测试经内核调用 `provider.models`，同时核对返回结果与 mock 收到的路径。

### R-02 · TUI 无法设置 review-gate

- 现象：`/settings` 只有 provider/base/model/Key/温度/上下文/回合/工作区/auto-allow；review-gate 只能在 WebUI 改或手改 `data/config.json`。
- 修法：TUI 设置表单新增 9 个 review 字段：启用、最大轮次、guide 模型/温度、exec 模型/温度、judge 模型/温度，以及保存/取消。
  - `Enter`/`Ctrl+S` 通过一次 `config.set` patch 保存 `review_gate.enabled`、`max_rounds` 与三个角色。
  - `Space` 切换启用；`←/→` 调整轮次/温度，并从 `provider.models` 循环选择 review 模型。
  - 保存前校验温度区间：guide `0.20–0.50`、exec `0.60–1.50`、judge `0.00–0.20`；轮次 `1–5`。
  - 19 个字段的表单支持纵向滚动，80×24 终端下当前字段始终可见。
- WebUI 提示与 TUI 底部提示注明：guide/judge 建议使用 ≥7B 模型，4B 可能无法产出合规 rubric。

### R-03 · rubric 的 check 是自由文本（G1）

- `review.guide` 现在强制每条验收项输出 `must_include`：1–40 字的字面短语，必须逐字出现在最终答案中，优先结论句、文件名、命令或专有名词；`check` 必须复述该字面短语。
- `review.parse_rubric` 拒绝没有字面判据的 rubric：既没有 `must_include`，也无法从 `check` 的 `『』`、`「」`、反引号或引号中提取短语；同时拒绝超过 40 字的字面短语。
- 调用 judge 前，内核先执行 `review.hardcheck`：`must_include` 未逐字出现即确定判失败，该条不再调用 judge。
- 修订反馈现在带上失败项的 `criterion` 与 `check`，exec 能看到具体判据，不再只收到一句短 evidence。

### R-04 · judge evidence 为空或没有意义仍被采信（G2）

- `review.parse_verdict` 要求每条 item 的 `evidence` 和顶层 `evidence` 都至少 10 字；`"总结"`、`"通过"`、`"ok"` 等占位值按 judge 失败处理。
- evidence 过短或审批 JSON 不合格时，`review_judge` 用同一 rubric 重试 judge 一次；两次都失败才标记 degraded。
- `review_model_call` 对 review 路径的空响应自动重试一次，与普通对话的空响应策略一致。
- `review_prepare` 在 rubric 解析/校验失败时重试 guide 一次，不再立即 degraded。
- judge prompt 已删除 `"evidence":"总结"` 的示例诱导，改为要求引用答案原文且至少 10 字。

### R-05 · `chat.finished.status` 掩盖 unapproved/degraded（G3）

- review-gate 启用且回合正常结束时，`chat.finished.status` 现在反映真实结果：
  - `ok`：approved，或 review 未启用；
  - `unapproved`：已评审但达到轮次上限仍未通过；
  - `degraded`：guide/judge 连续两次失败或 review 基础设施失败。
- `review` 对象新增 `status: approved|unapproved|degraded`；`review.verdict` 新增规范化的 `items`（含 `criterion`/`check`）。
- `chat` CLI 对 `unapproved`/`degraded` 非零退出（原本就把 `chat.finished(status != ok)` 视为失败）；用户停止/取消的回合保持原 status。

## 保留 rc.2 修复

rc.2 的修复全部保留，并已被同一份报告复测确认：`/api/chat` 与 `/api/embed` 的请求体与 `Content-Length`、`enabled=false` 时仍校验 review 温度、启动打印生效 model/provider/base URL 及来源、embedding 使用当前模型。
