# FeatherAgent v1.2.1-rc.3.2 changes

This candidate fixes the three findings (J1–J3) from the Windows real-hardware retest of `v1.2.1-rc.3.1`. The rc.3.1 retest confirmed the previous fixes: real 7B review-gate moved from 4/4 `degraded` to **1/3 approved + 2/3 unapproved**, the guide succeeded on the first attempt (`attempts:1`), soft rubrics fell back to judge-only with `review.warn`, and judge evidence was a verbatim window of the answer. The remaining defects were about counting and wording, not architecture.

## J1 · `min_points` false kills (🟠)

**Symptom.** Two of three rounds were rejected with `答案只有 1 个要点，至少需要 2 个`, although the answer contained three semicolon-separated points. The old counter only looked at line-start list markers.

**Fix.**
- `count_points` now takes the maximum of four views: line-start `- * + • ·` and numbered markers, line-start bold sub-headings, `；`/`;`-separated clauses of at least 6 characters, and blank-line paragraphs; capped at 12.
- `review.hardcheck` no longer turns a `min_points` shortfall into a hard failure. It returns the item in a `soft` array instead.
- The engine emits `review.warn` (`min_points 机器计数不足，交 judge 复核：〔c2〕…（机器计数 1/2 个要点）`) and appends `[机器计数提示]` to the judge input, asking it to check the answer's actual content rather than list symbols alone.
- The judge still has to return an evidence window from the answer, so "放水" remains bounded by `parse_verdict`.

## J2 · rubric ids copied into the answer (🟠)

**Symptom.** The exec model wrote `**c1.**`, `**c2:**`, `-**c3. …**` into its answer. Root cause: `review.feedback.text` labelled failed items as `- c1:` / `- c2:`, which the model read as a template.

**Fix.** Feedback now uses `〔1〕` / `〔2〕` labels, never a bare `cN`, and ends with an explicit line: `注意：上面的〔1〕〔2〕只是给你看的序号，不要把它们写进答案正文，也不要用 c1/c2 这类编号当小标题。` The `review.feedback` event payload keeps `failed` ids for traceability; only the text sent to the model changed.

## J3 · Bench numbers not comparable across time (🟡)

**Symptom.** After a long test session the machine throttled: rc.3 and rc.3.1 both showed 108–314 ms warm boot, write P95 ≈ 10 ms and RPC P95 up to 1.5 ms, while the same rc.3 machine measured 45.6 ms earlier. The numbers were environment drift, not a version regression.

**Fix.** `bench --json` now carries `metrics.env` and the human output prints one fingerprint line:
- `captured_at_unix_ms`, `cpu_count`;
- Linux: `loadavg_1m/5m/15m`, `mem_total_kb`, `mem_available_kb`, `uptime_s`;
- Windows: `mem_total_kb`, `mem_available_kb`, `mem_load_pct`, `uptime_s` via `GlobalMemoryStatusEx` / `GetTickCount64`.

Gates and thresholds are unchanged. The fingerprint makes a degraded host visible; it does not make a bad run pass. A release baseline should still be taken on a freshly restarted machine.

## Display name

`featheragent-tui version` and `featheragent-webui version` now print `FeatherAgent TUI <v>` / `FeatherAgent WebUI <v>`. Binary names, subcommands, package names and paths are unchanged; only the user-visible product name changed.

## Compatibility

- `review.hardcheck` gains a `soft` array; it is a plugin-internal result, not a wire message.
- `review.warn` semantics extend to machine-count fallback; the event code (29) and fields are unchanged, `text` now also carries `min_points 机器计数不足…`.
- Feedback text format changed; `failed` ids in the `review.feedback` payload are unchanged.
- Bench JSON adds `metrics.env`; consumers that ignore unknown fields are unaffected.
- No provider, storage, tool or IPC frame changed.

## Verification

- Linux: exact test counts are recorded in `docs/Verification-Report.md`. New coverage: `count_points_recognizes_chinese_inline_enumeration`, `min_points_is_soft_and_defers_to_judge`, `review_feedback_uses_prose_labels_and_forbids_ids_in_answer`, and integration `review_gate_min_points_soft_falls_back_to_judge`.
- Mock end-to-end: a rubric with `min_points:2` against a one-paragraph answer produces `review.warn`, judge approval and `review.finished{status:"approved"}`.
- `cargo fmt --check` and `cargo clippy --locked --all-targets -- -D warnings` must pass.
- Windows x64 package is cross-compiled; automation still runs only on Linux.
- Bench numbers from this VM are only a sanity check; see `metrics.env` before comparing.
