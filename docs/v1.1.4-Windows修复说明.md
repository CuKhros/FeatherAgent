## 2. 逐项修复

| 编号 | 现象 | 根因 | v1.1.4 修复 | 验证 |
|---|---|---|---|---|
| NEW-A | `chat` 无法授权 `tool.fs.write` / `tool.shell`，等 120 s 后 `permission.denied` | `chat` 是无界面客户端，不处理 `tool.confirm_request` | `chat` 新增 `--allow <tool,...>` / `--yes`；收到确认请求时按白名单发 `tool.confirm`；未放行则立即 `tool.deny`；`--confirm-timeout` 可保留等待窗口 | mock：`--allow tool.fs.write` → `tool.result` 成功、文件落盘；未放行 → 立即拒绝且不再等 120 s |
| NEW-B | 拒绝后模型只看到“工具没回来”，最终答复为空/无效 | 拒绝只发 `permission.denied`，没有回注到会话上下文 | 拒绝时同时发结构化 `tool.result`：`{"denied":true,"result":{"error":"permission_denied","reason":"...","tool":"..."}}`；引擎把拒绝计入本轮进度，继续下一轮模型推理 | mock：拒绝事件后出现第二轮 `model.message` 与 `chat.finished ok` |
| NEW-C | 模型偶发空响应，直接失败 | 没有重试 | 空响应自动重试一次，带 `temperature=0.7`（Ollama 放 `options`，OpenAI 放顶层）；新增 `model.retry` 事件；仍空则失败 | 空 mock：`model.retry` 后 `status=failed`；先空后成功 mock：`model.retry` 后 `status=ok` |
| NEW-D | `chat` 没有确认等待控制 | 确认超时固定 120 s | 新增 `--confirm-timeout <秒>`；默认 0（立即拒绝），最多 30 s；`--allow` / `--yes` 立即授权 | `featheragent chat --help` 已列出三个新参数 |
| 命名 | 当前“GUI”实际是 Web 页面 | 历史命名与实现形态不一致 | 二进制 `featheragent-gui` → **`featheragent-webui`**；CLI 主命令 `webui`，`gui` 保留兼容别名；运行时 profile `gui-profile` → `webui-profile`；文档统称 WebUI | `cargo build --bins` 产出 `featheragent-webui`；旧 `gui` 别名可启动新二进制 |

## 3. 关键实现位置

- `src/bin/kernel.rs`
  - `chat`：解析 `--allow` / `--yes` / `--confirm-timeout`；处理 `tool.confirm_request`；`tool_matches` 支持全名、短名、`*`。
  - `launch_webui`：优先找 `featheragent-webui`，兼容旧 `featheragent-gui`。
- `src/engine/mod.rs`
  - 权限拒绝：发 `permission.denied` + 结构化 `tool.result`，`executed += 1` 保证进入下一轮。
  - 空响应：`run_model` 接受可选温度；`run_turn` 捕获“空响应”后重试一次并写 `model.retry`。
- `src/bin/plugin.rs`
  - provider 接收 `temperature`：Ollama 写 `options.temperature`，OpenAI 写顶层。
- `src/proto/types.rs`
  - 新增事件 `model.retry`（code 21，additive）。
- `src/bin/webui.rs`
  - 原 `gui.rs` 更名；启动信息、profile、日志改 WebUI。
- `scripts/package.sh` / `scripts/package-windows.sh`
  - 三产物与 Windows 包改用 `featheragent-webui`。
