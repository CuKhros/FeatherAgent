# FeatherAgent 1.2.1-rc.2.1 Changes

> Date: 2026-11-24 · Base: `v1.2.1-rc.2` · Type: Windows retest follow-up / regression patch

This release closes the two regressions reported after `v1.2.1-rc.2` and the review-gate quality findings G1–G3 from the same real-hardware report. It does not change R1 thresholds, provider wire endpoints, or the release asset layout.

## Fixed

### R-01 · Ollama model list returns 404 (regression since rc.1)

- Symptom: `provider.models` returned no models for a native Ollama service; TUI `/settings` and WebUI Settings had an empty model list.
- Root cause: `provider_http("ollama", "probe", ...)` requested `{base}/models` for every base URL. Native Ollama exposes `GET /api/tags`; `/models` is the OpenAI-compatible path and returns 404.
- Fix: when the provider is `ollama` and the base URL does not use the `/v1` OpenAI-compatible form, probe `{base}/api/tags`; keep `{base}/models` for OpenAI-compatible bases. Existing native parsing of `models[].name` is unchanged.
- Coverage: unit test asserts the request line is `GET /api/tags` and the parsed model names; integration test calls `provider.models` through the kernel and verifies both the result and the mock request path.

### R-02 · TUI cannot edit review-gate options

- Symptom: `/settings` only exposed provider/base/model/key/temperature/context/turns/workspace/auto-allow; review-gate values could only be edited in the WebUI or by hand-editing `data/config.json`.
- Fix: the TUI settings form now has nine review fields: enabled, max rounds, guide model/temperature, exec model/temperature, judge model/temperature, plus save and cancel.
  - `Enter`/`Ctrl+S` saves through `config.set` in one patch, including `review_gate.enabled`, `max_rounds`, and all three roles.
  - `Space` toggles enabled; `←/→` adjusts rounds/temperature and cycles review models from `provider.models`.
  - Temperature ranges are validated in the TUI before saving: guide `0.20–0.50`, exec `0.60–1.50`, judge `0.00–0.20`; rounds `1–5`.
  - The 19-field form now scrolls vertically so the active field remains visible on an 80×24 terminal.
- The WebUI hint and TUI footer now state that guide/judge should use a ≥7B model; 4B models may not produce a compliant rubric.

### R-03 · Review rubric used free-text checks (G1)

- `review.guide` now requires every item to carry `must_include`: a 1–40 character literal phrase that must appear verbatim in the final answer, preferably a conclusion sentence, filename, command, or proper noun. `check` must repeat that literal phrase.
- `review.parse_rubric` rejects rubrics without a literal (either `must_include` or a phrase quoted in `check` with `『』`, `「」`, backticks, or quotes), or with an over-long literal.
- Before calling the judge, the kernel runs `review.hardcheck`: any missing `must_include` fails the item deterministically. The judge is not called for that item.
- Revision feedback now includes the failed item's `criterion` and `check` as well as the evidence, so exec can see what to fix instead of only a short judge sentence.

### R-04 · Empty or meaningless judge evidence was accepted (G2)

- `review.parse_verdict` now requires every item's `evidence` and the top-level `evidence` to be at least 10 characters. Placeholder values such as `"总结"`, `"通过"`, `"ok"` are rejected as judge failures.
- On a short-evidence or malformed verdict, `review_judge` retries the judge once with the same rubric. Only after two failed judges does the turn degrade.
- `review_model_call` retries an empty review response once (guide or judge), matching the normal-chat empty-response policy.
- `review_prepare` retries guide once when the rubric fails parsing or validation, instead of degrading immediately.
- The judge prompt no longer contains the `"evidence":"总结"` example that induced placeholder output; it now requires quoting the answer verbatim and at least 10 characters.

### R-05 · `chat.finished.status` hid unapproved/degraded reviews (G3)

- `chat.finished` status now reflects the review result whenever the gate is enabled and the turn otherwise completed:
  - `ok` — approved, or review disabled;
  - `unapproved` — judged but not approved before the round limit;
  - `degraded` — guide/judge failed twice or review infrastructure failed.
- The `review` object also carries `status: approved|unapproved|degraded`; `review.verdict` now includes the normalized `items` (with `criterion`/`check`).
- `chat` CLI exits non-zero for `unapproved`/`degraded` because `chat.finished(status != ok)` is already a failure. A stopped/cancelled turn keeps its existing status.

## Retained from rc.2

The rc.2 fixes remain in place and were re-confirmed by the same report: provider request body and `Content-Length` on `/api/chat` and `/api/embed`, review-gate temperature validation with `enabled=false`, effective model/provider/base URL banner with source, and embeddings using the active model.

## Verification

- Linux: **102 tests, 101 passed, 1 ignored by default** (59 lib, 9 plugin, 2 kernel, 3 TUI, 3 WebUI, 2 golden, 24 integration). The ignored `local_web_search_tool_via_kernel` needs public network access and passes when run separately.
- `cargo fmt --check` and `cargo clippy --locked --all-targets -- -D warnings` pass.
- New coverage: Ollama `/api/tags` probe + `provider.models`, unapproved `chat.finished.status`, literal rubric/hardcheck, short-evidence rejection.
- Windows x64: mingw-w64 cross-compiled PE; automation still runs on Linux only. Wine, if run, is a startup smoke test, not Windows evidence.

## Still requires Windows real-hardware confirmation

1. Ollama Settings model list is populated from a real `ollama serve` (TUI and WebUI).
2. TUI `/settings` can edit, save, and reload all review-gate fields; form scrolling works in the user's terminal size.
3. Review-gate with a real 7B guide/judge: rubric contains `must_include`, judge evidence quotes the answer, and `chat.finished.status` is `ok` only when approved.
4. 4B-only review: expect a clear `degraded` status if the model cannot produce a literal rubric, not a false `ok`.
