# FeatherAgent v1.2.1-rc.4.1 变更说明

2026-11-25 候选版。本补丁修复 rc.4 Windows 复测的 N10–N13，并把 N14 的模型能力边界写进文档；不替代稳定版。

## N10：路径/文件型 `must_include` 不再被 12 字上限误伤

rc.4 对所有 `must_include` 统一套用 12 字上限，`workspace/notes.txt`（19 字）因此连续三次被判不合格，整轮在进入 judge 前就降级。

解析器现在区分“路径/文件名”和“答案短语”：

- 含 `/`、`\`，或带 1–8 位 ASCII 字母数字扩展名的点号形式，视为路径/文件名；
- 路径/文件名上限 64 字，普通术语仍是 12 字；
- 超限文案会写明适用上限，并提示“真正要核对文件产出时改用 `pattern/regex` 或 `criterion/check`”。

测试：`review_rubric_allows_file_path_must_include` 覆盖 `workspace/notes.txt` 通过、超长路径按 64 字拒绝；原有整句/长术语拒绝测试继续通过。

## N11：纯文本工具调用兜底与畸形工具名归一化

review-gate 开启后，4B exec 有时把调用写进正文，而不是通过结构化的 `tool_calls` 返回：

```text
tool_call tool.fs.write {"path":"workspace/notes.txt","content":"..."}
```

上下文解析器新增兼容回落：当没有结构化调用、也没有 `name`+`arguments` 对象时，识别 `tool_call <name> <json>` / `tool_call: <name> <json>`，配平 JSON 后解析，并归一化常见别名：

- `tool_fs_read` → `tool.fs.read`，`tool_fs_write` → `tool.fs.write`，`tool_fs_list` → `tool.fs.list`，`tool_shell` → `tool.shell`；
- `tool_fs` 默认映射为 `tool.fs.read`，带 `content` 字段时映射为 `tool.fs.write`；裸 `tool.fs` 只在带 `content` 时映射为写，否则保留为未知工具，走既有纠错提示。

review feedback 的系统消息同时加入工具格式守卫：需要调用工具时必须走 API 的 `tool_calls` 通道，不得写进最终答案。这是兼容兜底，不保证 4B 永远遵守格式；无法识别的工具名仍走既有的未知工具纠错。

测试：`plain_text_tool_call_line_is_extracted`、`plain_text_tool_call_aliases_are_normalized`。

## N12：搜索结果在 `data/` 下有可审计副本

rc.4 只把 search/news/fetch 结果写到项目工作区（`workspace/<项目>/.featheagent/search/`）。复测只检查 `data/`，因此认为没有产物，无法独立审计。

`persist_web_result` 现在双写：

- 工作区镜像：`workspace/<项目>/.featheagent/search/<ms>-<token>-<tool>.json`，工具结果回传 `artifact` 与 `artifact_kind`；
- 数据审计副本：`data/web-artifacts/<sanitized-session>/<ms>-<token>-<tool>.json`，工具结果回传 `audit_artifact`。

任一路写失败都会合并进 `persist_error`，但不影响搜索本身。审计文件保留 `tool`、`arguments`、`result`、`untrusted:true`、`saved_at_unix_ms`。

测试：`web_search_artifact_audit_copy_is_written`；原工作区落盘测试保留。

## N13：最终 rubric 单独留档

复测的 judge 产物为 0，因为 guide 三次失败。报告无法判断“最终本应采用哪份 rubric、`match`/`min_matches` 是什么”。

rubric 被接受后、发出 `review.guide` 前，内核现在写入：

```text
data/review-artifacts/<sanitized-session>/<ms>-rubric-final.json
```

内容包含 `role:"rubric-final"`、`session`、`model`、`temperature`、`attempt`、`at_unix_ms`、`input`、规范化后的 `rubric`（含 `match`/`min_matches`）、`hard_items`、`judge_only`。`review.guide` 新增 `final_artifact`。失败尝试仍保留为 `guide-aN`；整轮没有接受的 rubric 时不会生成 `rubric-final`，这本身就是“未选中任何 rubric”的信号。

## N14：4B 多任务长流程边界（仅文档）

rc.4 复测中同一提示在 review-gate 关闭时先得 3/4，再跑只得 1/4，属模型漂移/能力边界，不是内核确定性缺陷。文档现明确：

- 多任务、长流程建议使用 ≥7B exec 模型；
- 测试基线需多次取样，不能只看一次；
- 4B 结果按观测记录，不作为回归门禁。
