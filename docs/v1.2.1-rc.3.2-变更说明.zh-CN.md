# FeatherAgent v1.2.1-rc.3.2 变更说明

本候选版修复 `v1.2.1-rc.3.1` Windows 真机复测提出的 J1–J3。rc.3.1 复测已确认上一轮修复有效：真实 7B 下 review-gate 从 4/4 `degraded` 变为 **1/3 approved + 2/3 unapproved**，guide 一次成功（`attempts:1`），软判据降级为 judge-only 并打 `review.warn`，judge evidence 是答案原文窗口。剩下的缺陷集中在“计数与措辞”，不动架构。

## J1 · `min_points` 误杀（🟠）

**现象。** 3 轮里有 2 轮被 `答案只有 1 个要点，至少需要 2 个` 拒绝，但答案实际有 3 个分号分隔的要点；旧计数器只数行首列表标记。

**修法。**
- `count_points` 改为四种口径取最大值：行首 `- * + • ·` 与数字编号、行首加粗小标题、`；`/`;` 分隔且长度 ≥6 的分段、空行段落；上限 12。
- `review.hardcheck` 不再把 `min_points` 不足当硬失败，而是把该项放进 `soft` 数组返回。
- 引擎打 `review.warn`（`min_points 机器计数不足，交 judge 复核：〔c2〕…（机器计数 1/2 个要点）`），并在 judge 输入追加 `[机器计数提示]`，要求按答案实际内容复核，不要只看列表符号。
- judge 仍必须返回答案原文 evidence，由 `parse_verdict` 做连续 ≥10 字校验，放水有边界。

## J2 · rubric 编号被抄进答案（🟠）

**现象。** exec 把 `**c1.**`、`**c2:**`、`-**c3. …**` 写进答案。根因是 `review.feedback.text` 用 `- c1:` / `- c2:` 标注未通过项，模型把它当成答案模板。

**修法。** feedback 改用 `〔1〕` / `〔2〕` 自然序号，不再出现裸 `cN`，并在末尾明确写：`注意：上面的〔1〕〔2〕只是给你看的序号，不要把它们写进答案正文，也不要用 c1/c2 这类编号当小标题。` `review.feedback` 事件里的 `failed` id 保留用于追溯，只有发给模型的文本变了。

## J3 · bench 数字跨时段不可比（🟡）

**现象。** 长时间测试后整机降级：rc.3 与 rc.3.1 都出现 108–314 ms 热启动、写 P95 ≈10 ms、RPC P95 最高 1.5 ms；同一台机器上 rc.3 早些时候是 45.6 ms。数字是环境漂移，不是版本回退。

**修法。** `bench --json` 增加 `metrics.env`，人类可读输出加一行指纹：
- `captured_at_unix_ms`、`cpu_count`；
- Linux：`loadavg_1m/5m/15m`、`mem_total_kb`、`mem_available_kb`、`uptime_s`；
- Windows：`mem_total_kb`、`mem_available_kb`、`mem_load_pct`、`uptime_s`（`GlobalMemoryStatusEx` / `GetTickCount64`）。

门禁与阈值不变。指纹只让“机器降级”可见，不会把不合格跑成合格；发版基线仍应在刚重启的干净机器上取。

## 显示名

`featheragent-tui version` 与 `featheragent-webui version` 改为打印 `FeatherAgent TUI <v>` / `FeatherAgent WebUI <v>`。二进制名、子命令、包名与路径不变，只改用户可见的产品名。

## 兼容性

- `review.hardcheck` 增加 `soft` 数组；它是插件内部结果，不是 wire 消息。
- `review.warn` 新增“机器计数降级”语义；事件编号（29）与字段不变，`text` 里会出现 `min_points 机器计数不足…`。
- feedback 文本格式变化；`review.feedback` 事件里的 `failed` id 不变。
- bench JSON 增加 `metrics.env`；忽略未知字段的消费方不受影响。
- provider、storage、tool、IPC 帧均未改。

## 验证

- Linux 精确测试数见 `docs/Verification-Report.md`。新增覆盖：`count_points_recognizes_chinese_inline_enumeration`、`min_points_is_soft_and_defers_to_judge`、`review_feedback_uses_prose_labels_and_forbids_ids_in_answer`，以及集成 `review_gate_min_points_soft_falls_back_to_judge`。
- mock 端到端：`min_points:2` + 单段答案会走 `review.warn` → judge 复核通过 → `review.finished{status:"approved"}`。
- `cargo fmt --check` 与 `cargo clippy --locked --all-targets -- -D warnings` 必须通过。
- Windows x64 包来自交叉编译；自动化仍只在 Linux 跑。
- 本 VM 的 bench 数字只作 sanity check，对比前先看 `metrics.env`。

## 仍需 Windows 真机确认

1. 真实 7B 用中文分号/加粗小标题作答时计数正确，或最差表现为 `review.warn` + judge 复核，而不是硬拒绝。
2. 连续多轮 exec 不再把 `c1/c2/c3` 写进答案。
3. `bench --json` 的 `metrics.env` 数值合理（CPU 数、内存、平台可得的负载）。
4. `featheragent-tui version` / `featheragent-webui version` 显示 `FeatherAgent …`。
5. rc.3.1 仍未核对的项：真实 Ollama 的模型下拉、ConPTY 下 Enter 保存、Windows Terminal 的权限弹窗、S3 t6 单次调用。
