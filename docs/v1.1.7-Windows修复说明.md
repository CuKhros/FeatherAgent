# FeatherAgent v1.1.7 · Windows v1.1.6 复测修复与体验/架构升级

> 依据：《Windows 真机复测报告 v1.1.6》（2026-11-22）
> 基线：`v1.1.6`，发布提交 `1ef5e33`
> 本版输出：v1.1.7 代码 + Windows x64 测试包；**Windows 真机结论仍以用户复测为准**，Wine 只作冒烟。

## 1. 结论

v1.1.6 报告确认：NEW-H（启动可观测性）、NEW-I（`config.set` 单字段原子更新）、NEW-J（S3 三档）均已在真机修复；悬置 5 轮的 NEW-4 断连孤儿回合也验证通过。报告只新发现 1 条缺陷 **NEW-K**，并给出 5 项未验证项。

v1.1.7 处理 NEW-K，并落地四项追加要求：TUI 会话/对话双模式与光标编辑、外置工作区与 `.featheagent` 工作记忆、插件管理页与设置侧边栏、WebUI 顶部插件入口。Linux 自动化测试 **70/70** 通过；TUI 用 PTY、WebUI 用真实浏览器逐项驱动验证。

## 2. NEW-K：bench 与运行中的内核冲突

**现象**（报告）：先 `serve`，不停止就 `bench --root . --json`，报 `系统找不到指定的文件 (os error 2)`；停掉内核后 bench 6/6。

**根因**：bench 需要自己拉起内核实例做测量，与已运行的 `serve` 争用同一端点；底层管道打开失败没有翻译成可读的业务错误。

**修复**：bench 入口先解析 `--root/--socket`，读取 `runtime/ipc/ready`，若 ready 存在且 `ipc::connect(socket)` 成功，则解析 `pid` 并直接返回非零错误：

```
检测到内核正在运行（pid N），请先停止 serve 再运行 bench；当前端点 <socket>
```

不再进入临时目录测量。ready 不存在、或 ready 存在但端点连不上（残留标记）时仍按原流程执行。

**验证**（Linux）：

- serve 运行中：`bench --root /tmp/fa-newk --json` → 上述错误，exit 1。
- 停 serve 后：`bench --root /tmp/fa-newk --json` → exit 0，输出 6 项指标。
- 单元测试覆盖 `--workspace` 优先级与相对/绝对工作区解析。

## 3. TUI：会话列表 / 对话双模式

v1.1.6 的 TUI 只有会话列表，↑↓ 始终切换会话，进入会话后无法翻阅历史。v1.1.7 改为两个显式模式：

| 模式 | ↑↓ | Enter | Esc |
|---|---|---|---|
| 会话列表 `Focus::Sessions` | 选择会话 | 进入/恢复会话 | 退出 TUI |
| 对话 `Focus::Chat` | 翻阅对话上下文（↓ 回到底部） | 发送输入 | 退回会话列表 |

- `PageUp` / `PageDown` 一次翻 10 行；滚动量按**可视行**计算，长会话不会滚成空白。
- 会话内容来自内核事件日志 `data/sessions/`：`session.resume` 返回最近 200 条事件，TUI 回放 `user.message` / `model.message` / `tool.*` / `chat.finished`。安装目录内的完整上下文仍以日志为准，不依赖 TUI 进程内存；退出 TUI 再进入可恢复。
- `resume` / `create` / `send` 后自动进入对话模式，并清空输入、回到底部。
- 会话列表仍显示每个会话的事件条数与 live 状态。

**PTY 实测**：进入会话后连按 ↑↓，header 保持“对话”、选中会话不变；Esc 后 header 变“会话列表”；再 Esc 退出。用 15 轮长会话验证 ↑ 5 次、↓ 2 次的可见内容变化，底部始终显示最后一轮。

## 4. TUI 输入光标

原实现按**字符数**估算光标列，CJK 占 2 列但只算 1 列，导致光标比实际字符串末尾偏左/偏移；且没有横向滚动，长输入会跑出输入区。

v1.1.7：

- 输入状态增加字符索引 `input_cursor`；←/→、Home/End、Backspace/Delete 均可用。
- 光标列按 `unicode-width` 的显示宽度计算：CJK 2 列、ASCII 1 列；公式为 `area.x + 1（边框）+ 2（提示符）+ display_width(光标前文本)`。
- 输入超过可视宽度时按字符逐步横向滚动，光标始终可见；发送/新建/恢复会清空输入并复位光标。
- 新增依赖 `unicode-width = "0.1"`。

**PTY 实测**（120×34）：输入 `你好abc` 后光标列 10；← 后 9；Home 后 3；End 后 10；末尾再输入 `Z` 后 11。与“边框 1 + 提示符 2 + 显示宽度”完全一致。

## 5. 外置工作区与 `.featheagent` 工作记忆

### 5.1 选择安装目录外的工作区

`Config` 新增 `workspace_root: String`（`#[serde(default)]`）：

- 空字符串 = `<安装根>/workspace`（兼容旧配置）。
- 相对路径按安装根解析；绝对路径可直接指向安装目录外。
- 优先级：CLI `--workspace` > `workspace_root` > 默认。
- `serve` / `doctor` 启动时应用；`serve` banner 增加 `workspace=`。
- `config.get` 自动返回该字段；WebUI 设置页和 TUI `/settings` 均可编辑并通过 `config.set` 保存。
- **运行中的内核不会热迁移工作区**；保存后需重启 `serve` 才切换。UI 已明确提示。

### 5.2 `.featheagent/` 项目记忆

`Kernel::new` 在卷类型检查后调用 `prepare_agent_home(&paths.workspace)`，创建：

```
<workspace>/.featheagent/
├── worklog.md   # 工作日志（追加）
├── memory.md    # 项目长期记忆
└── README.md    # 目录说明
```

文件已存在则不覆盖，避免抹掉用户积累。`ContextEngine` 的 system 前缀追加工作习惯：

- 有实际产物或项目进展的任务结束前，用文件工具向 `workspace/.featheagent/worklog.md` 追加本次日志；
- 出现稳定事实、决策或用户偏好时更新 `workspace/.featheagent/memory.md`；
- 简单问答不写，避免噪声。

文件工具路径语义同步收紧：`workspace/` 前缀访问工作区根，普通相对路径落在当前会话目录，不接受前导斜杠。

**实测**：临时安装根配置 `workspace_root=/tmp/fa-ext-ws` 后重启 serve，banner 显示外置路径，三个模板文件生成；WebUI 保存 `/tmp/fa-web-ws` 后重启 serve，banner 与目录切换均生效。单元测试覆盖模板创建与“已存在不覆盖”。

## 6. 插件管理页与设置侧边栏

### 6.1 运行时启停

- `PluginHost::unregister(name)`：移除 spec，并终止已运行进程。
- `plugin.enable`：更新 registry 后，把该插件 spec 注册进运行 host；下一次调用按需拉起。
- `plugin.disable`：更新 registry 后 unregister，运行进程立即终止。
- `plugin.install`：安装成功后若插件启用，立即把 spec 注册进 host，无需重启。
- `plugin.list` 返回 `registry`（name/program/args/category/enabled/blake3）与 `live`（name/state/manifest）。

### 6.2 WebUI

- 顶栏新增 **🧩 插件**，与 **⚙ 设置** 并列；点击直接打开插件管理页。
- 设置页改为“左侧栏 + 右侧内容”：
  - 固定项：常规、插件管理；
  - 动态项：每个已登记插件一个侧栏条目，点击进入插件详情（API、live 状态、capabilities、permissions、program、blake3、启停按钮）；
  - 插件安装框：输入插件目录绝对路径（含 `plugin.json`）→ `plugin.install` → 自动刷新侧栏和列表。
- 常规页新增“工作区根目录”，保存 patch 包含 `workspace_root`。
- 插件状态文案区分“运行中 / 按需启动 / 已停用”。

**浏览器实测**：设置侧栏渲染 4 个插件条目；插件管理页显示列表与启停按钮；`storage` 停用后 live=stopped、再启用后恢复登记；从 `/tmp/fa-install-src` 安装 `demo-tool` 成功，侧栏即时出现新条目；顶栏“🧩 插件”可直接进入插件管理页。

### 6.3 TUI

- 新增 `/plugins` 页面：↑↓ 选择，Space/Enter 启停，`r` 刷新，Esc 返回。
- 列表显示 name、category、运行状态、enabled 标记；状态栏提示“启停会同步到运行进程”。
- TUI 设置页字段从 9 增至 10，新增 Workspace root；`Auto allow safe` 的空格切换索引同步修正。

## 7. 版本与配置

- `Cargo.toml` / `Cargo.lock` 根包 / 4 个 `plugin.json` / WebUI / TUI / 文档统一为 **1.1.7**；契约仍为 `1.0`。
- `Config::default()` 的 `context_window` 仍为 **8192**。报告中 v1.1.6 读到 10240，不是本版自动探测或默认值变化：`config.get` 返回的是 `data/config.json` 中已保存的生效值；旧测试目录里该值曾被设置页写入 10240。若要恢复默认，删除/改写 `data/config.json` 的 `context_window` 后重启。
- 新增配置字段只有 `workspace_root`，旧配置可无损加载。
