# FeatherAgent v1.2.1-rc.4 —— 变更说明

公开发布候选版，2026-11-25。本版修复 rc.3.6 Windows 复测的 N5–N9，并实现搜索落盘与文件附件路径；不替代稳定版。

## N5 —— `must_include` 匹配模式

多项 `must_include` 不再默认“全部命中”。guide 阶段统一规范化：

- `match: "any" | "all" | "min"`；
- `match` 为 `min` 时可用 `min_matches: 1..n`；
- `n > 1` 缺省为 `min`，要求 `ceil(n/2)` 项；
- 单项目标等价于 `all`。

hardcheck 统计满足的 `must_include` 项数（每项仍用 `include_terms` 拆词匹配），再与所需数比较。失败文案报告 `{hits}/{total}`、判据、模式与所需数，不回显字面短语。

非法 `match`、越界 `min_matches`、无 `must_include` 却写 `match` 都会在 guide 阶段报错。

测试：`review_rubric_defaults_multi_must_include_to_half`、`review_hardcheck_supports_any_all_and_min`；原 TCP 测试改为显式 `match:"all"`。

## N6 —— 主观判据不能用 `must_not_include`

解析阶段识别主观词：`准确`、`准确无误`、`正确`、`恰当`、`专业`、`规范`、`流畅`、`自然`，以及原有的简洁/清晰/完整等。若 criterion/check 命中主观词且 `must_not_include` 非空，guide 直接报错，要求改成可计数/可核对的形式或交给 judge。禁词已经出现在用户输入中时也报错，避免判据与任务自相矛盾。

`GUIDE_SYSTEM` 第 4、9 条同步说明 `match`/`min_matches` 与主观禁词规则。N4 的 fixture 整条丢弃继续由 rc.3.5 原始回归测试覆盖。

测试：`review_rubric_rejects_subjective_must_not_include`、`review_rubric_rejects_banned_word_from_input`。

## N7 —— bench 唯一临时目录与结构化错误

原临时目录只含 pid，Windows pid 复用会撞上残留目录并报 `os error 2`。现在每次运行使用 `fa-bench-<pid>-<random_token(6)>`，不再先删同 pid 的旧目录。

CLI 拆成 `bench`（参数/JSON 包装）与 `bench_run`。失败时若带 `--json`，先输出一行：

```json
{"ok":false,"code":"artifact_missing","error":"...","hint":"..."}
```

`os error 2` 映射 `artifact_missing`，其他失败用 `bench_failed`。关键路径错误加 `[bench:temp_dir]`、`[bench:kernel_init]`、`[bench:boot_ready]`、`[bench:log_store]`、`[bench:rpc_kernel]`、`[bench:rpc_ready]`、`[bench:rpc_connect]` 前缀并带路径。`kernel.rs` 与 `kernel_en.rs` 同步。

## N8 —— 重复工具调用抑制

同一条模型回复内，`name` 与序列化 `arguments` 完全相同的 `tool_calls` 只执行一次；参数不同仍分别执行。`tool.call` 新增：

- `attempt`：`run_turn` 模型重试循环中的第几次 attempt（从 1 开始）；
- `call_index`：同一回复内的第几个调用。

这样能区分“重试又产生了同一个调用”和“一次回复要求多个调用”。

## N9 —— reliability 感知启动门禁

bench 读取 `env_fingerprint` 的 `reliability`，只有 `high` 可信。原始门禁仍为 `boot_p50 < boot_limit`，有效门禁为 `raw || !trusted`；环境不可信时，不再仅因启动抖动判红。

新增字段：

- gates：`boot_gate_status`（`pass`/`fail`/`advisory`）、`boot_gate_trusted`、`boot_gate_raw`、`reliability`；
- metrics：`reliability`、`boot_gate_raw`、`boot_gate_trusted`。

`boot_lt_20ms` / `boot_lt_100ms` 改用有效门禁值。`kernel.rs` 与 `kernel_en.rs` 同步。

## 搜索落盘

`web.search`、`web.news`、`web.fetch` 结果写入：

```text
workspace/<项目>/.featheagent/search/<unix_ms>-<random_token(4)>-<tool>.json
```

文件含 `tool`、`arguments`、`result`、`untrusted:true`、`saved_at_unix_ms`。工具结果增加 `artifact`（实际路径）与 `artifact_kind`；写入失败只追加 `persist_error`，不使搜索失败。

`save_web_artifact` 由运行时与集成测试 `web_search_artifact_is_persisted_under_project_workspace` 共用。

## 文件附件

内核：

- `file.attach` / `file.prepare` 接受 `path`（本地文件）或 `name` + `data_base64`（浏览器上传）。
- 本地路径 canonicalize 后必须是文件；与 canonicalize 的安装根比较，在安装目录内原样返回（`copied:false`），否则复制到 `workspace/default/uploads/<unix_ms>-<random_token(4)>-<safe_name>`。
- 浏览器字节总是写默认工作区；空文件和超过 8 MiB 拒绝。
- 返回 `{path, copied, source, name, bytes}`；模型只拿返回路径。

TUI：

- 行首或空白后的 `@<路径>`；支持 `@"含空格路径"`；邮箱不触发。
- 发送前 `is_file` 校验，调用 `file.prepare`，在发往内核的文本末尾追加 `[附件] <内核路径>`。文件不存在则停止发送并在状态栏提示。
- `/help` 列出 `@<路径> 添加附件`。

WebUI：

- `+` 通过隐藏的 `<input type="file" multiple>` 调系统选择框。
- 文件读成 base64，走 HTTP RPC `file.attach`（不走 WebSocket，WS 单帧上限仍 1 MiB）；HTTP body 上限 12 MiB，为 8 MiB 文件的 base64 留余量。
- chip 显示内核路径且可删除；上传中禁止发送；切换会话清空附件。
- 发送文本带同样的 `[附件]` 行。
