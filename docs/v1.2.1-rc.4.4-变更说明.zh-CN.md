# FeatherAgent v1.2.1-rc.4.4 变更说明

2026-11-26 候选版。本补丁处理 rc.4.3 Windows 真机复测的 N23–N27，并修复 TUI 长对话在顶部继续按上键后的“虚拟滚动量”问题。N28 为测试侧规则限制，产品不改。本候选版不替代稳定版。

## N23：bench 不再卡死在服务器停止/join

rc.4.3 报告在 `bench[2/6]` 后 150 秒无输出，连续 5 次 `bench --json` 都是 0 字节。静态复核定位到两个叠加点：

- `Server::stop` 在 rc.4.3 改成“最多 5 次 one-shot `try_connect`、每次间隔 50 ms”，总窗口只有约 250 ms；Windows 命名管道正在重建时，唤醒连接可能全部失败；
- bench 随后执行无限 `handle.join()`；Windows `Listener::accept` 用阻塞的 `ConnectNamedPipe`/`GetOverlappedResult`，没有收到唤醒就会永久阻塞。

修法分两层：

- `Server::stop` 改为 3 秒总预算、20 ms 间隔的短重试；成功发出一条唤醒连接后立即返回；
- bench 的 warm 与 RPC 两处 `join` 改为 `is_finished()` + 5 秒 deadline 轮询；超时返回 `[bench:boot_stop]` / `[bench:rpc_stop]` 的明确错误，不再无限等待；
- `scripts/ci.sh` 增加 `timeout 90` 的 `bench --json` 门禁，并校验 7 个发布 gate，避免“进程活着但永远不结束”再次进入发布。

## N24：写文件任务由 judge 核对文件，不再被 guide 自造词卡死

rc.4.3 报告里写文件任务仍 `failed`：`notes2.txt` 已写成功，但 guide 生成的 c1 要求文件正文出现 `- 内存分配`、`- 内存回收`、`- 页面置换`，实际内容讲的是引用计数、标记清除、分代回收；c4 又要求“最终答复使用 tool.fs.write 写入文件”，而工具事实不在答复文本里。结果 `votes=0`，hardcheck 直接判死。

修法：

- 抽出共享 `util::requests_file_write`，engine 与 review-gate 用同一套“明确写文件任务”识别；
- 对这个场景，guide 产出的所有判据统一转 `judge_only`，剥掉 `must_include` / `must_not_include` / `min_points` / `pattern` / `regex` / `hard` / `match` / `min_matches`，不再按答复措辞判死；
- review 证据增加 `tool.fs.write path=... status=success` 工具事实，再附文件正文，一起交给 judge；
- guide 提示新增“不要猜文件正文具体词、不要要求最终答复复述文件”；
- 文件已写成功、但后续模型仍返回畸形 XML 或空响应时，引擎用确定的“已写入 path（N 字符）”收尾，再进入 review，不再把整个回合降为 `failed`。

测试：`requests_file_write_is_explicit_about_target`、`review_rubric_moves_file_task_terms_to_judge`、`review_rubric_keeps_hard_items_for_code_tasks`、`review_answer_includes_written_file_content_before_final_answer`、`write_fallback_names_the_file_without_claiming_missing_content`，以及写文件端到端测试对 judge `votes>0` 的断言。

## N25：XML 开标签漏 `>` 的恢复

rc.4.3 报告重新出现与 rc.4.1 相同的 function 开标签被 parameter 结束标签闭合。

根因：`parse::xml_tool_call` 用第一个 `>` 当 function 开标签结尾；漏 `>` 时会把第一个 parameter 标签的 `>` 误当结尾，body 从参数值中间开始。

修法：开标签边界取 `>`、换行、parameter 标记三者的最早位置；缺 `>` 时只读到换行或参数前。parameter 开标签也做同样的缺 `>` 容错。

测试：`malformed_xml_function_open_without_gt_is_recovered`。

## N26：区别/对比题按对比轴逐条展开

rc.4.3 的 TCP/UDP 三区别仍只覆盖机制/连接、可靠性两维，性能/开销与场景为 False，答案 117 字。

系统提示新增专项规则：问区别/对比/差异时，先列机制/连接、可靠性/一致性、性能与开销、典型场景四个对比轴；按用户要求的条数逐轴展开，每维至少一行、双方各写关键取值；这类题不受默认简洁限制。

测试：`system_prompt_distinguishes_brevity_from_coverage` 增加“每个维度至少一行”“不受默认简洁限制”断言。

## TUI：长对话到顶后不再积累虚拟滚动量

现象：在中英 TUI 的长对话里按上键翻到顶后继续按，向上多按 N 次，向下就要先按约 N 次才能动。

根因：Up 对 `chat_scroll` 做 `saturating_add`，只增不减；渲染时把值截到 `max_scroll` 用于显示，但没有回写状态，所以多按的次数被保存下来。

修法：`draw` 改为接收可变 `App`，算出 `max_scroll` 后先把 `chat_scroll` 夹到上限，再计算显示偏移；中英两份同步，并抽 `clamp_chat_scroll` 纯函数。

测试：`chat_scroll_is_clamped_after_overscrolling_at_top`（中英 TUI 各一份）。

## N27：bench 临时目录在任何退出路径都清理

rc.4.3 卡死被 timeout 杀掉后留下 `fa-bench-11776` 等目录；旧代码只在函数末尾 `remove_dir_all`，中途问号返回或 panic 都不会执行。

修法：`BenchTempDir` 的 `Drop` 统一清理；bench 启动时扫描临时目录，删除超过 24 小时的旧 `fa-bench-*` 残留，不动其他进程的新目录。中英 bench 同步。

验证：release bench 三连跑后临时目录计数为 0；人为创建 3 天前的 `fa-bench-stale-test` 后再跑 bench，目录被清除。

## N28：Q7 粗体小标题不被列表规则识别，属测试侧限制

报告已确认 Q7 内容三条齐全，只是打分规则只认短横线或数字列表，粗体小标题被判 0/3。本版不改产品输出，只记录测试口径；后续评分脚本应同时识别粗体小标题与无序列表。
