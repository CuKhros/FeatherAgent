# FeatherAgent 1.2.1-rc.3.1 变更说明

> 日期：2026-11-24 · 基线：`v1.2.1-rc.3` · 类型：review-gate 真实模型可靠性 + 设置体验 + 显示名

这是 `v1.2.1-rc.3` 之上的补丁版本。rc.3 真机复测的结论是“引擎做对了，方向盘打过头了”：mock 下 include / not_include / 答案原文 evidence / 两轮 approved 都能复现，但真实 7B guide 让 4/4 全部 `degraded`——判据只有 `criterion`/`check`、没有硬键，而两次重试只是原样重发同一个 prompt。本版修掉这条链路，并落实三条体验要求：插件设置里的模型字段从本地模型服务列表下拉选择、TUI 插件页任意字段 Enter 即保存、TUI/WebUI 权限申请显示完整命令；同时把产品显示名统一为 **FeatherAgent**。

二进制名、CLI 子命令、包名、环境变量与磁盘路径一律不变（`featheragent`、`featheragent-tui`、`featheragent-webui`、`feather-plugin`、`feather-storage`、`.featheagent` 工作区标记），只改用户可见的产品名。

## I1 · 真实 7B 下 review-gate 全量 degraded

- 现象（rc.3 真机）：4/4 真实模型运行都是 `review.finished{status:"degraded", rounds:0}`，原因 `验收项 1 没有判据`；mock 全绿。
- 根因：guide 的 system prompt 只用文字描述了判据种类，没给 JSON 形状，7B 于是只回 `{criterion, check}`；`review.parse_rubric` 对任何缺少硬键的条目直接报错，整轮门禁在出答案前就降级。
- 修法三层：
  1. **先给 schema。** `GUIDE_SYSTEM` 直接给出带四种判据的 JSON 模板，并写明“criterion/check 只是说明，判定只认 `must_include` / `must_not_include` / `min_points` / `pattern`”“短语 ≤20 字”“1–5 条”。
  2. **错误回注。** `review.guide` 新增可选 `feedback` 参数并追加 `[上一次的判据不合格]` 段；`review_prepare` 改为**在重试循环内**构造 prompt 并传入上一轮 `review.parse_rubric` 的错误，第 2、3 次是与第 1 次不同的请求。最多 3 次（首答 + 两次带错误回注的重试）。
  3. **宽容判据。** `review.parse_rubric` 接受 1–5 条，只有 `criterion`/`check` 的条目标 `judge_only:true` 并保留，整份清单只要求 ≥1 条硬判据。零硬判据时先带错误回注重试；最后一次仍是软判据则**交给 judge 逐条评估**并打 `review.warn`，不再让整轮 degraded。`must_include` 仍限 ≤20 字且拒绝整句。

## I2 · 新增事件 `review.warn`（29）

- `EventKind::ReviewWarn` / `review.warn` 用来报告“能用但不完美”的质量告警，不判定失败：“N 条判据只有描述、没有硬检查（c1, c2）：交给 judge 评估”“判据全是字面短语，建议再加一条 …”，以及每次被拒的重试（“第 1 次判据不合格：…”）。
- 走既有事件总线，不进模型上下文；TUI 与 WebUI 以系统提示显示。
- 契约：编号 29，名称 `review.warn`，payload `{text, model, attempts, retry?}`。

## I3 · S3 t6 仍多调一个工具

- `tools/s3_batch.py` 的 t6 追加“本轮只允许一次工具调用”，并点名禁止第二次调用以及 `tool.shell` / `tool.ping`，与原有“不要重试、不要换路径”并列。

## I4 · H3 未知工具纠错缺可构造入口

- 纠错路径本身已有集成测试 `unknown_tool_name_gets_correction_instead_of_raw_rpc_error`；本版把真机可用的入口写进测试说明：用 `provider-mock` 执行 `featheragent chat --text 'TOOL:{"name":"tool.fs","arguments":{"path":"a.txt"}}'`，必须得到含 `未知工具 tool.fs` 和可用工具清单的 `tool.error`。

## 设置 · 模型名从本地模型服务列表选取

- `SettingField` 新增 `options_source`（`"" | "models"`）与 `allow_custom`；内核只转述声明，列表由各前端通过既有 `provider.models` RPC 获取。
- `plugins/review-gate/plugin.json` 给 `guide.model` / `exec.model` / `judge.model` 声明 `options_source: "models"`、`allow_custom: true`。
- WebUI：真 `<select>`（占位项“（跟随当前模型）”+ 服务返回的全部模型）配一个文本输入框；选中下拉即写入输入框，服务没报的模型仍可手动键入。
- TUI：`←/→` 在“跟随当前模型 → 模型列表”之间循环；列表不可用时退回手动输入，并在表单上说明。
- `provider.models` 失败时两端都降级为手动输入并显示行内提示，不阻塞整页。

## TUI · 任意字段 Enter 保存

- 以前只有“保存并应用”行（或 `Ctrl+S`）有动作，光标停在值字段上按 Enter 毫无反应，看起来像“保存了其实没保存”。
- 现在任意值字段 Enter 提交整张表单；启停行先翻转再保存；`Esc` 仍是丢弃返回。

## 权限申请显示完整命令

- `tool.confirm_request` 新增 `arguments`（原样）与 `preview`（人读）：`tool.shell` 给命令行（`$ …`）加其余参数，其他工具给缩进 JSON；超过 4 KB 截断并标注原始长度。
- TUI：居中“权限申请”弹窗，展示工具、风险、完整命令与 `y 允许 / n 或 Esc 拒绝`；上下文面板保留一行提示指向弹窗。
- WebUI：确认弹窗用可滚动的 `<pre>` 展示同一份 preview；老内核缺 `preview` 时回退为 `arguments` JSON。
- 新增集成断言：`tool.shell` 的确认请求必须带 `params.arguments.cmd == "echo hi"`，且 preview 含该命令。

## 显示名 · FeatherAgent

- `version`、`serve` banner、help 头部、TUI/WebUI 标题统一显示 **FeatherAgent**；二进制名、子命令名、ZIP/tar 包名与路径不动。

## 兼容性

- `manifest.settings` 的 `options_source` / `allow_custom` 可选，默认空/false；未声明的插件渲染与之前完全一致。
- `review.guide` 的 `feedback` 可选；忽略它的插件仍产出与 rc.3 相同的 prompt。
- `review.warn` 是新增事件；忽略未知事件名的客户端不受影响。
- `tool.confirm_request` 只加两个字段，原 `session/token/tool/risk` 不变，rc.3 的前端仍可工作（只是显示得少）。

## 验证

- Linux：**110 个测试，109 通过，1 个默认 ignored**（61 lib、14 plugin、2 kernel、3 TUI、3 WebUI、2 golden、26 integration）。ignored 的 `local_web_search_tool_via_kernel` 需要公网。
- `cargo fmt --check` 与 `cargo clippy --locked --all-targets -- -D warnings` 通过。
- 新增覆盖：`review_gate_reinjects_schema_error_and_falls_back_to_judge_only`（回注后第 2 次成功；始终软判据则以 judge-only 收尾并带 `review.warn`，不是 `degraded`）、`review_rubric_accepts_description_only_items_with_warning`、`guide_prompt_injects_previous_schema_error`，以及 `tool_execution_and_permission_gate` 中的确认请求参数断言。
- 前端：TUI PTY 实跑（打开 review-gate 页 → `←/→` 循环模型 → 值字段 Enter 保存 → 读 `data/config.json`）；WebUI 浏览器实跑（三个 `<select>` 渲染、保存落盘、随后一轮对话成功）。

## 仍需 Windows 真机确认

1. 真实 7B guide 能产出至少一条硬判据；若不能，`review.warn` 要明确提示，且门禁仍评估而非 `degraded`。
2. 第 2 次重试确实带着上一轮错误（guide 的回答与第 1 次不同）。
3. 插件设置：三个模型字段显示来自本地 Ollama `/api/tags` 的下拉，同时自定义模型名仍能保存。
4. TUI：任意插件字段 Enter 保存；权限弹窗显示完整的 `tool.shell` 命令。
5. S3 t6 在真机上只调用一次工具。
