# FeatherAgent 1.2.1-rc.3.1 Changes

> Date: 2026-11-24 · Base: `v1.2.1-rc.3` · Type: review-gate real-model reliability + settings UX + naming

This is a patch release on top of `v1.2.1-rc.3`. The rc.3 real-hardware retest concluded that the review-gate machinery itself worked (include / not_include / answer-verbatim evidence / two-round approval all reproduced under mock), but a real 7B guide made every run `degraded`: the rubric only had `criterion`/`check` and no hard key, and the two retries re-sent the identical prompt. This release fixes that path, adds the model-list dropdown requested for plugin settings, makes Enter save from any field on the TUI plugin page, shows the full command in permission prompts on both front ends, and renames the product display to **FeatherAgent**.

The binary names, CLI subcommands, package names, environment variables and on-disk paths are unchanged (`featheragent`, `featheragent-tui`, `featheragent-webui`, `feather-plugin`, `feather-storage`, `.featheagent` workspace marker). Only user-visible product strings changed.

## I1 · review-gate degraded on every real 7B run

- Symptom (rc.3 retest): 4/4 real-model runs ended `review.finished{status:"degraded", rounds:0}` with `验收项 1 没有判据`; mock runs were green.
- Cause: the guide prompt described the criterion kinds in prose but never showed the JSON shape, so a 7B model returned `{criterion, check}` only; `review.parse_rubric` rejected any item without a hard key, so the whole gate degraded before the first answer.
- Fix, three layers:
  1. **Schema-first guide prompt.** `GUIDE_SYSTEM` now carries a literal JSON template with all four criterion kinds, an explicit “criterion/check are documentation only, the verdict keys are `must_include` / `must_not_include` / `min_points` / `pattern`” rule, the ≤20-character phrase rule, and a “1–5 items” rule.
  2. **Error reinjection.** `review.guide` accepts an optional `feedback` argument and appends a `[上一次的判据不合格]` block; `review_prepare` now builds the prompt *inside* the retry loop and passes the previous `review.parse_rubric` error, so attempt 2 and 3 are different requests, not a resend. Attempts: 3 (first + two reinjected retries).
  3. **Tolerant rubric.** `review.parse_rubric` accepts 1–5 items, keeps items that only have `criterion`/`check` (marked `judge_only:true`), requires only that the rubric as a whole has ≥1 hard criterion. A rubric with zero hard criteria is retried with the same error feedback, and if still soft on the last attempt it is **accepted for judge-only evaluation** instead of degrading the whole round. `must_include` stays ≤20 characters and non-sentence-like.

## I2 · New event `review.warn` (29)

- `EventKind::ReviewWarn` / `review.warn` reports quality warnings without failing the gate: “N 条判据只有描述、没有硬检查（c1, c2）：交给 judge 评估”, “判据全是字面短语，建议再加一条 …”, and each rejected attempt (“第 1 次判据不合格：…”).
- The event is carried on the existing event bus and is not injected into the model context; TUI and WebUI surface it as a system note.
- Wire contract: code 29, name `review.warn`, payload `{text, model, attempts, retry?}`.

## I3 · S3 t6 still called an extra tool

- `tools/s3_batch.py` t6 now states “本轮只允许一次工具调用” and explicitly forbids a second call and `tool.shell` / `tool.ping`, in addition to “do not retry / do not switch paths”.

## I4 · H3 unknown-tool correction needed a constructible entry

- The correction path was already covered by `unknown_tool_name_gets_correction_instead_of_raw_rpc_error`; the entry point is now documented for real-hardware use: with `provider-mock`, `featheragent chat --text 'TOOL:{"name":"tool.fs","arguments":{"path":"a.txt"}}'` must produce `tool.error` containing `未知工具 tool.fs` and the available tool list.

## Settings · model names come from the local model service

- `SettingField` gains `options_source` (`"" | "models"`) and `allow_custom`. The kernel only relays the declaration; each front end resolves the list through the existing `provider.models` RPC.
- `plugins/review-gate/plugin.json` declares `options_source: "models"`, `allow_custom: true` for `guide.model`, `exec.model`, `judge.model`.
- WebUI: a real `<select>` (占位项 “（跟随当前模型）” + every model returned by the service) paired with a text input; choosing an option writes it into the input, so a model the service does not report can still be typed.
- TUI: `←/→` cycles “跟随当前模型 → 模型列表”；when the list is unavailable the field falls back to manual typing and the form says so.
- If `provider.models` fails, both front ends degrade to manual input with an inline hint instead of blocking the page.

## TUI · Enter saves from any field

- Previously only the explicit “保存并应用” row (or `Ctrl+S`) had an action; Enter on a value row did nothing, which read as “saved but not saved”.
- Now Enter on any value row submits the whole form; the enable row toggles first and then saves. `Esc` still discards.

## Permission prompts show the full command

- `tool.confirm_request` now carries `arguments` (verbatim) and `preview` (human-readable): for `tool.shell` the command line (`$ …`) followed by the remaining parameters, otherwise pretty-printed JSON; truncated at 4 KB with the original length noted.
- TUI: a centered “权限申请” popup with tool, risk, the full command, and `y 允许 / n 或 Esc 拒绝`; the context panel keeps a short marker that points at the popup.
- WebUI: the confirm modal shows the same preview in a scrollable `<pre>`; older kernels that omit `preview` fall back to the raw `arguments` JSON.
- New integration assertion: the `tool.shell` confirm request contains `params.arguments.cmd == "echo hi"` and a preview containing the command.

## Naming · FeatherAgent

- Version output, `serve` banner, help header and TUI/WebUI titles show **FeatherAgent**; binary names, subcommand names, ZIP/tar names and paths are untouched.

## Compatibility

- `manifest.settings` fields `options_source` / `allow_custom` are optional and default to empty/false; plugins that do not declare them render exactly as before.
- `review.guide` `feedback` is optional; a plugin that ignores it still produces the same prompt as rc.3.
- `review.warn` is additive; clients that ignore unknown event names are unaffected.
- `tool.confirm_request` gains two fields; the existing `session/token/tool/risk` are unchanged, so rc.3-era front ends still work (they simply show less).
