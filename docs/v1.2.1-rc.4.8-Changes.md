# FeatherAgent v1.2.1-rc.4.8 Changes

> Baseline: `v1.2.1-rc.4.7` (commit `0c51399`)
> Source: Windows real-machine retest report for v1.2.1-rc.4.7, findings N40–N42; N36 still needs a clean-environment check
> Date: 2026-11-27

## Summary

The rc.4.7 retest confirmed two real gains: with `tool.shell` allowed, the small math paper rose 19.5→21.5 and the large paper 40.7→41.6, while FA time dropped to 126 s / 446 s; N38's title-only stop also recovered from MS2 37 / ML02 109 characters to 729 / 1568. N36 produced no valid reading because leaked turns kept returning `interrupted/stopped`.

This release handles the three new findings:

- **N40 (🟠)**: formula checks were still string matches, so `\dfrac{\pi^2}{6}`, `\zeta(2)`, Unicode `π²/6`, `(π^2)/6` and other equivalent forms could miss.
- **N41 (🟡)**: partial-credit steps were too coarse; ML10 had a complete derivation but still scored 1.3/4.
- **N42 (🟡)**: after a long task was force-killed, a leaked turn made the next client on the same session receive the old `interrupted/stopped`.

## N40: wider formula checks

**Observed.** ML02 in `math-large` accepted only `π²/6`, `pi^2/6` and `\frac{\pi^2}{6}`. The 1568-character answer in the report still matched 1/3 and scored 1.0; the report inferred `\dfrac{\pi^2}{6}` or `\zeta(2)`.

**Fix.** ML02's formula check now accepts:

- Unicode superscript: `π²/6`;
- ASCII/LaTeX: `π^2/6`, `π^{2}/6`, `pi^2/6`;
- parenthesized: `(π^2)/6`, `(π²)/6`;
- fractions: `\frac{\pi^2}{6}`, `\dfrac{\pi^2}{6}`, `\frac{\pi^{2}}{6}`;
- reversed product: `\frac{1}{6}\pi^2`;
- zeta: `\zeta(2)`, `ζ(2)`.

ML10's `π/16` also accepts `\frac{\pi}{16}`, `\dfrac{\pi}{16}`, `\frac{1}{16}\pi` and `pi/16`.

**Verification.** New `math_paper_formula_variants_and_steps_are_scored` asserts each form matches and that `π^2/5` does not.

**Boundary.** This remains regex coverage, not symbolic parsing or numeric equivalence. The report's longer-term "parse and compare" proposal is left for later; unknown equivalent forms can still miss.

## N41: step-level ML10 scoring

**Observed.** ML10 is worth 4 but had only 3 checks; a complete trig derivation matching one check scored 4/3≈1.3, so substitution, expansion, reduction and result were not represented.

**Fix.** Four checks, one point each:

1. substitution method: `sin` / trig substitution / `trig` / Beta / B function;
2. substitution expansion: `cos` / substitution / Beta / B function;
3. reduction or double angle: `sin^2` / `sin²` / double angle / reduction / `1/4` / `1/8` / Beta;
4. result: `π/16` and equivalents.

Both the trig-substitution and Beta routes can earn their steps. The regression test is shared with N40.

## N42: stale turns no longer contaminate new clients

**Observed.** After a chat client was killed by a 240 s timeout, a later request on the same session could receive:

```
model.message {"finish":"interrupted"}
chat.finished {"status":"stopped"}
```

**Reproduction.** With the rc.4.7 Linux release and the mock provider, five cycles of "SPIN long turn → kill after 3 s → same-session `echo: clean`" were run. On the fifth cycle the new client received the old turn's `chat.finished(status=stopped)` and exited with `exit=1`, matching the report.

**Root-cause chain.**

- `cancel_connection` only set `cancel=true`, cancelled the provider and emitted `tool.cancelled(client.disconnect)`; it did not bump a run generation or immediately mark the session `Cancelled`.
- `session.create` could unconditionally take the holder for the new connection while the old turn kept running and broadcasting its own `chat.finished`.
- The `chat` CLI subscribed to all events and treated any `chat.finished` as its own turn end, with no `session` or `run` filter.

**Fix.**

- `Session` gains `run_id: AtomicU64`; `chat.send` calls `begin_run()` and returns `run`.
- `run_turn` takes `run_id` and checks `run_is_current` at turn start, each round, after the model returns, before every tool call and before final state persistence. A stale turn returns silently: no state overwrite, no `chat.finished`. The `run_model` stream loop also checks `run_id` and stops pulling deltas once superseded.
- Normal `chat.finished` adds `"run": run_id`; the failure path also carries `run` and only writes `Failed` when the run is still current.
- When a client disconnects mid-turn, `cancel_connection` bumps `run_id` first, then cancels the provider, and marks the session `Cancelled` immediately.
- `session.create` now calls `cancel_connection` for an old holder owned by another connection before taking over.
- The `chat` CLI stores the `run` from `chat.send` and only accepts `chat.finished` with the same `payload.run`; a stale finish prints a notice and is ignored.

**Verification.**

- New integration test `killed_client_does_not_leak_or_block_next_run`: drop a client in a long turn, reconnect to the same session after 100 ms, accept only the new run's `chat.finished(ok)` and require `echo: clean` in the body.
- The rc.4.8 Linux release repeated the 5-cycle kill/reconnect test: 5/5 new clients exited 0 with `status=ok` and exactly one `chat.finished` (run=3 each).
- Wine 6.0.3 smoke ran one SPIN kill/reconnect: the new client returned `status=ok`, and `chat.finished` carried `run=3`.

## Compatibility

- No new frame, endpoint, event kind, or error code.
- `chat.send` adds a `run` (u64) result field; `chat.finished.payload` adds `run` (u64). Both are additive and old clients can ignore them; clients that do not filter by run can still observe stale events.
- `session.create` now cleans an old same-session holder owned by another connection: after a force-killed client, a new connection can take over at once.
- N40/N41 change only the public paper JSON and scoring notes, not the product protocol.

## Not verified

- N36's Chinese evidence floor still needs a clean environment and a real 7B judge; this release does not claim it fixed.
- The actual ML02 answer text from the report was not available; N40 variants follow the report's inference, and whether the real answer reaches 2/3 or 3/3 needs a rerun.
- Whether ML10's four-step rules match a real 4B derivation needs a real-hardware rerun; only the rules are verified here.
- N42's Windows kill timing (Task Manager end-process, named-pipe cleanup) still needs a real retest; Linux/Wine evidence is not a Windows conclusion.
- Numeric-equivalence scoring, other formula variants, TUI feel, high DPI, proxy, network-drive/24h and macOS/arm64 remain uncovered.
