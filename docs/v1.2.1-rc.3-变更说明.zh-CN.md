# FeatherAgent 1.2.1-rc.3 变更说明

> 日期：2026-11-24 · 基线：`v1.2.1-rc.2.1` · 类型：架构调整（插件自述设置）+ review-gate 质量修补

本版把“插件设置”从“每个前端单独适配”改成**声明式**：插件在自己的清单里说清设置项，内核原样转述，所有前端统一渲染。同时修掉 rc.2.1 真机复测提出的 H1–H4。review-gate 仍是实验特性且默认关闭；provider 端点与通道线格式除新增一个 RPC 外不变。

## 架构 · 插件自述设置

### A-01 · 设置由插件声明，内核转述，前端通用渲染

- 每个插件可在 `plugins/<name>/plugin.json` 里声明 `manifest.settings`：
  - `root`——这批字段落在哪个配置路径（缺省 `plugin_settings.<插件名>`）；
  - `title`、`description`——设置页顶部显示什么；
  - `fields[]`——`key`、可选绝对 `path`、`label`、`type`、`default`、`description`、`placeholder`、`min`、`max`、`step`、`options`、`secret`。
- `type` 只允许 `bool | int | number | string | enum`，保证任意前端（TUI、WebUI、将来的 GUI）都能渲染，不需要为某个插件写专用代码。插件不带界面代码，装新插件也不用改前端。
- `feather-plugin` 握手时刻意返回 `settings: None`；清单文件是唯一事实源，避免两处漂移。内核在安装/刷新时读清单并落进登记表。
- `src/proto/types.rs`：`SettingsSchema`、`SettingField`、`SettingsSchema::root_for()`、`SettingField::path(root)`、`SettingField::validate()`。
- `src/runtime/registry.rs`：`Entry.settings` 由 `install()` 写入；`scan_builtin()` 对旧版本登记过、`settings.is_none()` 的条目从清单补齐（`update_settings` + `read_settings`）。

### A-02 · 新 RPC `plugin.settings`（向后兼容的新增）

- `plugin.settings {name}` 返回 `{name, root, title, description, fields[], values{}, defaults{}}`；未声明设置项的插件返回业务错误（“插件 X 未声明设置项”），而不是一个空表单。
- 前端只在打开插件页时调用，因此设置页不依赖插件进程存活。

### A-03 · 校验放在内核，所有前端同一套规则

- `Config.plugin_settings: BTreeMap<String, Value>` 作为未声明 `root` 插件的兜底命名空间。
- `declared_settings()` 把登记表里的 schema 展开成 `(绝对路径, 字段)`；`validate_plugin_settings()` 校验类型、区间、枚举，并拒绝 `plugin_settings.<name>` 下没声明过的键。
- `config.set` 允许对已声明路径首次写入（自动补父级），未声明路径仍报“配置项不存在”。拼错字段会在内核失败，而不是在某个界面里静默吞掉。

### A-04 · TUI 与 WebUI 按声明渲染

- TUI：常规设置页恢复为 11 个字段（Provider…自动放行、保存、取消）；侧边栏每个插件打开的是由 `plugin.settings` 生成的页面，含启用开关、声明字段、保存、取消。文本、整数、小数、布尔、枚举都可编辑，并显示声明区间。
- WebUI：常规页不再有 review-gate 与联网搜索区块；插件页先渲染清单摘要，再按声明渲染表单（复选框、数字、文本、下拉）并通过 `config.set` 保存。
- 两端侧边栏都以**插件名**为主标签（类别只作次要信息），避免类别特殊的插件被误认成别的插件。

## 修复 · review-gate 与 S3（rc.2.1 复测）

### H1 · 判据退化成“指导者写答案、执行者抄句子”

- 现象：三条判据就是答案的三句话；7 次模型调用产出的答案只是把指导者的句子复述一遍，门禁仍判通过。
- 根因：`must_include` 允许 1–40 字（含整句），且判据类型只有 `must_include`，等于只衡量“有没有抄到那句话”。
- 修法：
  - `review.parse_rubric` 现要求 2–5 条，`must_include` ≤20 字，并拒绝整句（句末标点，或 ≥12 字且含 是/的/了/和/并/而/为 这类连接词）；
  - 清单必须至少一条 `must_include`，且至少一条**非子串**判据（`must_not_include`、`min_points`、`pattern`）；
  - `review.hardcheck` 在 judge 之前确定性地核对四类判据：字面子串、禁用短语、要点数（markdown 列表、数字编号、顿号编号）、glob 模式（`*`、`?`、`|`，大小写不敏感，零新增依赖）；
  - guide 提示词改为：只写 2–5 条可核对判据、不写答案、必须至少一条非子串判据。

### H2 · judge 的 evidence 抄了提示词而不是答案

- 现象：judge 用提示词原文凑够 ≥10 字，每条都“通过”，实际没读答案。
- 修法：`review.parse_verdict` 现在接收答案，要求每条 item 的 evidence **和**顶层总结都是答案中连续 ≥10 字的原文窗口（比对前归一化 markdown 标记与空白）。抄提示词、“总结”、“ok”、改写都不算证据，按 judge 失败处理，进入既有重试策略。

### H3 · 畸形工具名只得到一句难懂的 RPC 错误

- 现象：模型输出 `tool.fs` / `tool.read_file`，内核原样转给工具插件，回显 `rpc40401`，且不给真实工具名。
- 修法：`execute_tool` 先用 `available_tools(&session.locked_tools)` 校验名字，不在清单就返回业务错误 `未知工具 tool.fs。可用工具：tool.fs.read, …`。对模型是正常 `tool.error`，不触发熔断。

### H4 · S3 的 t5 不调工具、t6 反复重试

- 修法：`tools/s3_batch.py` 的 t5 明确写“必须先调用 `tool.fs.read`，禁止不调工具回答”；t6 写“只调用一次读取工具，失败就说明原因，不要重试、不要换路径、不要换工具”。S3 口径因此可复现，而不是看提示词运气。

## 兼容性

- `manifest.settings` 是可选字段；没有声明的插件仍在侧边栏出现，页面只有启用开关与“未声明设置项”提示。
- `plugin.settings` 是新增方法，旧客户端不受影响；`chat.finished`、`plugin.list`、`config.*` 语义不变。
- 配置自动迁移：`plugin_settings.<name>` 下已有的未知键保留原地，但在声明之前不能通过 `config.set` 写入。

## 验证

- Linux：**109 个测试，108 通过，1 个默认忽略**（61 lib、12 plugin、2 kernel、3 TUI、3 WebUI、2 golden、26 integration）。被忽略的 `local_web_search_tool_via_kernel` 需要公网。
- `cargo fmt --check` 与 `cargo clippy --locked --all-targets -- -D warnings` 通过。
- 新增覆盖：`plugin_settings_are_relayed_and_validated`（登记表 schema、RPC 返回值、未声明插件报错、声明路径首次写入）、`unknown_tool_name_gets_correction_instead_of_raw_rpc_error`、四类判据的 rubric/hardcheck/verdict 单测。
- 设置页：TUI 用 PTY 实测（打开插件页 → `max_rounds` 2→3 → `Ctrl+S` → `data/config.json` 读到 3）；WebUI 在真实浏览器实测（9 个声明字段含枚举全部渲染，保存后 `max_rounds: 3` 落盘），并在保存后用 WebSocket 复测桥层（收到 `model.message` 与 `chat.finished(ok)`）。
- Windows x64：mingw-w64 交叉编译出 PE；自动化仍只在 Linux 跑。

## 仍需 Windows 真机确认

1. 新装插件在 TUI 与 WebUI 侧边栏都出现，声明字段能渲染、能保存，且不需要改任何前端代码。
2. 用真实 7B guide/judge 跑 review-gate：判据是短语、至少一条非子串、judge 的 evidence 是答案原文。
3. 只有 4B 模型时：guide 的判据要么被拒绝（重试后 `degraded`），要么产出真正可核对的判据；不得靠复述答案判通过。
4. S3 复现性（t5 触发工具、t6 只调一次）与 H3 的纠错文案在真实终端上的表现。
