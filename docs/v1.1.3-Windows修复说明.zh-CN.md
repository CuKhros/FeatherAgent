# v1.1.3 · Windows 复测报告缺陷修复对照

> 输入：`Windows真机复测报告-v1.1.2.md`（Windows x64，Ollama 0.32.9，`qwen3.5:4b`）  
> 输出：v1.1.3 代码与 Windows x64 包。**真机复测仍由用户执行**；Wine 结果只用于冒烟，不作为 Windows 结论。

## 1. 复测基线

v1.1.2 在真机上通过了 8/9 个旧 BUG：GUI token、GUI 连接、并发管道、断连恢复、卷类型、bench、help、TUI 均验证通过；BUG-6 以 Wire Format 文档 + 参考客户端解决。  
本轮新增 4 个问题，其中 2 个为 P0：空响应静默成功、真实 Ollama 工具调用被丢弃。

## 2. 逐项修复

| 编号 | 现象 | 根因 | v1.1.3 修复 | 验证 |
|---|---|---|---|---|
| NEW-1 | 带系统代理时 Ollama 返回 `finish: empty`、`text: ""`，但 `chat.finished status=ok` | 运行环境 `HTTP_PROXY` 干扰本地链路；更关键的是空响应没有错误语义 | 1) 插件子进程保留并补齐 `NO_PROXY=127.0.0.1,localhost,::1`；2) HTTP 客户端确认直连 TCP，不读 `HTTP_PROXY`；3) `content` 与 `tool_calls` 都为空时发 `error` 事件并返回失败，`chat` 命令非零退出 | 空响应 mock：`chat.finished status=failed`，错误原因可见 |
| NEW-2 | 真实 Ollama 能产出 `tool_calls`，但内核 0 个 `tool.*` 事件，最终 empty | `provider-ollama` 只读 `message.content`，完全忽略 `message.tool_calls`；引擎也只从文本 `extract()`，没有结构化入口 | 1) provider 解析 Ollama 原生 `message.tool_calls`（arguments 对象）；2) 解析 OpenAI `/v1` 的 `delta.tool_calls`（arguments JSON 字符串分片）；3) `done` 事件携带结构化 `tool_calls`；4) 引擎优先消费结构化 calls，文本解析仅回落；5) `workspace/xxx` 按安装根解析 | mock Ollama：`tool.call` → `tool.result` → 第二轮模型回复 → `chat.finished ok` |
| NEW-3 | Windows 上 6 项门禁恒红 2 项（启动 65.25 ms、写 P95 4499.7 µs） | 门禁阈值只有 Linux 目标 | bench 增加 `platform`、`boot_limit_ms`、`write_limit_us`；Windows 用启动 <100 ms、写 P95 <10 ms，Linux 保持 20 ms / 100 µs；人类可读输出同步显示分档值 | Linux/Wine `bench` 输出含平台字段；Windows 真机需确认两项转绿 |
| NEW-4 | kill -9 客户端后，该会话仍在后台跑完，浪费算力 | reader EOF 只退出连接线程，没有取消 active_req；session holder 也未释放 | 连接断开时：若会话处于 Assembling/Generating/ToolExecuting，置 cancel + `plugin.cancel(req)` + `client.disconnect` 事件；随后清空 holder。正常完成后退出不产生 cancel 噪音；`Cancelled/Failed` 状态允许下一次 `chat.send` 重试 | 长回答客户端 kill 后，同会话新请求立即 ok |
| P3 | bench 结束打印 `accept error: 管道正在被关闭 (os error 232)` | stop 唤醒连接与 accept 收尾竞争 | Windows 下把 `ERROR_NO_DATA(232)` / `ERROR_BROKEN_PIPE(109)` 视为良性，静默重试 | Wine `bench` 不再刷该错误 |

## 3. 关键实现位置

- `src/bin/plugin.rs`
  - `provider_ollama` 的 `chat` 分支：`native_calls` + `openai_calls` 双路径；空响应 error；`done` 事件带 `tool_calls`。
  - `tool_base` / `tool.fs.read` / `tool.fs.write`：兼容 `workspace/xxx` 根路径与普通会话相对路径。
- `src/engine/mod.rs`
  - `ModelReply { text, finish, tool_calls }`；`run_model` 捕获 done 事件里的结构化 calls；`run_turn` 优先使用结构化 calls。
- `src/server/mod.rs`
  - `cancel_connection`：断连取消 + holder 释放；`chat.send` 允许从 `Cancelled/Failed` 重试；Windows 管道收尾错误静音。
- `src/runtime/plugin.rs`
  - 插件子进程 `NO_PROXY` 补齐回环地址。
- `src/bin/kernel.rs`
  - `chat` 对 `chat.finished status != ok` 返回非零；bench 平台门禁。
- `src/net.rs`
  - 明确直连 TCP，不读取 HTTP 代理环境变量。

## 5. 未验证 / 风险

- **真实 Windows 工具调用**：mock 验证了协议解析与执行链；真实 Ollama `qwen3.5:4b` 的 tool_calls 仍需用户在同一台机器上复测。
- **真实 Windows 代理环境**：Wine/容器无法复现宿主 `HTTP_PROXY`；代码已做回环绕过与空响应报错，但需真机确认。
- **真实 Windows 断连取消**：kill 进程的时序与 Windows 命名管道关闭语义有关；需要真机 kill 后看 `tool.cancelled` / 新连接。
- **Windows bench 门禁**：65.25 ms / 4.5 ms 在 v1.1.3 分档下应转绿，但需真机重新跑。
