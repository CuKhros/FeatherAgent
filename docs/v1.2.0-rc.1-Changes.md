## 2. Dual-platform alignment

### Single version source

- `Cargo.toml` is the source of truth; the `Cargo.lock` root package, all `plugins/*/plugin.json`, and the WebUI `{{VERSION}}` must match.
- `scripts/version-check.sh` runs before Linux packaging and Windows cross-compilation.
- Windows PE `FileVersion` / `ProductVersion` come from `CARGO_PKG_VERSION` in `build.rs`, not hand-written values.
- Local-search User-Agent uses `env!("CARGO_PKG_VERSION")`.

### Build entry points

| Target | Build | Package |
|---|---|---|
| Linux x64 | `scripts/build-linux.sh` (`cargo build --release --bins --locked`) | `scripts/package.sh` → core/webui/plugins tar.gz |
| Windows x64 | `scripts/build-windows.sh` (`x86_64-pc-windows-gnu` + static CRT + `--locked`) | `scripts/package-windows.sh` → one zip with five exes |

Both include `README.md`, `LICENSE`, and `docs/`; Windows also includes `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `CHANGELOG.md`, and `START-HERE.md`. Linux splits into three artifacts as designed.

### Platform differences (only what is necessary)

- Windows uses named pipes; Linux uses UDS; isolated by `cfg` branches in `src/ipc.rs`.
- Windows resources are written by `build.rs`; Linux has no resource section.
- Startup/event-write gates use platform thresholds (Windows cold start <100 ms, write P95 <10 ms); other gates are shared.
- Code, plugin protocol, event-log format, and tool schemas are identical.
