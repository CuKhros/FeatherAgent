# FeatherAgent v1.2.1-rc.3.4 变更说明

本候选版修复 rc.3.3 真机复测的 L1/L2，并给 review-gate 的 Guide / Judge 两个角色增加落盘记录。

该轮已确认 K1/K3/K4：判据分流与短路按设计运行，三次运行 0 degraded；hardcheck 失败时 `review.verdict` 在答案后 0.01 s 落地，证明没有调用 judge。但门禁 0/3 通过，问题不在模型答案：guide 把内核 JSON schema 示例原样抄成判据，连 `must_include:"REVIEW-FINAL"` 一起抄走。该词只属于 mock 夹具，真实任务里不存在，c1 因此永远无法满足。

## L1 · guide 不得抄袭 schema（🔴）

**现象。** 输入 `用三句话说明什么是操作系统` 时，guide 产出的 `criterion`/`check` 是 schema 的说明文字，`must_include` 是 `REVIEW-FINAL`。三次都只挂 `c1`，所以 0/3 是假信号。

**修法。**
- `GUIDE_SYSTEM` 不再包含可抄的示例值。所有取值位都改成尖括号占位符：`<这条判据检查的任务事实>`、`<怎样从答案核对>`、`<任务要求中必须出现的短语>`、`<至少几个要点，填数字>`。mock 专用词 `REVIEW-FINAL` 已从提示词删除。
- 提示词明确要求每条判据针对当前任务输入，不得复用示例的领域或文字；禁止 `REVIEW-FINAL` / `REVIEW-START` 测试标记，禁止保留 `<...>` 占位符。
- `review.parse_rubric` 对 `criterion`、`check`、`must_include`、`must_not_include` 做占位符校验：尖括号模板、`这项检查什么`、`怎么核对`、`检查项`、`核对方式`、`criterion`、`check`、`...`、`…`，以及包含这两句 schema 说明的文本，都会在 exec 轮之前被拒绝。
- `must_include` 若字面值就是 `REVIEW-FINAL` / `REVIEW-START`，且用户输入里没有出现，直接拒绝。该规则**不**扩大到所有大写词，避免把 `HTTP`、`JSON` 这类任务内本来就该出现的术语误杀。
- 解析时把用户输入一并传入，才能区分夹具令牌与真实任务。

内核仍是“给 JSON 结构，让模型填值”，没有改成完全由内核生成骨架表单。占位符硬化加校验已覆盖报告中的失败路径；若后续仍出现抄结构，可再做骨架化。

## L2 · feedback 不再把字面短语递给 exec（🟠）

**现象。** `review.hardcheck` 输出 `答案未逐字出现必须短语『REVIEW-FINAL』`，feedback 原样交给 exec，exec 在答案末尾补上 `REVIEW-FINAL`，hardcheck 通过但内容没有改善。

**修法。** `must_include` 缺失时，evidence 改为 `答案未覆盖判据「{criterion}」要求的关键内容（缺少必须出现的短语）`。不再包含字面值，exec 没有可粘贴的目标；同时保留 criterion 文本，模型仍知道漏了哪条要求。

报告还建议“检测答案仅新增判据短语并告警”。本版未做该差异检测：feedback 去掉字面值已经堵住报告中的路径，而文本 diff 启发式容易把合法的短补充误判为作弊。报告本身也把 L2 视为 L1 的症状。

## Guide / Judge 生成物落盘

两个角色现在都在解析前落盘每次模型输出，畸形 rubric / verdict 不再随重试消失。

- 目录：`<data>/review-artifacts/<session>/`
- Guide：`<unix-ms>-guide-a<attempt>.json` —— 角色、会话、模型、温度、尝试序号、时间、输入、原始输出、解析结果、解析错误。
- Judge：`<unix-ms>-judge-v<vote>-a<attempt>.json` —— 角色、会话、模型、温度、票号、尝试序号、时间、输入、答案、当次 rubric 子集、原始输出、解析结果、解析错误。
- `review.guide` 事件新增 `artifact`（写盘失败时为空字符串）。
- `review.verdict` 事件新增 `attempts`、`votes`、`artifacts`。`attempts` 是该轮 judge 模型调用次数；`votes` 是完成的票数（3 票设置下前两票一致早停时为 2）；`artifacts` 列出该次裁决的全部 judge 文件。
- 落盘是 best-effort：`create_dir_all` 或写文件失败只返回空路径，不让门禁因磁盘问题整轮降级。
- session id 只保留 ASCII 字母、数字、`-`、`_`，其余替换为 `_`，截断 80 字符。
- 文件包含用户输入、答案和模型原始输出，只留在本机 data 目录，不上传。

## 兼容性与设置

- 没有改动 wire 消息、IPC 帧、provider、storage、tool 契约。
- `review.guide` 与 `review.verdict` 只是新增字段，忽略未知字段的消费方不受影响。
- `plugins/review-gate/plugin.json` 仍是 14 个声明字段，没有新增开关；生成物记录始终开启。
- 判据校验变严：抄 schema 的 guide 现在会收到校验错误并重试，而不是生成一条永远无法满足的判据。

## 验证

- Linux：120 个测试，119 通过，1 ignored（`local_web_search_tool_via_kernel`，需公网）。分布：62 lib、19 plugin、2 kernel、3 TUI、3 WebUI、2 golden、29 integration。
- 新增覆盖：`review_rubric_rejects_schema_placeholders`（拒绝 rc.3.3 原样抄来的 rubric，接受 `must_include:"操作系统"` 的合法判据）、`review_hardcheck_does_not_leak_must_include_literal`；集成测试 `review_gate_three_roles_retry_and_approve` 端到端断言 guide 文件与每个 judge 文件都存在于 `data/review-artifacts/<session>/` 且可解析为 JSON。
- `cargo fmt --check`、`cargo clippy --locked --all-targets` 与全量测试通过。
- Linux bench 与包哈希在最终重打包后写入发布说明。
- Windows x64 交叉编译；自动化仍只在 Linux 跑。

## 仍需 Windows 真机确认

1. 用不含测试标记的真实 7B 任务（`用三句话说明什么是操作系统`）：guide 必须写任务相关判据，不再复现 0/3。
2. 检查 `data/review-artifacts/<session>/`：应有 1 个 guide JSON 和每票/每次尝试一个 judge JSON；`review.guide.artifact` 与 `review.verdict.artifacts` 指向这些文件。
3. 故意让 `must_include` 缺失：feedback 必须是“未覆盖判据…”，不能含字面短语，exec 不能靠贴标签通过。
4. 复确认 K1/K3/K4 与此前遗留：负向判据留在 hardcheck、`judge.votes:3` 峰值并发 1、热启动 P90/样本数、内存压力注记、模型下拉、Enter 保存、权限弹窗、S3 t6 单次调用。
