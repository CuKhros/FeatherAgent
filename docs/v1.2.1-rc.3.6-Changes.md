# FeatherAgent v1.2.1-rc.3.6 changes

This candidate fixes N1–N4 from the rc.3.5 real-hardware retest and adds English editions of every top-level binary. The rc.3.5 package verified checklist item 1 completely, but checklist item 2 stopped at 4/5 because N1 still produced an unapproved review round; checklist item 3 reached 4/5; the bench output showed P90 lower than P50; and the N4 fixture phrase was not dropped as a single item. The wire contract is unchanged.

## N1 · `must_include` accepted a conceptual sentence (🟠)

**Symptom.** The guide produced `must_include:["管理计算机硬件和资源"]`. The 7B answer said “操作系统是管理计算机硬件与软件资源…”, which is correct prose but does not contain the exact string. Three rounds failed c1, votes stayed 0, and the round was unapproved.

**Fix.**

- `GUIDE_SYSTEM` rule 4 now allows only proper nouns, terms, file names, commands or fixed forms, 2–12 characters. Conceptual descriptions and sentences are forbidden. Connection words `和 / 与 / 及 / 或 / 是 / 的 / 了` are rejected. A requirement such as “explain the role” or “describe the process” must go to `criterion/check` and be evaluated by the judge, not encoded as `must_include`.
- `MUST_INCLUDE_MAX_CHARS` is reduced from 20 to 12. `must_not_include` keeps the 20-character limit through the separate `MUST_NOT_INCLUDE_MAX_CHARS`.
- `parse_rubric_with_input` rejects a one-character term and reports “至少 2 字”; it also rejects a connection word and explains that the item is conceptual rather than a term.
- `review.hardcheck` no longer requires the literal phrase as one continuous substring. `include_terms` splits the phrase at whitespace, `、`, `，`, `,`, `；`, `;`, and `/` (the slash is kept when the phrase looks like a path with a dot). Every term must appear somewhere in the answer. Thus `管理计算机硬件和资源` is rejected at guide time, while `管理计算机硬件 资源` can pass against the paraphrase “硬件与软件资源”.

The design deliberately keeps term matching lightweight rather than pretending to segment Chinese words. It fixes the observed case without making every legitimate multi-word term fail on harmless word-order changes.

## N2 · Bench reported P90 lower than P50 (🟡)

**Symptom.** For samples `36.9, 35.6, 39.1, 56.3, 36.5`, the rc.3.5 bench printed P50 39.09 ms and P90 36.52 ms. The cause was that `percentile` assumed the caller passed an already sorted array; the boot samples were raw.

**Fix.**

- `util::percentile` copies the samples, sorts them internally, and then applies the nearest-rank rule `ceil(p * n)`. P50 and P90 therefore always come from the same ordered data, and `P50 <= P90` is structural rather than accidental.
- `kernel bench` computes `boot_p50` and `boot_p90` once, reuses both for the JSON and the human-readable line, and adds `metrics.boot_percentiles_consistent`.
- `gates` adds `metrics_consistent`; the boot gate still uses P50. The report sample now yields P50 36.9 and P90 56.3.
- New unit test `percentile_works_on_unsorted_samples_and_p50_le_p90` uses exactly the report's sample and also keeps the original sorted-array checks.

## N3 · Empty responses and malformed tool calls

**Symptom.** rc.3.5 retried an empty model response once, but did not retry Ollama malformed tool-call errors (`XML syntax error`, `element ... closed by ... parameter`). The report showed both kinds in the same session; one bad tool-call format ended the round.

**Fix.** `run_turn` now runs a single retry loop around `run_model`:

- Empty response: at most 2 retries, temperatures 0.70 then 0.75, each emits `model.retry` with `reason:"empty"` and the attempt number.
- Malformed tool call: `is_tool_format_error` detects the Ollama XML error, an element closed by the wrong tag, and generic `tool call ... format/格式/invalid` errors. At most 2 retries, each emits `model.retry` with `reason:"tool_format"` and appends a system correction message telling the model to emit standard JSON `tool_calls` (`name` / `arguments`), not XML.
- Plugin crash: still restarts the provider plugin and retries once.
- Only after the relevant budget is exhausted does the round become `failed`.
- New unit test `tool_format_error_detector_covers_ollama_and_json_errors` covers the report's XML sample, a generic invalid-format string, and a non-match (`ollama 返回空响应`).

## N4 · Fixture phrase was not dropped as one item (🟡)

**Symptom.** The c4 item had `must_not_include:["REVIEW-FINAL","REVIEW-START","<...>"]`. It was only blocked indirectly because another item in the same rubric was rejected. If the other item had passed, c4 would have survived into a rubric that can never be satisfied by a real task.

**Fix.** `strip_placeholder_meta_items` now checks every `must_not_include` phrase. A single hit on `REVIEW-FINAL`, `REVIEW-START`, `<...>`, `__FILL`, `{{` or `}}` marks the whole item as fixture/meta and drops it, with `review.warn` naming the item. Empty `criterion`/`check` are still structural errors and are not silently dropped. New test `review_rubric_drops_fixture_must_not_include_item` keeps c1/c5, drops c4, and asserts the warn text.

## English editions of every top-level binary

All five top-level executables now have an English build, selected by the `-en` filename suffix:

| Chinese | English |
|---|---|
| `featheragent` | `featheragent-en` |
| `featheragent-tui` | `featheragent-tui-en` |
| `featheragent-webui` | `featheragent-webui-en` |
| `feather-plugin` | `feather-plugin-en` |
| `feather-storage` | `feather-storage-en` |

The kernel and TUI English editions are separate source targets (`kernel_en.rs`, `tui_en.rs`) with all user-visible runtime strings replaced. The WebUI shares `webui.rs` but `current_exe()` detects the `-en` suffix and serves `index.en.html` / `app.en.js`; the nine CLI messages also switch. The plugin and storage workers are stdio protocol services with no user-facing UI; their `-en` targets are dedicated build aliases and are byte-equivalent to the Chinese workers. The Chinese binaries remain the default and their behaviour is unchanged.

Cargo builds all targets with `cargo build --release --bins`. The Windows zip contains ten exes (five Chinese + five `-en`). The Linux core tarball contains eight binaries (kernel, plugin, storage, TUI, and their four `-en` editions); the WebUI tarball contains both `featheragent-webui` and `featheragent-webui-en`. English WebUI assets are also staged in `web/` for inspection.

## Compatibility and settings

- No wire message, frame, endpoint, provider, storage, tool or plugin setting changed.
- `bench --json` adds `metrics.boot_percentiles_consistent`; `gates` adds `metrics_consistent`. Both are additive; old consumers can ignore them.
- Rubric validation is stricter for conceptual `must_include` and fixture `must_not_include`; no new setting was added.
- English editions do not change the package layout of existing Chinese executables. `dist/` remains git-ignored.
