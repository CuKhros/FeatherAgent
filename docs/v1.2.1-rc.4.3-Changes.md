# FeatherAgent v1.2.1-rc.4.3 — Changes

Release candidate, 2026-11-25. This patch addresses N19–N22 from the rc.4.2 Windows retest and adds a curated local-model test-report archive under `docs/model-test-reports/`. It does not replace a stable release.

## N19 — cold spawn no longer pays the IPC retry deadline

The rc.4.2 retest reported `cold_spawn_ms_p50` at roughly 3.18 s with five samples between 3.18 s and 3.31 s, while `cold_spawn_lt_250ms` stayed red. The report suspected the bench RPC retry; the actual fixed wait was earlier in `serve` startup:

- before opening the listener, `serve` called the retrying `ipc::connect` to detect an already running kernel;
- N16 made that call wait up to 3 seconds for `ERROR_FILE_NOT_FOUND(2)` / `ERROR_PIPE_NOT_CONNECTED(233)`;
- on a clean install root there is no old kernel, so every cold start waited the full deadline before creating the pipe.

The fix separates one-shot probing from normal client connections:

- `ipc::try_connect` performs a single OS connect attempt and never enters the retry deadline;
- `serve`'s existing-kernel check, `wait_ready`, the end-of-smoke socket probe and `Server::stop` use `try_connect`;
- real clients and `bench` still use the bounded retrying `connect`, so N16's Windows pipe-creation protection remains.

Linux release bench now records cold-spawn P50 **5.848 / 5.376 / 5.556 ms** (three runs; the machine load average was 1.31, so this is not a quiet-host minimum). Windows should return to real process-startup cost rather than a fixed 3 s; that still needs the next real-hardware run.

Test: `try_connect_does_not_enter_the_retry_deadline`.

## N20 — code answers stay in the answer, not in a file

The rc.4.2 seven-question exam exposed a tool-first failure: for “implement an LRU cache in O(1)” the model called `tool.fs.write` and put the code in a file instead of returning a code block. The keyword scorer still awarded 5/5, but the user-visible delivery was worse.

The system prompt now separates content output from file creation:

- when the user asks for code, text, a plan or a translation, answer directly in the response;
- call a file tool only when the user explicitly asks to save, write or create a file;
- tool-first remains for information that must be fetched or changed.

Tests: `system_prompt_separates_content_output_from_file_creation`.

## N21 — first-level list items follow the requested comparison axes

rc.4.2 still lost the “overhead / header size” dimension in a TCP-vs-UDP answer: the first-level items were connection setup, reliability/order and error detection. The prompt now requires:

- confirm the requested count and dimensions before writing a list or comparison;
- make the first-level items map directly to those dimensions;
- when the user gives no dimensions, cover mechanism, reliability/consistency, performance/overhead and applicable scenarios;
- do not spend slots on synonyms of one dimension.

Test: `system_prompt_distinguishes_brevity_from_coverage` now checks the axis rule.

## N22 — write-file review checks the file, not answer wording

rc.4.2's write task no longer ended `failed`, but review-gate kept it `unapproved` while the model re-read the same file four times. The gate was judging only the final answer text, so a correct file could fail because the answer did not repeat its contents.

The review path now handles explicit write tasks as artifacts:

- the engine records the latest successful `tool.fs.write` path and content per turn;
- when the task explicitly asks to write to a file, the judge receives those file contents as labelled review evidence before the final answer;
- the guide is told to check write success, target path and file content, not to demand a verbatim copy in the answer;
- the system prompt tells the model not to re-read a file after a successful write just to self-check.

The file-content evidence is only added for explicit write tasks, so N20's “code answer wrongly written to a file” cannot be hidden by this change.

Tests: `review_file_evidence_is_only_for_explicit_write_tasks`, `review_answer_includes_written_file_content_before_final_answer`, `review_gate_validates_written_file_content_instead_of_answer_wording`.

## Test report archive

`docs/model-test-reports/` now contains nine curated Windows real-machine reports with reusable local-model data, plus extracted CSVs for:

- the rc.4.1 four-task bare-vs-FeatherAgent comparison;
- the rc.4.2 seven-question exam;
- the rc.2 → rc.4 review-gate real-model milestones.

Selection criteria, test environment and caveats are documented in English and Chinese READMEs. Reports that only contain build/UI defect checklists are intentionally excluded.
