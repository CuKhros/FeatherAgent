# FeatherAgent v1.2.1-rc.4.6 — Changes

> Baseline: `v1.2.1-rc.4.5` (`4dc2ded`)
> Source: Windows real-machine retest report for v1.2.1-rc.4.5, findings N32–N35
> Date: 2026-11-26

## Summary

rc.4.6 is not just four report fixes. It starts with a code-accumulation audit that found five real structural debts in rc.4.5: the Chinese/English Rust UI generator had failed, the review parser carried an unreachable branch inside a very large function, `bench --json` mixed several semantics inside `gates`, the output cap was hard-coded to 512, and the English WebUI was a hand-maintained bundle that had lost attachment sending. This round re-planned those five areas from earlier working shapes and fixed N32–N35.

## N32: Windows backslashes in judge output

**Root cause**: N29 gave the judge the successful `tool.fs.write` path and file body. A Windows path such as `C:\Users\...` was copied into a JSON string, so `\U`/`\w` became invalid escapes; all three judge outputs failed to parse and the round ended `degraded`.

**Fix**:

1. New `src/review.rs` holds the review parser; `plugin.rs` keeps only the adapter.
2. New `parse_json_value` + `repair_json_text`: parse standard JSON first; on failure, repair only invalid backslash escapes inside strings (`\P`/`\w` become `\\`), raw newline/CR/tab and control characters below `0x20`; `\u` must have four hex digits. No global replacement, so valid JSON is not damaged.
3. `json_slice` accepts a top-level object or array and picks the earlier `{`/`[`.
4. Evidence paths given to the judge use forward slashes `/`; the judge system prompt requires “paths use forward slashes, and backslashes inside JSON strings must be written `\\`”. Tool events and the final answer keep the original path.

Tests: `verdict_repairs_windows_backslash_escapes`, `rubric_repairs_windows_backslash_escapes`, `json_slice_accepts_top_level_array`.

## N33: truncated answers

**Root cause**: `ModelProfile.max_output` was hard-coded to 512 in two engine sites, `Config` had no output cap, and provider requests never sent `num_predict`/`max_tokens`. M20's 390 Chinese characters are roughly 500 tokens, right at the 512 cap.

**Fix**:

- `Config.max_output` defaults to **2048**, accepts 128–8192, and is editable in Settings.
- Both `ModelProfile` sites read `cfg.max_output`; `run_model` and review calls pass it to the provider.
- Provider: Ollama receives `options.num_predict`; OpenAI-compatible endpoints receive `max_tokens`; temperature is preserved.
- Normal chat `ModelMessage` gains `truncated` (true when `finish=length`).
- A review role ending with `finish=length` fails with “output reached max_output, result may be incomplete” and retries; a half JSON is no longer accepted.

Tests: `truncated_review_output_is_an_error`; provider integration asserts Ollama carries `num_predict:2048` and OpenAI-compatible carries `max_tokens:2048`.

## N34: diagnostics mixed into `gates`

**Root cause**: `bench --json` `gates` held booleans, `platform`, `reliability`, `*_gate_status`, `*_gate_raw`, thresholds and modes. A consumer counting `false` values treated `write_gate_raw=false` as a failure.

**Fix**:

- `gates` contains only boolean verdicts: `binary_le_8mb`, `rss_le_15mb`, `assemble_p95_lt_30ms`, `rpc_p95_lt_1ms`, `metrics_consistent`, `boot_lt_*`, `cold_spawn_lt_*`, `write_p95_lt_*`.
- New `diagnostics`: `platform`, `boot_gate_raw/status/trusted`, `write_gate_raw/status`, `reliability`, `boot_mode`, `boot_limit_ms`, `cold_spawn_mode`, `cold_spawn_limit_ms`, `write_limit_us`.
- `bench --json` top level is `metrics/gates/diagnostics/advisory_gates`.
- `scripts/ci.sh` asserts every `gates` value is boolean and reads status/raw from `diagnostics`.

**Contract change**: old scripts that read `write_gate_status` / `write_gate_raw` from `gates` must read `diagnostics`; verdict keys are unchanged.

## N35: `reliability` only saw memory

**Root cause**: rc.4.5 derived `reliability` only from memory usage; a warm boot of 115 ms still graded `high`, ignoring CPU contention.

**Fix**:

- `env_fingerprint` adds `cpu_load_pct` and `cpu_load_source`.
- Linux: `loadavg_1m / cpu_count * 100`, capped at 100, source `loadavg_1m/cpu_count`.
- Windows: `GetSystemTimes` samples 250 ms; kernel time already includes idle, so usage is `(kernel+user-idle)/(kernel+user)`.
- New `reliability_grade` and `merge_reliability`: either dimension ≥70 is medium, ≥85 is low, the worse wins; unknown only when both are unknown.
- `reliability_basis` reports `mem=%cpu=%`; the note names memory or CPU pressure.

Tests: `reliability_uses_worse_of_memory_and_cpu`, `env_fingerprint_reports_cpu_and_memory_basis`.

## Structural refactor

### Review parser extracted

`src/bin/plugin.rs` drops from 3,028 to 2,219 lines (-809); new `src/review.rs` is 924 lines of pure functions. `parse_rubric_with_input` now builds the base `id/criterion/check/weight` `norm` at the top of the loop, keeps a single early `file_task` branch, handles only normal tasks in the second half, and deletes the unreachable second `file_task` branch.

### Chinese/English generation chain restored

Rebuilt `scripts/en-ui/tui_en.py` and `kernel_en.py` from the `v1.2.1-rc.3.6` 166/72 mapping in current `sorted(zh)` order, adding the rc.4/rc.4.5 entries. `gen-en-ui.py` only generates `src/bin/tui_en.rs` and `src/bin/kernel_en.rs`, then runs `cargo fmt --all`; two runs produce identical hashes and both files have no Chinese residue. CI fails if regeneration produces a diff.

### English WebUI

`web/app.en.js` + `web/index.en.html` are explicitly an independently maintained bundle. New `scripts/check-en-web.py` checks: no Chinese literals in English JS, identical function names/element ids/RPC methods, identical element ids between English and Chinese HTML, `lang="en"` and an app-script reference. Attachment sending, the `file.attach` 60,000 ms timeout and three Chinese leftovers were restored.

### Left alone

`engine/mod.rs` (3,712 lines), `tui.rs` (3,222) and `plugin.rs` (2,219) can still be split, but this round found no specific unreachable branch or duplicate implementation there; it is recorded for a dedicated refactor round in the Code-Accumulation Audit.
