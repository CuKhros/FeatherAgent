## 2. 双平台对齐

### 版本单一来源

- `Cargo.toml` 是版本源；`Cargo.lock` 根包、全部 `plugins/*/plugin.json`、WebUI `{{VERSION}}` 必须一致。
- `scripts/version-check.sh` 在 Linux 打包、Windows 交叉编译前强制运行。
- Windows PE 的 `FileVersion` / `ProductVersion` 由 `build.rs` 从 `CARGO_PKG_VERSION` 写入，不再手写。
- 本地搜索 User-Agent 使用 `env!("CARGO_PKG_VERSION")`，不再硬编码版本。

### 构建入口

| 目标 | 构建 | 打包 |
|---|---|---|
| Linux x64 | `scripts/build-linux.sh`（`cargo build --release --bins --locked`） | `scripts/package.sh` → core/webui/plugins 三个 tar.gz |
| Windows x64 | `scripts/build-windows.sh`（`x86_64-pc-windows-gnu` + 静态 CRT + `--locked`） | `scripts/package-windows.sh` → 5 exe 单 zip |

两边都包含 `README.md`、`LICENSE` 与 `docs/`；Windows 包另含 `SECURITY.md`、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、`CHANGELOG.md` 与 `START-HERE.md`。Linux 三产物按设计文档拆分。

### 平台差异（只保留必要差异）

- Windows 使用命名管道，Linux 使用 UDS；由 `src/ipc.rs` 的 `cfg` 分支隔离。
- Windows 资源段由 `build.rs` 写入；Linux 无资源段。
- 启动/事件写入门禁按平台取不同阈值（Windows 冷启动 <100 ms、写入 P95 <10 ms），其余门禁共用。
- 代码、插件协议、事件日志格式、工具 schema 两端一致。
