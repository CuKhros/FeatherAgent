# FeatherAgent v1.2.1-rc.3.6 变更说明

本候选版修复 rc.3.5 真机复测的 N1–N4，并为全部顶层二进制增加英文版。rc.3.5 的清单 1 已完全达成，但清单 2 因 N1 仍为 4/5、清单 3 为 4/5；bench 出现 P90 < P50；N4 的 fixture 禁词没有按单项丢弃。wire 契约未变。

## N1 · `must_include` 接受概念性整句（🟠）

**现象。** guide 生成 `must_include:["管理计算机硬件和资源"]`。7B 答案写的是“操作系统是管理计算机硬件与软件资源…”，语义正确，但不含这串连续字面。三轮 c1 全失败，votes=0，整轮 unapproved。

**修法。**

- `GUIDE_SYSTEM` 第 4 条只允许专有名词、术语、文件名、命令或固定写法，长度 2–12 字；禁止概念性描述和整句，禁止 `和 / 与 / 及 / 或 / 是 / 的 / 了` 等连接词。像“说明作用”“解释过程”这类要求必须写进 criterion/check 交 judge。
- `MUST_INCLUDE_MAX_CHARS` 从 20 降到 12；`must_not_include` 保留 20 字上限，单独使用 `MUST_NOT_INCLUDE_MAX_CHARS`。
- `parse_rubric_with_input` 拒绝单字词项（提示“至少 2 字”），也拒绝连接词并说明这是概念描述、不是术语。
- `review.hardcheck` 不再要求整串连续子串。`include_terms` 按空白、`、`、`，`、`,`、`；`、`;`、`/` 拆成词项（含点号的路径不拆斜杠），要求每个词项都在答案中出现。因此 `管理计算机硬件和资源` 会在 guide 校验阶段被拒并重试；`管理计算机硬件 资源` 则可在“硬件与软件资源”这类措辞下通过。

这是轻量词项匹配，不做汉语分词；目标是修掉已观察到的失败，同时不因正常语序变化误杀合法术语。

## N2 · bench 出现 P90 < P50（🟡）

**现象。** 样本 `36.9, 35.6, 39.1, 56.3, 36.5` 在 rc.3.5 输出 P50 39.09 ms、P90 36.52 ms。根因是 `percentile` 假设调用方已排序，而 boot 样本是原始数组。

**修法。**

- `util::percentile` 内部复制样本并排序，再按最近秩 `ceil(p * n)` 取值。P50/P90 必然同源，`P50 ≤ P90` 成为结构保证。
- `kernel bench` 只计算一次 `boot_p50`/`boot_p90`，JSON 与人类输出复用同一对变量，并新增 `metrics.boot_percentiles_consistent`。
- `gates` 新增 `metrics_consistent`；boot 门禁仍用 P50。报告样本现在得到 P50 36.9、P90 56.3。
- 新增单测 `percentile_works_on_unsorted_samples_and_p50_le_p90`，直接使用报告样本，并保留原有序数组断言。

## N3 · 空响应与畸形工具调用

**现象。** rc.3.5 只对空响应重试一次，没有覆盖 Ollama 的畸形工具调用错误（`XML syntax error`、`element ... closed by ... parameter`）。报告里两类错误都出现，一次错误格式就结束整轮。

**修法。** `run_turn` 用单一重试循环包住 `run_model`：

- 空响应最多重试 2 次，温度 0.70、0.75，每次发 `model.retry`，`reason:"empty"`。
- `is_tool_format_error` 识别 Ollama XML 错误、元素被错误闭合、以及通用的 `tool call ... format/格式/invalid`。最多重试 2 次，每次发 `model.retry`，`reason:"tool_format"`，并追加 system 纠错消息，要求只输出标准 JSON `tool_calls`（`name` / `arguments`），不要 XML。
- 插件崩溃仍重启后重试一次。
- 相关预算耗尽后才把回合置为 `failed`。
- 新增单测 `tool_format_error_detector_covers_ollama_and_json_errors`，覆盖报告 XML 样本、通用 invalid 字符串和反例（`ollama 返回空响应`）。

## N4 · fixture 禁词没有按单项丢弃（🟡）

**现象。** c4 的 `must_not_include:["REVIEW-FINAL","REVIEW-START","<...>"]` 之前只因为同一 rubric 的另一条被拒而间接拦住；如果另一条通过，c4 会进入一份真实任务永远无法满足的清单。

**修法。** `strip_placeholder_meta_items` 逐条检查 `must_not_include`，只要命中 `REVIEW-FINAL`、`REVIEW-START`、`<...>`、`__FILL`、`{{` 或 `}}` 任一 fixture/占位词，就整条丢弃，并由 `review.warn` 指明条目 id。空 `criterion`/`check` 仍按结构错误处理，不静默丢弃。新增单测 `review_rubric_drops_fixture_must_not_include_item`：保留 c1/c5、丢弃 c4，并断言 warn 文本。

## 全部顶层二进制的英文版

五个顶层可执行文件都提供英文版，以 `-en` 文件名后缀选择：

| 中文版 | 英文版 |
|---|---|
| `featheragent` | `featheragent-en` |
| `featheragent-tui` | `featheragent-tui-en` |
| `featheragent-webui` | `featheragent-webui-en` |
| `feather-plugin` | `feather-plugin-en` |
| `feather-storage` | `feather-storage-en` |

内核与 TUI 的英文版是独立源码 target（`kernel_en.rs`、`tui_en.rs`），运行时可看到的字符串全部替换为英文。WebUI 复用 `webui.rs`，由 `current_exe()` 检测 `-en` 后缀并返回 `index.en.html` / `app.en.js`，9 条 CLI 文案同步切换。plugin 与 storage 是 stdio 协议进程，没有用户界面；它们的 `-en` target 是专用构建别名，与中文 worker 字节等价。中文二进制仍是默认版本，行为不变。

`cargo build --release --bins` 会构建全部 target。Windows zip 含 10 个 exe（5 中文 + 5 个 `-en`）；Linux core 包含 8 个二进制（kernel、plugin、storage、TUI 及四个 `-en`），WebUI 包含 `featheragent-webui` 与 `featheragent-webui-en` 两个。英文 WebUI 资源也放进 `web/` 便于检查。

## 兼容与设置

- 没有改动 wire 消息、帧、端点、provider、storage、tool 或插件设置。
- `bench --json` 新增 `metrics.boot_percentiles_consistent`，`gates` 新增 `metrics_consistent`；都是增量字段，旧消费者可忽略。
- rubric 对概念性 `must_include` 与 fixture `must_not_include` 更严格；没有新增设置。
- 英文版不改变中文可执行文件的包内位置；`dist/` 仍被 gitignore。

## 验证

- Linux 全量：**162 次测试执行，161 通过、1 ignored**（`local_web_search_tool_via_kernel` 需公网）。英文 plugin/storage/WebUI 别名 target 复用同一测试模块，plugin 26 与 WebUI 4 各执行两次；独立逻辑未变。分项：63 lib、26 plugin ×2、2 kernel、3 TUI、4 WebUI ×2、2 golden、31 integration。
- `cargo fmt --all` 与 `cargo clippy --locked --all-targets -- -D warnings` 通过；英文别名改用 wrapper 源码后，Cargo 的重复 target warning 已消除。
- release bench 连跑三次：热启动 P50 **1.142 / 1.167 / 1.163 ms**，P90 **1.761 / 1.190 / 1.170 ms**（每次 P50 ≤ P90，`metrics_consistent:true`）；冷启动 **3.722 / 2.324 / 2.262 ms**；RSS 最大 **3,456 / 3,584 / 3,456 KiB**；写入 P95 **2.634 / 2.704 / 3.005 µs**；组装 P95 **0.138 / 0.143 / 0.123 ms**；RPC P95 **0.030 / 0.030 / 0.028 ms**；门禁全绿；`mem_load_pct` 16、`reliability:high`。
- 英文冒烟：三个 `-en` 主程序 `--help` 与版本 `1.2.1-rc.3.6` 为英文；英文 TUI 在 120×40 PTY 中显示 `Sessions`、`Conversation`、`Context`、`Input`，无中文 UI 标签；英文 WebUI 返回 `<html lang="en">` 和 `RPC timeout`，中文 WebUI 仍返回 `lang="zh-CN"` 和 `RPC 超时`。
- Windows x64 由 `scripts/build-windows.sh` 交叉编译；PE 依赖与包哈希写入发布说明。自动化仍只在 Linux 跑。
