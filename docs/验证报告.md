## 0. v1.1.3 修复摘要（Windows 复测报告驱动）

v1.1.2 真机复测确认 8/9 个旧 BUG 已修复；v1.1.3 处理复测暴露的新问题：

- **NEW-1**：Ollama 空响应不再 `status=ok`；插件子进程补齐 `NO_PROXY` 回环，HTTP 客户端直连不读代理环境变量。

- **NEW-4**：客户端断开触发 `chat.cancel` 语义，取消 active_req 并释放 session holder；`Cancelled/Failed` 会话可重试。
- **P3**：Windows 管道收尾 `os error 232/109` 静默，不再刷错误。
- **自动化测试 58 / 58 通过**；新增结构化工具调用单测、mock Ollama 工具链端到端、空响应失败、断连后同会话恢复。

- Wine 6.0.3 冒烟：`version` / `help` / `doctor` / `stress-log` 通过；`bench` 写入 P95 4.64 ms、体积 0.84 MiB、RSS 14,976 KiB 通过，启动 163.32 ms 受 Wine 开销影响未达 100 ms；`serve` 在 Wine 的重叠命名管道下 `initialize` 超时，**不作为 Windows 结论**。

## 0. v1.1.2 修复摘要（Windows 真机报告驱动）

v1.1.2 只针对 Windows 前端层缺陷，不改 Linux 主链路：

- **自动化测试 56 / 56 通过**（41 lib + 2 GUI + 2 golden + 11 integration）。
- 命名管道改为 **overlapped I/O + `DuplicateHandle` 独立句柄**，修复 BUG-2/3 的并发阻塞与断连占死。
- 随机 token 改用 **系统 CSPRNG**（Windows `ProcessPrng` / Unix `/dev/urandom`），修复 BUG-1。
- Windows 卷类型改用 **`GetDriveTypeW`**，修复 BUG-4。
- GUI/TUI `initialize` **3 秒超时 + 明确报错**，修复 BUG-7/9 的静默挂起。
- 新增 **`help` / `chat` / `serve --codec json`**、bench 进度、`runtime/ipc/endpoint`，修复 BUG-5/6/8 的可观测性与契约问题。
- 新增 **`docs/前端契约-WireFormat.md`** 与 **`tools/feather_client.py`**；Linux JSON 全链路实测通过。
- Windows x64 已重新交叉编译并打包；Wine 冒烟覆盖 `version` / `help` / `doctor` / `stress-log` / `bench` / `serve`。**Wine 的 overlapped 管道客户端不支持，`chat` 在 Wine 下超时，不作真机结论。**
- 真机复测项：overlapped 并发、异常断开、TUI ConPTY、GUI `--app`、网络盘拦截、bench 停止与 Windows 性能。

## 7. 本轮发现并修复的真实缺陷

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | `Args::has("--flag")` 与解析后去掉 `--` 的 key 不匹配 | `doctor --check-storage`、`--stress-log` 被静默忽略，门禁“看似跑了” | 统一 strip `--` 前缀后匹配 |
| 2 | GUI 每条 HTTP 请求新建 UDS 连接 | 会话 holder 绑在已断开的连接上，后续 `chat.send` 被判 observer（40301） | 桥持有单条常驻上游连接；WS 每页面一条连接 |
| 3 | `quote_bare_keys` 逐字节 `as char` 重建字符串 | 中文参数在 JSON 修复后变乱码，且产生重复工具调用 | 改为字节缓冲 + 原样 UTF-8 切片 |
| 4 | mock provider 按**字节**切 16 字节流式分块 | 中文/emoji 被切断成 `�`，模型文本损坏 | 按字符切块 |
| 5 | HTTP chunked 解码逐 chunk `from_utf8_lossy` | chunk 边界切断多字节 UTF-8 → 流式中文乱码（Ollama 路径） | 字节累积，按 `\n` 取完整行再解码 |
| 6 | `tool.shell` 超时只 `kill` `/bin/sh` | `sleep` 子孙仍持有 stdout 管道，`wait_with_output` 挂到 30 s，内核侧表现为工具无结果 | `setsid` 建进程组 + 超时 `kill(-pid, SIGKILL)` |

## 8. 未测项与偏差（如实声明）

### 8.1 未测

1. **真实模型 / S3 指标卡**：本机无 Ollama 服务（`127.0.0.1:11434` 无监听），未接 `qwen2.5-coder:7b` / `deepseek-r1:7b` / `qwen3-vl:4b`。因此工具调用语义正确率、首响应延迟、压缩后任务成功率等 **S3 数字全部留空**；100 轮预算稳定是用 mock provider 验证“机制不超预算”，不能当作小模型效果结论。
2. **Windows 实机**：已完成 `x86_64-pc-windows-gnu` 交叉编译与 Wine 冒烟（命名管道、GUI 桥、RPC、配置重写、50 次截断恢复）；**未在真实 Windows 机器上运行**，TUI 键盘、GUI `--app` 拉起浏览器、SmartScreen 与 Windows 性能数字均未实测。
3. **macOS**：未构建、未运行。
4. **四平台 × 双架构矩阵**（win/mac/linux × x64/arm64）：未测，`sonic-rs`/SIMD 默认值因此未切换。
5. **GUI 原生壳变体（`wry`）**：文档列为可选，本版未实现；默认 `--app` 形态已验证。
6. **长时间稳定性**：未跑 24 h 浸泡 / 内存泄漏曲线。
7. **事件分发单跳 P95**：无独立基准数字。

### 8.2 偏差（均可解释，非静默改口径）

- **`sonic-rs` → `serde_json`**：文档 §10.1 允许不支持 SIMD 的目标走 `json-fallback`；本机未启用 AVX2 构建分支，按回退实现。
- **GUI 前端不用 Svelte/Preact**：采用零构建的原生 HTML/JS（无 Node 工具链），换取“解压即用 + 无前端构建依赖”；契约与安全约束不变。
- **浏览器桥增加 SSE 回退**：主通道是文档要求的 HTTP + WebSocket；SSE 仅作为 WS 不可用时的降级路径（文档 §7.2 也允许 SSE 推送）。
- **WebSocket 实现为自研最小帧编解码**：未引入 `tungstenite`，避免 GUI 包体积与依赖膨胀；仅支持文本帧、分片、ping/pong、close，满足 JSON-RPC 桥需求。
- **Windows GNU 的 C 依赖交叉编译**：`cc` 默认调用宿主 gcc 会产出 ELF 目标文件；构建脚本显式导出 `CC_x86_64_pc_windows_gnu` / `AR_x86_64_pc_windows_gnu`。blake3 汇编静态库在 windows-gnu 下会被 rustc 丢弃（`corrupt .drectve`），Windows 目标改用 `pure` 纯 Rust 实现，哈希结果不变。
- **Windows 文件替换**：`std::fs::rename` 不能覆盖已存在目标；配置 / 插件注册表 / 归档落盘统一走 `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`（Unix 仍是 `rename(2)`）。

## 10. 判定

对照文档 §2.4 / §9.3 的内核硬门禁，6 项全部达标，且留有明显余量（体积 0.93/8 MiB、RSS 2.63/15 MiB、写入 3.4/100 µs）。功能面覆盖 v1.1 的契约层、日志、总线、治理、插件运行时、上下文引擎、编排循环、TUI、GUI 桥、storage/provider/tool 插件与三产物打包。

**结论：v1.1 内核与前端达到文档描述的可交付程度；S3 小模型效果指标因环境缺真实推理服务，保留为待测项，不以 mock 数字充数。**
