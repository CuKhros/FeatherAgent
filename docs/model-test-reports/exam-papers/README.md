## 格式

```json
{
  "id": "small-a",
  "name": "小试卷 A · 通用八题",
  "size": "small",
  "full_score": 20,
  "desc": "覆盖说明",
  "questions": [
    {
      "id": "A1",
      "domain": "代码",
      "prompt": "题目正文",
      "full": 3,
      "checks": [
        {"name": "函数定义", "type": "regex", "val": "def ", "w": 1}
      ]
    }
  ]
}
```

`checks[].type` 目前使用两类规则：

- `regex`：答案中必须匹配 `val`；`w` 为最少出现次数，例如“三条列表”可设 `w: 3`。
- `len_le`：答案长度必须大于 0 且不超过 `val`。

空答案按 0 分处理。部分题目用多条 `checks` 拆分要点，单题得分按通过项比例计算，最高不超过 `full`。

## 数学卷运行与评分

- 数学题可能尝试用 `tool.shell` 调 sympy 等工具。若跑卷器支持，启动 `serve` / `chat` 时显式放行 `tool.shell`；不允许 shell 时，rc.4.7 的系统提示要求模型改用文字推导，但“想用工具却被拒”仍可能丢分。
- 评分是正则覆盖面，不是正确性证明；公式写法敏感。`ML02` 已兼容 `π^2/6`、`pi^2/6` 与 `\frac{\pi^2}{6}`，其他等价形式仍可能漏判。不要把绝对分当作数学正确率。

## 打分局限

规则化打分只反映**覆盖面**，不反映**正确性**：

- 代码题未实际执行，未做编译/运行校验；
- 翻译未做回译比对；
- 设计、推理、摘要等主观题只查关键词与结构。

因此结论应看**同一模型在两种环境下的相对差异**，不要把绝对分当成质量结论。
