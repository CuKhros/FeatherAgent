## 3. N42：强杀客户端后的残留 ✅

测试方式：`timeout -s KILL 3` 强杀 `chat` 客户端（此时模型正在生成），随后立刻用**新会话**发一条 `只回答 OK`。

| 轮次 | 强杀 | 新会话结果 |
|---|---|---|
| 1 | exit=137 | `status=ok`, `text="OK"` |
| 2 | exit=137 | `status=ok`, `text="OK"` |
| 3 | exit=137 | `status=ok`, `text="OK"` |
| 4 | exit=137 | `status=ok`, `text="OK"` |
| 5 | exit=137 | `status=ok`, `text="OK"` |

**5/5 全部干净**，与 changelog 所述「rc.4.7 复现 1/5、rc.4.8 干净 5/5」一致。
`run_id` 代际机制生效，被强杀的 turn 不再污染后续会话。

> 附带观察：内核进程**意外退出**后，`runtime/ipc/ready` 文件会残留，此时 `chat` 报
> `named pipe unavailable: win32=2；ready 标记存在，端点可能繁忙或内核正在重启` ——
> 报错文案已经能区分「ready 在但端点不在」这种情形，比早期清晰很多。

## 4. N36：中文 evidence 门限 ⚠️（附 N43）

写文件任务（review 开启）连跑 2 次：

| # | 结果 | 说明 |
|---|---|---|
| 1 | `ok` / `pass=True` / `votes=1` | **9 字中文 evidence 被接受** ✅ |
| 2 | `degraded` | `审批项 c3 的 evidence 过短（须至少 6 个汉字或 3 个英文词）：""` |

### 4.1 🟠 N43：判据不合格的原因是 **evidence 为空字符串**

第 2 次的报错里，引号内是 `""` —— 不是"句子太短"，而是**judge 什么都没写**。

门限从"10 字"放宽到"6 汉字 / 3 英文词"之后，`三条要点已写入文件` 这类短句已经能被接受（第 1 次即通过）。
剩下的失败是 **judge 输出质量**问题：7B 在某一票里给出了空 evidence。

**建议**：把"evidence 为空"与"evidence 过短"分开处理——
空 evidence 应视为**该票无效并重试**，而不是**该判据不合格**。当前实现会直接让整轮 degraded。

### 5.1 🔴 N44：XML 畸形工具调用复发

同一轮的内容完全正确，但收尾时报错：

```
error: XML syntax error on line 4: element <function> closed by </parameter>
```

**这是 N15 / N25 修过两次的老问题以新变体回归**（本次是 `line 4`）。
在这条 case 里文件/答案都已经产出，却仍被标记 `failed`。

**建议**：XML 恢复逻辑应做到「已经拿到正文就不要再因尾部畸形标记失败」——
即优先保留已解析的内容，把畸形标记降级为 `review.warn`。

## 6. N41：ML10 四步拆分 ✅（附 N45）

### 6.1 判据生效

关闭 review 后连跑 2 次：

| # | status | 长度 | ①代换 | ②展开 | ③降幂 | ④π/16 |
|---|---|---|---|---|---|---|
| 1 | ok | 1550 | ✓ | ✓ | ✓ | （脚本正则失效，见下） |
| 2 | ok | 3514 | ✓ | ✓ | ✓ | （同上） |

**①②③ 稳定命中**，说明四步拆分确实能让"用了三角代换并化简"的答案拿到步骤分。

### 6.2 ④ 的判定：其实是命中的，是我的测试脚本写错

单独复跑一次并 dump 原文，结尾处确实有：

```
**答案：** $\boxed{\displaystyle \int_0^1 x^2\sqrt{1-x^2}dx = \frac{\pi}{16}}?$
```

**是我在 bash 里写正则时转义被吃掉**（`\\frac` → `\frac` 变成了字面量），导致误判为未命中。
按实际内容，这一轮应为 **4/4**。

### 6.3 🟠 N45：模型会在算对之后自我推翻

同一段原文（上文提到的结尾）：

```
**答案：** ... = \frac{\pi}{16}}?
让我用 Python 验证一下这个推导是否准确... 实际上我应该相信数学推导。
使用 Beta 函数：$I = \frac{1}{8}\cdot B(\frac{3}{4}, \frac{5}{4})$？不对，重新整理：
...
$$I = \frac{1}{8}B(\tfrac{7}{4}, \text{}?)$$
抱歉，这个推导太复杂了。让我给出最简洁的答案：
```

**它先给出正确答案，然后想"用 Python 验证"，但没有真正调用工具，转而自我否定，最后草草收尾。**

这是本轮最值得注意的行为：**工具可用却没被使用，反而变成了"我该不该验证"的犹豫源**。
建议在系统提示里明确"若没有把握可以调用工具验证；一旦调用就等结果，不要凭想象否定已有的推导"。

### 6.4 长度分布（说明答案稳定性仍差）

同题 5 次：**140 / 973 / 1136 / 1550 / 3514** 字。

- 140 字那次直接在中途停（N38 的提示词缓解并非 100% 生效）
- 3514 字那次则包含大量反复验算

**结论**：N41 的"四步给分"方向正确，但**答案长度方差仍然很大**，评分会因此抖动。
