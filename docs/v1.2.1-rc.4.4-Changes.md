# FeatherAgent v1.2.1-rc.4.4 — Changes

Release candidate, 2026-11-26. This patch addresses N23–N27 from the rc.4.3 Windows retest and fixes the TUI long-conversation overscroll. N28 is a test-scorer limitation, not a product change. It does not replace a stable release.

## N23 — bench no longer hangs on server stop/join

rc.4.3 reported no output after `bench[2/6]` for 150 s; five `bench --json` runs were 0 bytes. The regression has two layers: `Server::stop` only allowed 5 one-shot probes at 50 ms (about 250 ms), and bench joined the server thread forever.

Fix: `Server::stop` retries one-shot wake connections for a 3 s deadline at 20 ms intervals; bench warm/RPC joins poll `is_finished` with a 5 s deadline and return explicit `bench:boot_stop` / `bench:rpc_stop` errors instead of hanging. `scripts/ci.sh` now wraps `bench --json` in `timeout 90` and checks the seven release gates.

## N24 — write-file tasks are judged from the file, not guide-invented words

rc.4.3 still returned `failed` for a write task: `notes2.txt` was written, but the guide demanded literal words that were absent, and a second criterion required the answer text to mention the write tool. `votes` stayed 0 and hardcheck failed the turn.

A shared `util::requests_file_write` keeps engine and plugin aligned. For explicit write tasks all guide criteria become `judge_only`, deterministic keys are stripped, and the judge receives `tool.fs.write` path plus `status=success` and the file body. If the write succeeded but a later model reply is malformed XML or empty, the engine emits a deterministic written-path summary and continues to review instead of failing the turn.

Tests: `requests_file_write_is_explicit_about_target`, `review_rubric_moves_file_task_terms_to_judge`, `review_rubric_keeps_hard_items_for_code_tasks`, `review_answer_includes_written_file_content_before_final_answer`, `write_fallback_names_the_file_without_claiming_missing_content`, and the write-file integration test now requires judge votes greater than 0.

## N25 — XML open-tag recovery

The rc.4.3 report showed the same function-open/parameter-close error as rc.4.1. `xml_tool_call` used the first `>` as the open-tag end, so a missing `>` swallowed the first parameter tag. The parser now takes the earliest of `>`, newline, and the parameter marker; parameter open tags get the same tolerance.

Test: `malformed_xml_function_open_without_gt_is_recovered`.

## N26 — comparison answers expand each axis

The rc.4.3 TCP/UDP answer covered only mechanism/connection and reliability, missing performance/overhead and scenarios, in 117 characters. The system prompt now requires a comparison-specific pass: list mechanism/connection, reliability/consistency, performance/overhead and typical scenarios; one line per dimension, both sides carrying values; this task is not subject to default brevity.

## TUI — no virtual overscroll at the top

Pressing Up at the top of a long conversation kept increasing `chat_scroll`, while the renderer only clamped the display value. After N extra Up presses, Down needed roughly N presses before moving. `draw` now takes a mutable `App` and clamps `chat_scroll` to `max_scroll` before computing the offset; Chinese and English TUI share the `clamp_chat_scroll` helper.

## N27 — bench temp dirs are cleaned on every exit path

The timed-out rc.4.3 run left `fa-bench-*` directories because cleanup was a single `remove_dir_all` at the end. `BenchTempDir` now removes the directory in `Drop`, and startup removes `fa-bench-*` entries older than 24 hours without touching fresh directories. Chinese and English bench share the behavior.

## N28 — Q7 bold headings are a scorer limitation

The report confirms Q7 contained all three items; the scorer only accepted dash or numeric lists and scored bold headings 0/3. No product change; the scorer should recognize bold sub-headings alongside unordered lists.
