# FeatherAgent v1.2.1-rc.3.4 changes

This candidate fixes L1/L2 from the rc.3.3 real-hardware retest and records the Guide / Judge rollouts of review-gate.

That retest verified K1/K3/K4: criterion routing and short-circuit ran as designed, three runs produced **0 degraded**, and a hardcheck failure emitted `review.verdict` 0.01 s after the answer, proving no judge call. Approval was still **0/3**, but the cause was the guide copying the kernel JSON schema: `criterion:"这项检查什么"`, `check:"怎么核对"`, `must_include:"REVIEW-FINAL"`. `REVIEW-FINAL` is a mock fixture word absent from the real task, so `c1` could never pass.

## L1 · The guide must not copy the schema (🔴)

**Symptom.** For `用三句话说明什么是操作系统`, the guide wrote schema description text as `criterion`/`check` and used `REVIEW-FINAL` as `must_include`. All three runs failed only `c1`, so 0/3 was a false signal.

**Fix.**
- `GUIDE_SYSTEM` no longer contains copyable example values. Every slot is an angle-bracket placeholder: `<这条判据检查的任务事实>`, `<怎样从答案核对>`, `<任务要求中必须出现的短语>`, `<至少几个要点，填数字>`. The mock-only `REVIEW-FINAL` is removed from the prompt.
- The prompt now requires every criterion to target the current task input, forbids reusing the example domain or wording, forbids `REVIEW-FINAL` / `REVIEW-START` test markers, and forbids keeping `<...>` placeholders.
- `review.parse_rubric` rejects placeholders in `criterion`, `check`, `must_include`, and `must_not_include`: angle-bracket templates, `这项检查什么`, `怎么核对`, `检查项`, `核对方式`, `criterion`, `check`, `...`, `…`, and any text containing the two schema sentences. Rejection happens before the exec round.
- A `must_include` equal to `REVIEW-FINAL` / `REVIEW-START` is rejected when the user input does not contain it. The rule is **not** widened to all uppercase words, so task terms such as `HTTP` or `JSON` are not false positives.
- Rubric parsing now receives the user input, which is what separates fixture tokens from real tasks.

The kernel still provides a JSON structure for the model to fill; it does not generate a skeleton form. Placeholder hardening plus validation covers the reported failure path. If copying persists, skeleton generation is the next step.

## L2 · Feedback no longer hands the literal phrase to exec (🟠)

**Symptom.** `review.hardcheck` returned `答案未逐字出现必须短语『REVIEW-FINAL』`; feedback passed it to exec, exec appended `REVIEW-FINAL`, hardcheck passed, and the content did not improve.

**Fix.** A missing `must_include` now produces `答案未覆盖判据「{criterion}」要求的关键内容（缺少必须出现的短语）`. The literal value is gone, so exec has nothing to paste; the criterion text remains, so the model still knows which requirement is missing.

The report also suggested detecting “answer changed only by adding the criterion phrase”. This version does not implement that diff heuristic: removing the literal already closes the reported path, and a text diff can misclassify a legitimate short addition as cheating. The report itself treats L2 as a symptom of L1.

## Guide / Judge artifacts

Both roles now write every model output before parsing, so malformed rubrics/verdicts no longer disappear with a retry.

- Directory: `<data>/review-artifacts/<session>/`
- Guide: `<unix-ms>-guide-a<attempt>.json` — role, session, model, temperature, attempt, time, input, raw output, parsed result, parse error.
- Judge: `<unix-ms>-judge-v<vote>-a<attempt>.json` — role, session, model, temperature, vote, attempt, time, input, answer, the rubric subset, raw output, parsed result, parse error.
- `review.guide` adds `artifact` (empty string when writing failed).
- `review.verdict` adds `attempts`, `votes`, and `artifacts`. `attempts` counts judge model calls in that round; `votes` counts completed votes (2 when early stop skips the third); `artifacts` lists every judge file for that verdict.
- Writing is best-effort: `create_dir_all` or file-write failure returns an empty path and never degrades the gate.
- Session ids keep only ASCII alphanumerics, `-`, `_`; other characters become `_`, truncated to 80 characters.
- The files contain the user input, answer, and raw model output. They stay in the local data directory and are never uploaded.

## Compatibility and settings

- No wire message, IPC frame, provider, storage, or tool contract changed.
- `review.guide` and `review.verdict` only gained fields; consumers that ignore unknown fields are unaffected.
- `plugins/review-gate/plugin.json` still declares 14 fields. No switch was added; artifacts are always recorded.
- Rubric validation is stricter: a guide that copies schema text now gets a validation error and retries instead of emitting an impossible criterion.
