# FeatherAgent v1.2.1-rc.3.5 变更说明

本候选版修复 rc.3.4 真机复测的 M1、M3，并强化 S3 的 t6 工具调用提示（M4）。rc.3.4 复测的三项清单全部达成：判据真实化（5 个任务 4 个有真实判据，通过 2/5）、artifacts 路径一一对应、feedback 不再泄漏字面短语。剩下的失败是判据质量问题，不是传输或接线问题。

该轮真实 7B 数据：a1 操作系统任务 3 轮 unapproved，a2 TCP 三次握手 **degraded**（guide 连续 3 次被拒），a3 内存泄漏 approved，a4 TCP 三次握手 approved，a5 禁用「系统」任务 unapproved（要求自相矛盾，判定合理）。通过率 2/5，degraded 1/5。

## M1 · guide 把占位符当成了判据内容（🟠）

**现象。** a2 的 `c1` 正常（`must_include:["SYN","ACK"]`），`c3` 是 `min_points:3`，但 `c2` 写成了关于占位符本身的判据：`criterion:"禁止使用示例中的占位词"`、`check:"检查答案中是否出现 <...> 占位符"`、`must_not_include:["<...>"]`。校验正确拒绝 c2，但三次重试原样重复，整轮 degraded。

**修法。**

- `GUIDE_SYSTEM` 的示例值全部改成 `__FILL_CRITERION__`、`__FILL_CHECK__`、`__FILL_PHRASE__` 这类不可能出现在自然语言里的形态，不再使用 `<...>`。模型可以照抄字段名，但不会把尖括号 mock 当成任务短语。
- 提示词新增规则 8：示例只示范字段名与结构；不要在判据里讨论占位符、示例或模板本身，不要把 `__FILL_*__` 写进 `must_not_include`，不要写「禁止使用占位符」这类自我指涉条目。
- 提示词新增规则 9：不要写主观判据（简洁、清晰、美观、通顺、易懂、逻辑性强、排版好看）。需要篇幅或形态时用 `min_points`、`pattern`、`regex` 这类可计数判据，否则省略该条。
- `rubric_placeholder` 新增拒绝 `__FILL*__` 与包含 `{{` / `}}` 的文本。
- `placeholder_meta(t)` 只在**具体元词**（「示例中的占位」「示例判据」「模板标记」`__FILL`、`<...>`）与**动作词**（禁止 / 不得 / 不能 / 不要 / 检查 / 出现 / 使用 / 包含 / 提到 / 填写）同时出现时命中。刻意不使用泛化的「占位」单词，因此「解释占位符的作用」「模板方法模式」这类合法任务不会被误杀。
- `strip_placeholder_meta_items` 解析 JSON 后逐项检查，只丢弃 `criterion`/`check` 命中占位符或 `placeholder_meta` 的条目，保留其余真实条目；空 `criterion`/`check` 不丢弃（属于结构错误，必须交给正式解析报错）。若全部条目都是占位/示例文本，解析直接返回明确错误，不产出空清单。
- `parse_rubric_with_input` 先做清洗再走正式校验，成功时把 `已丢弃占位符/示例判据 c2（…）` 写入 `warn`。对 a2 样本，`c1` 与 `c3` 保留，整轮不再 degraded。
- `must_include` 同时接受字符串与字符串数组。a2 的 `["SYN","ACK"]` 会规范成数组，由 hardcheck 逐项要求全部出现，而不是静默退化成 judge-only。

报告的第 4 条建议「内核生成骨架、模型只填值」仍未实现。占位符硬化、元指令、元判据清洗、数组支持与主观降级已覆盖报告中的失败路径，同时避免把提示词变得更僵硬。

## M3 · 主观判据让 judge 摇摆（🟡）

**现象。** a1 的 `c4` 是「判断答案是否简洁明了」，没有可核对标准。judge 三轮给出不同结论，把整轮拖成 unapproved。

**修法。**

- 提示词规则 9 要求 guide 不写这类条目。
- 若描述型条目仍命中明确的主观形容词（`简洁`、`清晰`、`美观`、`通顺`、`易懂`、`可读性`、`逻辑性`、`完整性`、`语气`、`排版`），就标记 `advisory:true` 与 `advisory_reason`，不进入 hardcheck，也不进入 judge，并通过 `review.warn` 说明：`验收项 cX 是主观判据（含『…』）：不计入门禁；需要时改成可计数/可核对的格式`。
- `review.parse_rubric` 输出新增 `advisory` id 列表，与 `judge_only` 并列，内核与生成物都能看到哪些条目被降级，而不是被静默忽略。
- 匹配只列具体形容词，不包含「明了」：`说明了用途` 含有该子串，曾把真实描述判据误分类。
- 内核兜底：解析结果 `hard_items == 0` **且** `judge_only == 0`（只有主观评价或空描述）时，`review_prepare` 带错误 `整份清单没有可执行判据：只有主观评价或空描述，必须补一条可计数/可核对的判据` 重试；第三次仍不合格就失败，不再因为「条目数 > 0」放行。硬判据 + 主观条目的混合清单正常放行；描述型条目仍按原逻辑交给 judge。

## M4 · S3 t6 偶发不调工具直接作答（🟡）

`tools/s3_batch.py` 的 t6 提示词改为「必须先调用 tool.fs.read 一次……禁止不调用工具直接凭猜测回答」，同时保留「本轮只允许一次工具调用」和对 `tool.shell` / `tool.ping` 的禁止。这里只做提示词硬化；4B 模型的实际行为仍需真实 Ollama 复跑。

## 兼容性与设置

- 没有改动 wire 消息、IPC 帧、provider、storage、tool 契约。
- `review.parse_rubric` 输出新增 `advisory`；`review.warn` 新增丢弃与主观判据说明。忽略未知字段的消费方不受影响。
- `plugins/review-gate/plugin.json` 仍是 14 个声明字段，没有新增开关。
- 结构错误与占位符仍严格拒绝；放宽的只有数组 `must_include`，以及自动丢弃自我指涉的示例条目。

## 仍需 Windows 真机确认

1. 用真实 7B 复跑 a2：guide 不得写关于占位符的判据；出现时应被丢弃并打 `review.warn`，整轮必须给出裁决而不是 `degraded`。
2. 复跑 a1：`c4` 要么不出现，要么标记 advisory；不得进入 judge，整轮不得因它摆成 unapproved。
