# FeatherAgent v1.2.1-rc.4.2 — Changes

Release candidate, 2026-11-25. This patch fixes the four actionable findings from the rc.4.1 Windows retest (N15–N18). N10, N12 and N13 were confirmed fixed on real hardware; N11's plain-text recovery worked, but the XML-style variant did not. This candidate does not replace a stable release.

## N15 — XML-style tool calls are recovered instead of failing the turn

The rc.4.1 retest produced a call in the Qwen/Ollama function-tag style. Ollama reported an XML syntax error and the whole turn ended with `chat.finished status=failed`, even though `workspace/notes.txt` had already been written.

Two layers now handle this:

- the context parser accepts a function tag with `=` or `name="..."` and parameter children with `=` or `name="..."`; values run to the parameter close tag, a missing function close tag is tolerated, and tool aliases normalize as in N11;
- the Ollama provider no longer turns every streamed `error` or HTTP 500 into a terminal error. If the accumulated text contains a function tag, it tries the parser first; a recovered call is pushed into `native_calls` and the stream finishes as `tool_calls` instead of `failed`. If recovery fails, the original error is still surfaced and the existing `tool_format` correction and retry budget remain.

Tests: `xml_function_parameter_fallback`, `malformed_xml_function_without_close_is_recovered`; the existing plain-text and alias tests remain.

## N16 — bench RPC connect survives the Windows pipe creation window

The rc.4.1 retest still saw about 1/2 bench failures with a missing `featheragent.sock` under the run's unique RPC directory. The unique temporary root was already working; the remaining gap is the window between `wait_ready` (which connects once and disconnects) and the benchmark's own `Client::connect`.

Changes:

- Windows `ipc::connect` retries `ERROR_FILE_NOT_FOUND(2)` and `ERROR_PIPE_NOT_CONNECTED(233)` as well as `ERROR_PIPE_BUSY` inside its 3-second deadline, with a short sleep instead of a busy loop;
- `bench` creates the `rpc` directory explicitly and retries `Client::connect` for up to 10 seconds after `wait_ready`, instead of connecting only once;
- the `[bench:rpc_connect]` error keeps the socket path and the last OS error.

This is a bounded retry, not an infinite wait. Linux bench behavior is unchanged; Windows still needs the real-hardware retest.

## N17 — `boot_gate_trusted` moves out of the regular gate count

`boot_gate_trusted` is an environment-quality signal. In the rc.4.1 report it was false while `reliability="low"`, and a manual count of all boolean `gates` values produced 9/10 even though every actual release gate passed.

`bench --json` now separates:

- `gates`: release gates only; `boot_gate_trusted` is removed;
- `advisory_gates`: `boot_gate_trusted`, `boot_gate_status` and `reliability`, explicitly not part of `passed/total`;
- `metrics`: keeps `boot_gate_trusted` for diagnostics.

Human output prints `advisory (not counted in gates)` beside the gate object. The Chinese and English kernels are kept in sync. N9's advisory semantics are unchanged: a low-reliability boot measurement does not turn the boot gate red.

## N18 — “concise” does not mean “omit required points”

The rc.4.1 4B comparison scored FeatherAgent 15/16 versus a bare model 15/16, but FeatherAgent was about twice as fast (49s versus 104s). The remaining quality gap was coverage: the system prompt's “回答简洁” wording made list/answer tasks drop points such as ordering or overhead.

The system prompt now says:

- default: concise, tool-first, no fabrication;
- when the user asks to list, compare, enumerate, or explain all points: cover every required point; do not omit content merely to stay short.

Test: `system_prompt_distinguishes_brevity_from_coverage`.
