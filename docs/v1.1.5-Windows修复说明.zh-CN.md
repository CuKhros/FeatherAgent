# v1.1.5 · Windows v1.1.4 复测修复与设置页

> 输入：`Windows真机复测报告-v1.1.4.md`（Windows x64，Ollama 0.32.9，`qwen3.5:4b`）  
> 输出：v1.1.5 代码与 Windows x64 包。**真机复测仍由用户执行**；Wine 结果只用于冒烟，不作为 Windows 结论。

## 1. v1.1.4 复测结论

报告确认 v1.1.3 的 NEW-A～NEW-D 全部修复：

- `--allow tool.fs.write,tool.shell` 真实执行并落盘；`--confirm-timeout` 默认 0 立即拒绝。
- 拒绝回注为结构化 `tool.result`（`permission_denied` + reason + tool）。
- 空响应出现 `model.retry`（`temperature=0.7`）。
- Windows bench 6/6 全绿；WebUI `--app` 独立 profile 实际写入 92 MB。

但报告暴露了 1 个系统性缺陷和 2 个连带问题：业务错误被当作插件崩溃、路径前导斜杠跨平台语义不一致、S3 脚本判定偏松。

## 2. 逐项修复

| 编号 | 现象 | 根因 | v1.1.5 修复 | 验证 |
|---|---|---|---|---|
| NEW-E | 路径越界等业务错误触发 `plugin.degraded`，整个工具插件被熔断，模型退化为输出裸 `tool_call` 文本 | `execute_tool` 把 `PluginError::Rpc` 与崩溃一样计入 `record_failure`；熔断粒度是插件 | 新增 `tool.error`（业务错误，不计数、不重启、不熔断）；仅崩溃/超时/IO 计技术失败；按**工具名**连续 3 次熔断该工具；熔断后从 tools schema 移除，并注入“不要输出 tool_call 语法”的 system 提示 | mock 读不存在的文件：出现 `tool.error`，无 `plugin.degraded`，模型继续正常答复 |
| NEW-F | 模型写 `/workspace/x` 在 Windows 被当作当前盘符根，越界 | `tool_base` 只处理 `workspace/`，不处理 `/workspace/` | 工具层归一化 `workspace/x`、`/workspace/x`、`\workspace\x`、`./workspace/x` 为安装根相对路径；工具描述与 system prompt 明确“不要以 / 开头” | 单测覆盖四种写法；integration 用 `/workspace/lead.txt` 成功读到内容 |
| NEW-G | S3 脚本只统计 `tool.result`，把 `tool.failed` / `tool.error` 算成“执行无错” | 判定口径漏事件 | 严格口径：有 `tool.result`、未被拒绝、`result` 内无 `error`，且无 `tool.error` / `tool.failed` | `tools/s3_batch.py` 已更新；输出改称“工具执行成功（严格口径）” |

### 2.1 为什么业务错误不再走 `tool.failed`

- 路径越界、缺参数、文件不存在是工具**正常返回的业务结果**，不是进程故障。
- `tool.error` 会作为 tool 消息回注，模型下一轮能看到原因并改路径/说明失败。
- 只有崩溃、超时、stdin/stdout IO 故障才计入技术失败；连续 3 次只熔断该工具，不连累 `tool.fs.read` 等其他工具。
- 熔断后的回合会在 system 消息中明确“工具不可用，请直接用文字回答，不要输出工具调用语法”。

## 3. 新功能：各 UI 的设置页

### 3.1 设置入口

- **WebUI**：右上角 `⚙ 设置`，打开全屏设置页。
- **TUI**：输入 `/settings`（`/config` 同义），打开独立设置页；`Esc` 返回。

### 3.2 可配置项

| 分组 | 字段 | 说明 |
|---|---|---|
| 服务端 | Provider 插件 | `provider-mock` / `provider-ollama` 等已安装 provider |
| 服务端 | Base URL | Ollama / OpenAI 兼容端点 |
| 模型与采样 | 模型 | 从 `provider.models` 读取列表，也允许手填 |
| 模型与采样 | 温度 | 0.00–2.00，下一轮普通推理生效；空响应重试仍固定 0.7 |
| 高级 | 上下文窗口 | 512–131072 tokens |
| 高级 | 单轮最大工具回合 | 1–32 |
| 高级 | 自动放行安全工具 | 写入 `auto_allow_safe`，即时更新权限门 |

### 3.3 保存与应用链路

```
UI 表单
  → config.set {patch}
  → Kernel::set_config
      → merge + serde 校验
      → 写 data/config.json（临时文件 + 原子替换）
      → 更新 cfg（RwLock）
      → 更新 Gate.auto_allow_safe（AtomicBool）
      → 发 config.changed
  → 下一次 run_model / run_turn 使用新 provider、model、temperature、context_window、max_turns
```

- `config.get` 返回完整配置；`provider.models` 调 provider 的 `probe`，Ollama 读 `/api/tags`，OpenAI 兼容读 `/v1/models`。
- 设置页只在用户点“保存并应用”/按 `Ctrl+S`/`Enter` 提交，不做输入即改。
- TUI 设置页字段：Provider、Base URL、Model、Temperature、Context window、Max turns、Auto allow safe、保存、取消；模型列表支持手动输入。

- `web/index.html` / `web/app.js` / `web/style.css`
