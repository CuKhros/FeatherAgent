## 1. 定位与边界

### 1.1 一句话定位

> **FeatherAgent = 面向 1B~14B 本地小模型的「上下文引擎」+ 一个**体积极小、零运行时依赖**的可移植 Agent 内核。**

三个卖点：

1. **小模型上下文工程**（技术差异，研发重心）
2. **极致轻的内核**（Rust 单二进制，目标 **≤ 8 MB**，空闲 RSS **≤ 15 MB**）
3. **可移植性**（零运行时依赖；安装根 / 数据 / 工作空间三类路径可独立外置）

「一切皆插件」仍是实现手段，不作为卖点宣称。

### 1.2 与 DeepSeek Harness 的关系：互操作，不替代

dsh（MIT、Cordis 内核、`@deepseek-ai/dsh`）已覆盖插件化、轨迹追溯、配置组合、KV Cache。本项目存在理由三条：

| 维度 | dsh | FeatherAgent |
|---|---|---|
| 运行时 | 需 Node.js | **零依赖单二进制**（无 Node / 无 Python / 无 JVM） |
| 内核体积/启动 | Node 基线 ~50 MB / 数百 ms | **≤ 8 MB / < 20 ms 冷启动** |
| 优化重心 | 通用 Harness | **1B~14B 专用**上下文工程 |

**互操作三条路径**（非各玩各的）：
1. `bridge.mcp-client`：直接接入 dsh 生态里的 MCP server
2. `bridge.mcp-server`：把 FeatherAgent 工具反向暴露给 dsh
3. preset 语义对齐，便于用户迁移

> **Kill criteria（写进文档，防自我安慰）**：若 dsh 推出「无 Node 的单二进制分发 + 小模型上下文层」，
> 本项目应重新评估定位，而不是硬撑。

### 1.3 目标用户与非目标

- **用户**：有本地显卡 / 内网机 / NAS 的开发者与半技术用户；v1.x 起 GUI 可用，覆盖面扩展到普通用户。
- **非目标**：不内置推理引擎、不分发权重、不做云账号、不遥测、不做移动端。

### 1.4 体积模型（三套指标，互不混用）

| 指标 | 定义 | v1.1 目标 | 性质 |
|---|---|---|---|
| **开箱门禁** | 首次解压、零使用、零用户插件 | 软 **≤ 100 MiB** / 硬 **≤ 1 GiB** | **CI 硬断言** |
| **稳态占用** | 典型使用后的目录总量 | 1 ~ 2.5 GiB | 监控指标 |
| **用户配额** | 可配置软上限 | 默认 4 GiB | UI 可见 + 一键清理 |

> 1 GiB 是**开箱硬门禁**，不是终身上限。使用增长由「配额 + 可见 + 可清理」管理（§6.5）。

## 2. 总体架构

### 2.1 分层视图（三进程模型）

```
┌───────────────────────────────────────────────────────────────┐
│ 前端层（独立分发，均可替换）                                      │
│   TUI 插件（随主包）    GUI 插件（独立包）    第三方前端（契约接入）  │
└──────────────────────────┬────────────────────────────────────┘
                           │ ① 前端契约 Frontend Contract（IDL v1，UDS/命名管道 + WS）
┌──────────────────────────┴────────────────────────────────────┐
│ FeatherAgent 内核（Rust，单二进制，目标 ≤ 8 MB）                   │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ A. 编排核心：事件总线（单写多读）· 会话状态机 · 循环调度        │ │
│  │ B. 事件日志：自研追加格式（无 SQLite，§3.1）                  │ │
│  │ C. 插件运行时：进程外 RPC 管理 + WASM(wasmi) 沙箱            │ │
│  │ D. 治理层：协作式权限门 · 环境沙箱 · 卷类型守卫 · 路径解析      │ │
│  │ E. 契约层：插件契约 IDL + 前端契约 IDL + 多版本适配            │ │
│  └──────────────────────────────────────────────────────────┘ │
└──────────────────────────┬────────────────────────────────────┘
                           │ ② 插件契约 Plugin Contract（IDL v1，stdio JSON-RPC / MCP 兼容）
┌──────────────────────────┴────────────────────────────────────┐
│ 插件进程层                                                     │
│  ★ context-engine   storage/index（SQLite·FTS·向量）           │
│  provider-*         tool-*        bridge-*                     │
└──────────────────────────┬────────────────────────────────────┘
                           │ OpenAI 兼容 / 运行时原生协议
┌──────────────────────────┴────────────────────────────────────┐
│ 本地推理运行时（外部）：Ollama / llama.cpp / LM Studio / vLLM     │
└───────────────────────────────────────────────────────────────┘
```

**两条契约、一个内核**：内核只懂「契约」不懂「能力」。

### 2.2 内核三大不变式（v1.1 增补第 4 条）

1. **内核不懂 Agent**：删掉任何能力（含循环）都不改内核。
2. **能力皆插件**：插件走语言中立、版本化契约。
3. **一切可追溯**：append-only 事件流支撑 replay / fork / 审计。
4. **内核不持有业务存储**：内核只写「自己的追加日志」，**所有可查询的索引（FTS/向量/知识库）都在插件进程里**。

> 第 4 条是 P2 的架构化表达：它把 SQLite、向量、全文检索从内核彻底剥离，
> 换来体积与启动优势，也让索引层可以随时换实现（SQLite / redb / tantivy / 外部服务）。

### 2.3 内核语言：Go → Rust（决策翻转说明）

#### 为什么翻转

v1.0 的选型矩阵里，**权重最大的一行是「1~2 人 6 个月到 v1.0」**，Go 靠这一行胜出。
本轮前提变更后：

| 原矩阵中的 Go 优势 | 前提变更后的实际情况 |
|---|---|
| 「1~2 人 6 个月到 v1.0」可行性 | **前提被移除**（不排工期）→ 该权重归零 |
| 「TUI/GUI 生态成熟（Bubble Tea / Wails）」 | TUI 有 `ratatui`（同等成熟）；GUI 改为 **Web 前端 + 可选 wry 壳**，与语言解耦 |
| 「JSON/HTTP/SQLite 生态极成熟」 | **SQLite 已移出内核**（P2）；JSON/HTTP 用 `sonic-rs`/`hyper` 同样成熟 |
| 「并发模型契合事件总线」 | Rust 的 `mio`/`tokio`/`glommio` 提供同等甚至更精细的控制（io_uring） |
| 体积 ~30 MB | Rust 可控到 **4~7 MB** |
| GC 停顿 | **无 GC**，延迟确定性更好 |

→ **移除时间权重后，Go 唯一剩下的优势是"写得快"，而这恰是本次不考核的维度**；
而体积、启动、内存、延迟确定性四项全部指向 Rust。

#### 决策矩阵（v1.1）

| 维度 | C | **Rust（选定）** | Zig | Go（回退项） |
|---|---|---|---|---|
| 二进制体积（极致配置） | 1~3 MB | **4~7 MB** | 1~3 MB | 15~30 MB |
| 内存安全 | 手工，CVE 高危 | **编译期保证** | 手工（有安全检查） | GC |
| 延迟确定性 | 高 | **高（无 GC）** | 高 | 中（GC 停顿） |
| 异步/IO 生态 | 手工 epoll | **mio/tokio/glommio(io_uring)** | 较弱 | 成熟 |
| 跨平台交叉编译 | 需自建工具链 | 好（`cross`/`zigbuild`） | **最好**（`zig cc` 内建） | 好 |
| 内存安全 + 极致体积兼得 | ❌ | ✅ | ⚠️（无编译器保证） | ❌ |
| 与 C ABI 嵌入（libfeather） | 原生 | **`extern "C"` + cbindgen** | 原生 | 需 cgo |

**结论：Rust**。C 已无必要（同样的体积，丢掉内存安全）；Zig 保留为「体积再压 30%」的备选；
Go 保留为**可回退项**（§2.5 的可逆性设计使其代价可控）。

#### 体积手法（Rust 侧具体手段）

| 手段 | 预期收益 |
|---|---|
| `[profile.release] opt-level="z"` + `lto="fat"` + `codegen-units=1` + `panic="abort"` + `strip="symbols"` | 基线 -60% |
| 移除 `std` 中不必要能力（避免 `std::process` 全量、避免 `backtrace`） | -300 KB |
| **不引入 SQLite / goja**（P2/P3） | **-10 MB** |
| `serde_json` → `sonic-rs`（或自写零分配解析器） | 同量级，速度 +3~5× |
| `regex` → `regex-lite` | -900 KB |
| `anyhow`/`thiserror` → 手写错误枚举 | -150 KB |
| `hashbrown` + `ahash`（替代默认 SipHash） | 速度 +2×，体积微小 |
| `wasmi`（解释器）而非 `wasmtime`（JIT） | -8 MB |
| Linux 静态链接 musl；Windows 静态 CRT | 单文件免依赖 |
| `cargo bloat` / `cargo-udeps` 纳入 CI | 防反弹 |

> 目标不是「最小」，而是「**在不牺牲可维护性的前提下压到 8 MB 以内**」。
> 若压不到，宁可接受 10 MB，也不做 `no_std` 自虐式优化。

### 2.4 性能与体积指标（v1.1 极致目标）

| 指标 | v1.0 目标 | **v1.1 目标** | 手段 |
|---|---|---|---|
| 内核二进制 | ~30 MB | **≤ 8 MB** | §2.3 体积手法 |
| 冷启动到可用 | 未定义 | **< 20 ms** | 无 SQLite 初始化、无 GC 预热、mmap 懒加载 |
| 空闲 RSS | 未定义 | **≤ 15 MB** | 无 DB 缓冲池、arena 分配 |
| 事件写入（不含 fsync） | P95 < 5 ms | **P95 < 100 µs** | 追加写 + 组提交（§3.1） |
| 事件分发（单跳） | P95 < 1 ms | **P50 < 50 µs / P95 < 200 µs** | 单写多读无锁队列（§3.2） |
| 上下文组装（不含摘要模型） | P95 < 150 ms | **P95 < 30 ms** | 零拷贝分段拼接、预算计算 SIMD |
| 内核 ↔ 插件 RPC 往返 | P95 < 2 ms | **P95 < 1 ms** | 长度前缀 msgpack 帧（契约不变） |
| 端到端首 token（8B + prefix cache） | ≤ 1.5 s | ≤ 1.0 s | 前缀稳定 + 组批 |

> 指标全部进 CI 基线，回归 >10% 即门禁失败。

### 2.5 决策可逆性（保住最坏情况）

- 插件走**进程外契约**、前端走**前端契约** → 换内核语言**不波及插件生态与前端**。
- 契约 IDL 与实现语言无关；`libfeather` C ABI 嵌入 SDK 让第三方可绕过内核直用上下文引擎。
- 因此：即使 Rust 路线出现意外，回退 Go 只需重写内核本体，**插件与前端零改动**。

## 3. 内核设计（新增章节）

### 3.1 事件日志：自研追加格式（替代 SQLite）

**为什么不用 SQLite 写事件流：**
- SQLite 是 B-tree + WAL 双写：单条小事务大约 **0.1~1 ms**（`WAL` + `synchronous=NORMAL`），
  并不算慢；但**写路径形态是随机 B-tree 页管理，而非纯追加**，且自带库体积与写放大成本；
- 内嵌 SQLite 需带进 8~10 MB（modernc 或 C 库）；
- 追加写场景下 SQLite 的优势（事务、索引、并发）**用不上**，因为事件流只追加、只按顺序读。

**格式设计（分段 + 记录）：**

```
Segment 文件：data/sessions/<session_id>/<first_seq:016x>.log
  默认段大小 4 MiB，写满即滚动（段名不重复、只增不改）

记录布局（little-endian）：
  +0   u32   magic    = 0xFA1B0001
  +4   u16   kind     事件类型枚举（user.message / model.delta / tool.call / ...）
  +6   u16   flags    bit0=payload 为 msgpack，bit1=payload 已压缩
  +8   u64   seq      会话内单调递增
  +16  u64   ts_wall_ns  墙钟 CLOCK_REALTIME（Unix epoch 纳秒）
  +24  u32   len         payload 字节数
  +28  u32   crc32c      覆盖 [0, 28) ∪ payload（自校验，含头）
  +32  bytes payload
```

> **时间戳语义（勘误 R1）**：落库的是**墙钟 `CLOCK_REALTIME`**，不是单调时钟。
> `CLOCK_MONOTONIC` 不跨重启、不跨进程可比，归档文件换个开机周期后时间戳就失去意义，
> 跨会话排序与 replay 展示都会失效。**单调时钟只用于进程内耗时测量（§2.4 的性能计数器），绝不写进持久化记录。**
>
> **排序规则**：会话内**按 `seq` 排**（唯一权威，与时钟无关）；跨会话按 `ts_wall_ns` 排，
> 容忍 NTP 回拨造成的少量乱序，UI 侧做单调化修正（`max(prev, cur)`）。

**写入路径（单写者）：**
- `O_APPEND` + `writev`（头与 payload 一次系统调用）
- **组提交**：默认 5 ms 或累计 256 KiB 触发 `fdatasync`（可配 `--sync=always|interval|never`）
- 批量写合并：同一事件循环 tick 内的多条事件拼一次 `writev`

**崩溃恢复：**
- 启动扫描最后一段，从段内最后一个 `.idx` 检查点向后校验 CRC
- 遇到损坏记录 → **截断到上一条完好记录**，写一条 `log.recovered` 元事件（记录丢失字节数）
- 因此日志**永不部分写入**：要么整条有效，要么被截断

**索引（旁路，不在内核）：**
- 内核只维护极简旁路索引：每 256 条记录写一个 `<seq, offset>` 的 `.idx` 项（每项 16 B）
- **FTS / 向量 / 按字段查询 → storage 插件进程读日志后自建**（§6）

**归档：**
- 归档 = 段文件顺序拼接 + zstd 压缩为 `data/archive/<session>.fadb`，保留原始记录字节，可无损重导入
- 归档后原段删除，**但留下 `session.archived` 事件**（写在新段里，形成审计链）

### 3.2 事件总线：单写多读

- **写侧**：单一生者（编排核心），无锁；写入即发布
- **读侧**：多个订阅者（插件、前端、索引器），各自持有**环形缓冲游标**（SPSC per subscriber）
- 慢订阅者**不阻塞**生者：游标落后超过阈值即**丢弃 + 记录 `subscriber.lagged`**（订阅者自行从日志补齐）
- WASM 订阅者只能拿到**过滤后的投影**（只投递它声明订阅的 kind），避免全量事件泄露

### 3.3 插件运行时

| 形态 | 隔离 | 用途 |
|---|---|---|
| **进程外（主推）** | 独立进程 = 唯一真安全边界 | 所有第三方插件、storage、provider、tool |
| **WASM（wasmi）** | 进程内沙箱，fuel 计量 + 无系统调用 | 轻量、高频、无副作用的纯计算插件（压缩算法、解析器、评分器） |
| **内置（Rust，编译进内核）** | 同进程，信任边界 | 仅最小基础件（契约适配、日志写入） |

> **JS 插件已移除**（P3）。需要 JS 生态时：① 优先找同功能 Rust/WASM 实现；② 用进程外插件跑 Node（明示"系统依赖型，破坏零依赖承诺"）。

### 3.4 路径解析与环境沙箱

- **路径根**：以可执行文件位置为根，绝不依赖 CWD / 环境变量 / 注册表
- **三类路径可分离**（§7.1）：安装根 / 数据目录 / 工作空间
- **子进程 env 沙箱**：启动任何子进程前，unset / 覆盖已知 HOME 依赖变量清单（`RIPGREP_CONFIG_PATH`、`XDG_*`、`HOME` 等，随版本维护）
- **严格模式**：`--strict-temp` 把 `TMPDIR/TEMP/TMP` 重定向到 `runtime/tmp/`；提供白名单例外（TLS/字体缓存等）

### 3.5 卷类型守卫

**问题**：便携目录会被放到 OneDrive / 坚果云 / NAS 映射盘 / U 盘。
**SQLite 在网络盘不受支持；在同步盘会因客户端并发持有文件而锁冲突甚至损坏。**（注：v1.1 内核日志是纯追加文件，抗损性优于 SQLite，但**索引库仍在 storage 插件里用 SQLite，风险不变**。）

| 检测 | 实现 |
|---|---|
| 卷类型 | Win：`GetDriveTypeW`（FIXED/REMOTE/REMOVABLE）；Linux：`statfs` 的 `f_type`（nfs/cifs/fuse/overlay） |
| 已知同步盘 | 路径匹配 `OneDrive*`/`Dropbox`/`Nutstore`/`BaiduNetdisk`/`Google Drive`（名单随版本维护，可配置） |
| 锁行为探测 | 启动时对目标目录试独占开锁 `LockFileEx` / `flock` |

| 判定 | 数据目录 | 工作空间 |
|---|---|---|
| 本地固定盘 | ✅ | ✅ |
| **网络盘** | ❌ **拒绝启动** | ⚠️ 强告警 |
| **同步盘** | ❌ 拒绝 + 一键迁移向导 | ⚠️ 告警 |
| 可移动盘 | ⚠️ 告警 | ✅ |

`featheragent doctor --check-storage` 可单独诊断，输出可粘贴结论。

## 4. 插件系统

### 4.1 契约（IDL）与传输分离

- **契约**：版本化 IDL —— 方法名、参数 schema、错误码、生命周期握手、能力协商。
- **传输**：v1 = stdio JSON-RPC（MCP 兼容）；**v1.1 起默认长度前缀 msgpack 帧**（契约不变，仅编码/分帧层替换，插件无需改代码）。
- **为什么不用进程内 dlopen C ABI**：无隔离（一次 segfault 全崩）、跨语言内存所有权易错、6× 构建矩阵、收益≈0（编排是 I/O 密集，微秒差异被推理秒级延迟淹没）。
- **C ABI 的正确用法**：`libfeather` 嵌入 SDK（供 C/C++/Rust 应用**嵌入**，如 libgit2 定位），而非插件加载。

### 4.2 多版本适配

- 内核维护 `vN → vLatest` 适配层；manifest 声明 `api: ">=1.2 <2.0"`
- 主版本 N 在 N+2 发布后弃用，≥6 个月迁移窗口
- 所有适配层过同一套 **conformance suite**（契约一致性测试），CI 门禁

### 4.3 安全边界（诚实声明）

| 形态 | 边界性质 | 越权后果 |
|---|---|---|
| 内置（Rust） | **信任边界**（评审 + 构建签名） | 可拖垮内核 |
| WASM | 半安全边界 | 仅限导入表能力 + fuel 上限 |
| 进程外 | **真安全边界** | 白名单文件 + 资源限额 + kill |

**不得把「协作式权限门」称为"沙箱"**——它只拦"守规矩的调用者"。

### 4.4 供应链

| 机制 | v1.1 | 说明 |
|---|---|---|
| 包内容哈希（BLAKE3） | ✅ | 安装时计算记录 |
| 发布者签名（Ed25519） | ✅ 字段预留，`--allow-unsigned` 才可跳过 | 跳过后 UI 常驻警告条 |
| 权限变更重确认 | ✅ | 升级时权限扩大必须重新授权 |
| 黑名单 | ⬜ 本地名单文件（离线可更新） | 插件市场阶段启用 |

### 4.5 崩溃 vs 取消

| 场景 | 事件 | 循环行为 | 用户可见 |
|---|---|---|---|
| 主动取消 | `tool.cancelled`（终态） | 中止本轮，下轮注入"已取消" | 中止提示 |
| 插件崩溃 | `tool.failed(crash)` | **重试 1 次** → 仍失败则本轮标记该工具不可用，**继续推理** | 告警条 |
| 持续崩溃 | `plugin.degraded` | 连续 3 次熔断该插件 | 插件页标红 |

> 原则：**崩溃不中止会话**。小模型下工具失败是常态，中止的体验代价远大于降级续跑。

## 5. 上下文引擎（v1.0 §4 无变更，此处仅列要点）

1. **Provider 统一接入**：`chat / stream / FIM / embed / rerank` 五类能力探测 + 降级；模型画像（上下文窗口、温度、工具/JSON/视觉支持）。
2. **四层压缩**：L1 滑窗 → L2 摘要卡（附原文引用可 pin）→ L3 `task_state` 置头 → L4 向量记忆召回。
3. **容错解析**：JSON 修复 → markdown 提取 → 正则回退；GBNF/guided decoding 按需只编译当前可见工具集（≤12 个）。
4. **KV Cache 友好**：稳定前缀（system + task_state + 工具定义）置头；**会话开始即锁定技能集与工具集**，中途变更需告警并接受一次 cache miss。
5. **多模态**：消息分块；图像 token 独立预算（≤1500/轮），超限先降分辨率（短边 ≤768）再裁数量；**图像不落 DB**，存 `workspace/media/<blake3>.<ext>`，事件流记引用。
6. **技能规范**：`skill.yaml` 声明 `keywords/regex` 命中条件 + `inject.position=system_tail` + 预算（单技能 ≤400 token，会话总 ≤1200）。

> v1.1 变更点：L4 向量检索的实现从「内核内纯 Go 余弦」改为「**storage 插件进程内的向量索引**」（§6.2）。

## 6. 存储与索引（重写：从内核剥离）

### 6.1 三层职责划分

| 层 | 归属 | 职责 |
|---|---|---|
| **事件日志（写）** | **内核**（§3.1） | 只追加、只顺序读、自校验、组提交 |
| **索引与查询（读）** | **storage 插件进程** | FTS 全文、字段索引、会话列表、统计 |
| **向量 / 知识库** | **storage 插件进程** | embedding 存 BLOB、向量索引、召回 |

> 内核不知道「表」「索引」「SQL」这些概念。它只知道「写一条记录」「按 seq 读一段」。

### 6.2 storage 插件的默认实现

**默认：SQLite（bundled C 库，`rusqlite`）** —— 理由：生态最稳、FTS5 成熟、单文件、可被外部工具打开排障。
体量：~2 MB（库）+ 索引数据，**计入插件配额，不计入内核**。

**可选实现（契约不变，插件可换）：**

| 实现 | 适用 | 取舍 |
|---|---|---|
| `redb`（纯 Rust KV） | 追求免 C 依赖 / 交叉编译极简 | 无 SQL，需自建倒排 |
| `tantivy`（纯 Rust 全文） | 全文检索为主、量级大 | 体积大（~5 MB），索引独立文件 |
| 外部服务（Meilisearch / Qdrant） | NAS / 多机共享 | 需额外部署，破坏"零依赖" |

### 6.3 向量检索：三层冷热 + 内存预算

| 层 | 内容 | 常驻 |
|---|---|---|
| **L0 热** | 当前会话 + 最近 5,000 条 | ✅ ~15 MB |
| **L1 温** | 按 tag/时间分区，命中分区才加载（LRU） | 按需 |
| **L2 冷** | 全量在库，仅显式全库搜索时扫描 | ❌ |

- 内存预算 `VECTOR_MEM_BUDGET` 默认 **128 MB**
- 规模 > 100,000 条 → 启用 **HNSW**（纯 Rust `instant-distance` / `hnsw_rs`）
- **明确**：不是每次查询读库反序列化；L0 启动加载、L1 按需、L2 流式扫描
- 向量按 `(model, dim)` 分区，换 embedding 模型不互相污染

### 6.4 replay / fork / re-execute

| 操作 | 语义 | 副作用工具 |
|---|---|---|
| replay | 只读重建 | 绝不重执行 |
| re-execute | 从某点恢复运行 | 逐项人工确认；`destructive` 默认灰置 |
| fork | 复制事件流为新会话 | **默认不重放副作用工具**；已有结果原样注入，未完成调用转「待确认占位」 |

> 事件流是历史记录，不是待办清单。任何重执行必须越过确认门。

### 6.5 数据生命周期与保留

> **append-only 的作用域 = 单个会话内部**。跨会话的归档与清理是设计内能力，且必须留审计事件。

| 对象 | 策略 | 默认 |
|---|---|---|
| 会话日志 | 超阈值归档（zstd → `data/archive/`）或删除 | 最近 200 会话 / 90 天 |
| 图像 / 附件 | 外部文件 + 引用计数，归零即 GC | >90 天且无引用 |
| 向量 | 跟随记忆条目生命周期 | — |
| 工作空间产物 | **永不自动删除** | — |
| 日志 | 滚动 + 总量上限 | 50 MB / 7 天 |

`featheragent gc [--dry-run]` + TUI/GUI 清理面板（显示各项占用）。

## 7. 前端体系（重写：契约驱动 + 独立分发）

### 7.1 三类路径分离

| 类别 | 内容 | 默认 | 可迁移 |
|---|---|---|---|
| **安装根** | 内核、出厂插件、运行时工具、配置 | 自身目录 | 整目录搬 |
| **数据目录** | 事件日志、索引库、备份、归档 | `<根>/data` | 停机迁移（向导 + 校验） |
| **工作空间** | 用户产物、附件、导出 | `<根>/workspace` | **热切换** |

### 7.2 前端契约（Frontend Contract）

前端 = 内核的**客户端**，与插件契约**分开定义**。最小方法集：

```
session.create / list / resume / fork
chat.send / cancel
event.subscribe(kinds)            // 服务端推送，SSE 或 WS
tool.confirm / deny
ctx.inspect                       // 预算占用、压缩摘要、召回条目
config.get / set(path, value)      // 含三类路径与配额
storage.stats / gc(run|dry)
plugin.list / enable / disable / install
```

- **传输分层（勘误 R1：明确归属，避免自相矛盾）**：

  | 段 | 实现 | 归属 |
  |---|---|---|
  | 内核 ←→ 前端 | **仅 UDS / 命名管道** | 内核 |
  | 浏览器 ←→ GUI 桥 | HTTP + WebSocket | **GUI 包的启动器** `featheragent-gui`，不是内核 |

  > **内核不实现任何 HTTP/WebSocket 服务。** 否则要拉 `tokio` 全量 + `tungstenite`，
  > **8 MB 体积预算与 §10.1 的 `mio` 选型会同时破功**。
  > GUI 包内的 `featheragent-gui`（独立小二进制）职责：拉起内核 → 连 UDS →
  > 在 `127.0.0.1:<随机端口>` 提供静态资源 + WS → 双向桥接。

- **桥接端安全（必须，非可选）**：
  - 仅绑 `127.0.0.1`（**禁 `0.0.0.0`**），端口随机
  - 启动时生成**一次性随机 token**，经启动 URL 传入；HTTP 与 WS 握手均校验
  - 校验 `Origin`，并拒绝 `Host` 非 `127.0.0.1`/`localhost` 的请求
    （**防 DNS rebinding**——本机服务被任意网页打穿是这类架构的经典攻击面）
  - token 不落盘、不进日志、进程退出即失效

- 多前端可同时连接；非持有方降为**观察视图**（§4.5 单写者模型）
- 契约版本独立演进，前端可跨内核小版本兼容

### 7.3 三种前端形态

| 前端 | 分发 | 实现 | 体积 |
|---|---|---|---|
| **TUI** | **随主包** | `ratatui` + `crossterm` | ~3 MB |
| **GUI（默认形态）** | **独立包** | Web 前端（Svelte/Preact + htm）+ **`featheragent-gui` 桥接器**（静态资源 + WS，**不在内核**）+ 浏览器 `--app` 窗口 | 静态资源 ~1.5 MB（gzip） |
| **GUI（原生壳变体）** | 独立包（可选） | `wry`（WebView2 / WKWebView / WebKitGTK）+ 同一套 Web 资源 | +3~5 MB |

**为什么 GUI 默认不捆绑 WebView 运行时：**

- **`--app` 模式**（Chrome/Edge）：无边框独立窗口，**零额外二进制、零 WebView2 依赖判定**，老系统也不挑
- 直接消灭了 v1.0 的三个老问题：WebView2 用户数据目录漏水、Linux WebKitGTK 缺失、AppImage 体积膨胀
- 代价：需要机器上有 Chromium 内核浏览器（Win/mac 默认有；Linux 基本有）→ 缺失时提示安装原生壳变体

**`--app` 的两个必须约束（勘误 R1）：**

1. **必须显式指定独立 Profile 目录**
   ```
   chrome --app=http://127.0.0.1:<port>/?t=<token> \
          --user-data-dir=<安装根>/runtime/gui-profile \
          --no-first-run --disable-features=Translate,MediaRouter
   ```
   不指定的话 Chrome 会用**用户默认 Profile**，localStorage / 缓存 / 历史全部落进用户目录 ——
   「零用户目录写入」承诺与 CI 的进程树写入 diff **会当场失败**。
2. **前端必须无状态**
   一切状态经 `config.get/set` 存内核；`localStorage` 仅作可选缓存且可关闭
   （换 Profile、换机器、清缓存都不应丢状态）。

> **承诺边界（与 Ollama 同理）**：浏览器是**第三方程序**，它自身的 crashpad / 更新器
> 仍可能触及用户目录，**不在「零写入」承诺范围内**。
> CI 审计把浏览器进程树列为**外部程序白名单**（单独统计、不判失败），
> 但必须断言「`runtime/gui-profile` 存在且确实被该浏览器使用」。

**GUI 独立分发的好处：**
- 开箱包保持 ≤ 100 MiB，GUI 不背在主包里
- GUI 迭代节奏与内核解耦（改 UI 不必发内核）
- 第三方可基于前端契约做自己的前端（VS Code 插件、Web 面板、移动端）

### 7.4 GUI 功能（首版即做）

三栏布局：
- 左：会话列表 + preset 切换
- 中：对话流（Markdown、工具卡片可展开看参数/结果、耗时与 token 角标）
- 右：**上下文面板**（预算占用条、压缩摘要可 pin、记忆召回、**存储占用与配额**）

设置页：三类路径（含工作空间迁移向导）、配额、卷类型健康检查、插件管理。

## 9. 评测与回归

### 9.1 golden trace 回归（CI 门禁）

录制真实会话 fixture，回放整条管线逐字段断言。覆盖：非标 JSON、伪 XML、超长输出、中英混排、半截流式、工具超时、插件崩溃、**日志损坏恢复**。

### 9.2 小模型指标卡（固定模型，保证可比）

固定：`qwen2.5-coder:7b`、`deepseek-r1:7b`、`qwen3-vl:4b`。50 任务集。

| 指标 | 目标 | 实测 |
|---|---|---|
| 工具调用**格式**解析成功率 | > 95% | 待填（S3） |
| 工具调用**语义**正确率 | > 85% | 待填 |
| 100 轮 token 占用 | ≤ 预算 95% | 待填 |
| 压缩后任务成功率 / 基线 | ≥ 90% | 待填 |
| P50 首响应（8B + prefix cache） | ≤ 1.0 s | 待填 |

### 9.3 内核基线（v1.1 新增，CI 强制）

| 指标 | 门禁 |
|---|---|
| 二进制体积 | ≤ 8 MB（>10 MB 失败） |
| 冷启动 | < 20 ms |
| 空闲 RSS | ≤ 15 MB |
| 事件写入 P95 | < 100 µs |
| 上下文组装 P95 | < 30 ms |

> 全部用 `criterion` 基准 + 固定硬件 runner，回归 >10% 即失败。

> **Windows 例外（v1.1.4 起）**：NTFS `FlushFileBuffers` + 实时防护使事件写入天然慢一个数量级，Windows 门禁为启动 P50 **< 100 ms**、事件写 P95 **< 10 ms**；Linux 仍为 20 ms / 100 µs。`bench --json` 返回 `platform` 与对应限值，不把 Windows 固定标红。

## 10. 技术清单（v1.1 新增，逐层）

### 10.1 内核（Rust）

| 用途 | 选型 | 备注 |
|---|---|---|
| 异步 IO | **`mio`**（默认，体积小）/ `tokio`（需要成熟生态时） | Linux 可换 `glommio`（io_uring） |
| 事件总线 | 自研 SPSC 环形队列（`ringbuf` 思路，单写多读） | 不用 `crossbeam` 全量（体积） |
| 序列化 | **`sonic-rs`**（JSON，SIMD）/ `rmp-serde`（msgpack 帧） | 不支持 SIMD 的目标回落 `serde_json`（见下） |
| 日志记录 | 自研（§3.1）+ **`crc32c`** | **CRC-32C / Castagnoli**（有 SSE4.2 / ARMv8 硬件加速）；**不是** `crc32fast`（那是 IEEE CRC-32，算法不同，不可混用） |
| 内存映射 | `memmap2` | 读路径、索引加载 |
| 并发原语 | `parking_lot`（快 Mutex）/ `once_cell` | 少用 `std::sync` |
| 容器 | `smallvec` / `arrayvec` / `hashbrown` + `ahash` | 小对象免堆分配 |
| SIMD | `wide`（稳定）或 `std::simd`（nightly） | 余弦、token 计数 |
| 哈希 | `blake3`（内容寻址）/ `ahash`（内部表） | |
| 错误 | 手写错误枚举（`thiserror` 仅在体积允许时） | |
| 时间 | `std::time::Instant` / `quanta`（更低开销 TSC） | |
| 正则 | **`regex-lite`** | 大正则需要时按需链入 |
| WASM 沙箱 | **`wasmi`**（解释器） | 体积待 S1 实测（**预估 0.6~1 MB，非 400 KB**）；不用 `wasmtime`（JIT 太大） |
| CLI | `clap`（`derive` 关闭，手写 parser 可再省 200 KB） | |
| IPC | `interprocess`（命名管道跨平台）/ `tokio::net::UnixListener` | |

> **平台覆盖与回退（勘误 R1）**：`sonic-rs` 依赖 SIMD 指令集（x86 AVX2 / ARM NEON），
> 而 §10.5 承诺 win/mac/linux × x64/arm64 全矩阵。
> 因此：**不支持 SIMD 的目标在构建时回退 `serde_json`**（feature gate `json-fallback`），
> 并把「四平台 × 双架构的体积 / 启动 / 吞吐矩阵」纳入 **S1 门禁**，实测后再定默认值。

**编译配置：**

```toml
[profile.release]
opt-level = "z"
lto = "fat"
codegen-units = 1
panic = "abort"
strip = "symbols"
```

交叉编译：`cargo-zigbuild`（复用 `zig cc`）或 `cross`（Docker）。
体积监控：`cargo bloat --release --crates`，纳入 CI。

## 11. 路线图（阶段 + 门禁，不排工期）

> 每阶段以**门禁（Gate）**为完成标准，而非日历时间。

### Phase 0 — 决策验证（3 个 Spike）

| Spike | 验证 | 门禁 |
|---|---|---|
| **S1** | Rust 内核最小骨架能否压到 **≤ 6 MB**（含 mio + sonic-rs + crc32c + wasmi），冷启动 < 20 ms | ① 体积与启动实测达标 ② **四平台 × 双架构矩阵**（含 sonic-rs 回落分支）实测 |
| **S2** | 自研追加日志的崩溃恢复（kill -9 注入 + 断电模拟） | 1000 次随机截断测试，零数据错乱 |
| **S3** | 真实 7B/3B 工具调用**格式**与**语义**错误率（50 任务） | 得到真实数字，回填 §9.2 |

### Phase 1 — 内核核心

事件日志 → 事件总线 → 插件运行时（进程外 RPC）→ 契约适配层 → 治理层（权限门/环境沙箱/卷守卫）→ TUI。

**门禁**：30 轮稳定对话；进程树级便携 diff 通过；网络盘/同步盘拒绝生效；内核 ≤ 8 MB。

### Phase 2 — 上下文引擎

Provider 统一接入 → 预算器 → 四层压缩 → 容错解析 → 约束解码 → 技能规范。

**门禁**：100 轮长会话预算稳定；S3 数字达标或触发降级预案；golden trace 全绿。

### Phase 3 — 存储、工具与安全

storage 插件（SQLite+FTS+向量三层）→ tool 系列 → MCP 双向 → 权限确认流程 → 崩溃恢复 → 归档/GC。

**门禁**：50 任务成功率达标；fork 确认流程评审通过；gc 后配额回落；日志损坏恢复演练通过。

### Phase 4 — GUI（独立产物）

前端契约定稿 → Web 前端（三栏 + 上下文面板）→ `--app` 启动器 → 存储设置/迁移向导 → 原生壳变体（可选）。

**门禁**：Web 前端在 Chrome/Edge/Safari 三浏览器通过；`--app` 窗口无边框正常；与内核版本矩阵解耦验证（旧前端连新内核）；GUI 包 ≤ 2 MB（gzip 资源）。

### Phase 5 — 分发与生态

三产物打包 → 版本矩阵与兼容声明 → 插件目录安装/启停 → 签名与供应链 → 文档。

**门禁**：开箱 ≤ 100 MiB；zip 迁移演练；三路径用例（中文用户名/全中文/260 字符）通过；`--allow-unsigned` 警告可见。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **Rust 首版周期长于预期** | 交付延迟 | 不排工期是本轮前提；且**回退路径明确**（§2.5）——插件/前端零改动 |
| Rust 体积压不到 8 MB | 卖点受损 | S1 提前验证；压不到就接受 10 MB 并把卖点表述改为"≤10 MB"，不做 `no_std` 自虐 |
| 自研日志格式出现数据错乱 | **最严重** | S2 做 1000 次随机截断；CRC32C + 头自校验；`.idx` 可重建；提供 `doctor --verify-log` |
| 浏览器 `--app` 依赖机器有 Chromium | GUI 受限 | 检测 + 引导；提供原生壳变体；文档明示 |
| SQLite 索引库落在同步盘损坏 | 数据丢失 | §3.5 卷守卫；索引可**从未损坏的日志全量重建**（这是日志/索引分离的额外收益） |
| S3 实测远差于预期 | 架构假设崩塌 | 约束解码优先 → 工具集精简 → 任务分步化 → 最坏降级为"无工具纯对话" |
| 插件契约演进破坏生态 | 生态返工 | 多版本适配层 + conformance suite；主版本 ≥6 个月窗口 |
| 内核追求体积导致可维护性下降 | 长期成本 | 明确红线：不做 `no_std`、不手写 allocator、不为省 200 KB 牺牲可读性 |

## 13. 一次请求的完整数据流

```
用户输入（TUI 或 GUI）
→ 前端契约 RPC → 内核编排核心
→ 写入事件 user.message（追加日志，组提交）
→ 总线通知 context-engine 订阅者（SPSC 游标）
→ context-engine 组装上下文：
     预算器裁剪 → L2 摘要卡 → L4 记忆召回（storage 插件进程，L0/L1 热层）
     → task_state 置头 → 已锁定技能集追加 system_tail
→ provider-ollama（进程外插件）流式请求（前缀命中 KV cache）
→ 增量 delta 双写：① 追加日志 ② 推给所有前端订阅者
→ 容错解析器提取工具调用 → 协作式权限门（dangerous → 前端确认）
→ tool 插件执行（进程外 RPC）→ 观察结果入日志 → 回注上下文 → 循环至 finish
   ├─ 用户取消 → 取消传播链（SIGTERM 3s → SIGKILL）→ tool.cancelled
   └─ 插件崩溃 → tool.failed(crash) → 重试/降级 → 继续
→ 索引器（storage 插件）异步 tail 日志，更新 FTS 与向量索引
→ 后台：超阈值会话归档（zstd）→ 无引用媒体 GC → 配额检查
（全程子进程在环境沙箱内，零用户目录持久写入）
```
