# FeatherAgent v1.2.1-rc.2 变更说明

日期：2026-11-24

`v1.2.1-rc.2` 是针对 v1.2.1-rc.1 Windows 真机复测报告的补丁版。R1 与 review-gate 流程保持报告确认的状态；本版修复 P0 provider 回归与同一轮发现的配置问题。

## 1. P0：provider 请求体为空（已修）

### 现象

`provider-ollama` 的所有请求都带空 body（Windows 抓包为 `Content-Length: 0`），真实 Ollama 返回 `400 missing request body`。`/api/chat` 与 `/api/embed` 同病；响应解析正常。

### 根因

HTTP 请求构造把可选 Authorization 头塞进了已经格式化的头块：

```text
Content-Type: application/json\r\n{Authorization 或空}\r\nContent-Length: ...
```

`provider_api_key` 为空时，空的 Authorization 在 `Content-Length` 之前留下一个空行。空行就是 HTTP 头结束标记，服务端因此看不到 `Content-Length` 和 JSON body；body 虽被写出，对端却当成下一段请求或直接忽略。带 Key 时不会出现空行，所以旧测试被掩盖。

### 修复

`src/net.rs::build` 改为逐行追加头：`Content-Length` 永远在可选 `Authorization` 之前输出，结束空行只在所有头写完后输出一次。`post_json_auth` 与 `stream_post_lines_auth` 共用这个构造器。

### 回归测试

- `net::tests::empty_bearer_preserves_headers_and_body`：分别用 `None` 与 `Some("")` 抓原始请求，断言 `Content-Length: 2`、body `{}`，且 `Content-Length` 前没有空行。
- `ollama_native_chat_without_key_still_sends_body`：真实内核 + mock Ollama、空 Key；断言 `/api/chat` 有 `Content-Length`、`messages`、`stream:true`，`/api/embed` 有 `model` 与 `input`。

Linux 实时 echo 复现已记录到非空 `/api/chat` 请求：CLI 模型 `qwen3.5:4b` 时 body 含 `"model":"qwen3.5:4b"`、`Content-Length: 6842`，并返回 `ECHO_OK`。

## 2. P1：review-gate 温度区间真正生效（已修）

`validate_config` 以前只在 `review_gate.enabled=true` 时检查三角色温度，导致关闭状态下 `config.set` 接受 `judge=0.8`、落盘，直到以后打开才报错。

现在区间是 schema 级约束，与 `enabled` 无关：

| 配置路径 | 允许区间 |
|---|---|
| `review_gate.guide.temperature` | `[0.2, 0.5]` |
| `review_gate.exec.temperature` | `[0.6, 1.5]` |
| `review_gate.judge.temperature` | `[0.0, 0.2]` |
| `review_gate.max_rounds` | `[1, 5]` |

错误同时带路径、提交值和区间，例如：

```json
{"jsonrpc":"2.0","id":3,"error":{"code":-32602,"message":"review_gate.judge.temperature=0.8 超出允许区间 [0.0, 0.2]"}}
```

非法值在 `cfg.save` 之前被拒绝，`config.json` 不会被改写。WebUI 现在即使未勾选启用，也会先校验三角色温度与轮次；后端仍是最终防线。

若 rc.1 的 `config.json` 已经存有越界温度，rc.2 不会静默夹紧：后续 `config.set` 或启用操作会被拒绝，需要先在 WebUI 或 JSON 中改到合法区间。

## 3. P2：启动时显示最终生效配置（已修）

`serve` 在 banner 后新增一行：

```text
effective model=qwen3.5:4b provider=provider-ollama base_url=http://127.0.0.1:11499
  (model_source=cli, provider_source=cli, base_source=cli)
```

CLI 参数与 `config.json` 不同时还会打印：

```text
warn: --model 覆盖 config.json 的 qwen2.5:7b（实际使用 qwen3.5:4b）
```

运行时使用 CLI 值，warning 让优先级可见，不再静默沿用持久化值。`config.get` 返回同样的最终值。

### 关联修复：embedding 使用当前模型

复现时发现 `/api/embed` 仍请求 provider 默认的 `qwen2.5:7b`，而 chat 使用 `qwen3.5:4b`。`recall` 与 `index_user_text` 现在把 `cfg.model` 传给 embed，provider 按该模型请求，避免向 Ollama 请求一个用户没选的 embedding 模型。
