# FeatherAgent v1.2.1-rc.4.5 — Changes

Release candidate, 2026-11-26. This patch addresses N29–N31 from the rc.4.4 Windows retest. It does not replace a stable release.

## N29 — write-file tasks skip the hard-criteria gate

The rc.4.4 retest still produced `review.finished status=degraded rounds=0` for:

> 请用工具把三条关于「内存管理」的要点写入 workspace/notes3.txt，每条一行，以「- 」开头

The file was written, but the guide was rejected twice: first because the whole rubric had no hard criterion, then because `must_include:["-"]` was a one-character term under the “terms must be at least two characters” rule. Three rules conflicted: hard criteria are mandatory, terms must be ≥2 characters, and file tasks go to the judge.

Fix: when the parsed rubric has `file_task: true`, `parse_rubric_with_input` keeps only `id/criterion/check/weight/judge_only/file_task`, strips every deterministic key (`must_include`, `must_not_include`, `min_points`, `pattern`, `regex`, `hard`, `match`, `min_matches`), adds the IDs to `judge_only`, and continues. The guide prompt now tells file tasks to emit only `criterion/check`, with no hard keys or file-body guesses. `review_prepare` no longer retries a file task for having zero hard items.

Tests: `review_rubric_file_task_bypasses_symbol_term_limit`; the `REVIEW_WRITE` fixture now returns the N29 bad-symbol rubric (`must_include:["-"]`, `min_points:3`, `pattern:"(?m)^- "`), and the integration test still requires `approved` with judge `votes>0`.

## N30 — Windows write gate becomes advisory at the edge

The rc.4.4 report saw `write_p95_lt_10ms` occasionally red while `reliability` stayed `high`. The benchmark still completed, so a single edge sample should not turn the whole run red.

Fix: `bench` computes `write_p95`, `write_raw` and `write_margin`. On Windows, a P95 below twice the 10 ms limit is `advisory`; above 20 ms still `fail`. A low-trust host within four times the limit is also `advisory`. The platform write key uses the effective result, and `gates` gains `write_gate_status` (`pass|advisory|fail`) and `write_gate_raw`. Linux keeps the 100 µs limit.

Test: `write_gate_marks_windows_edge_jitter_as_advisory`; CI now rejects a missing or invalid `write_gate_status` / `write_gate_raw`.

## N31 — L17 recognises bold numbering

The large-1 paper scored L17 1.5/3 because the list regex accepted only `1.`, `-` and `*`, not `**1.**`. The scored answer actually had all three items.

Fix: `docs/model-test-reports/exam-papers/large-1.json` now accepts `**1.**` alongside the other list forms. This is a test-scoring change, not a product change. Historical rc.4.4 scores stay as recorded.
