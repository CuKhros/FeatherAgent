# FeatherAgent v1.2.1-rc.4.7 Changes

> Baseline: `v1.2.1-rc.4.6` (commit `0d7f4a7`)
> Source: Windows real-machine retest report for v1.2.1-rc.4.6, findings N36–N39; plus two new public math papers
> Date: 2026-11-26

## Summary

The rc.4.6 retest confirmed N32–N35 on real hardware and exposed four new findings:

- **N36 (🟠)**: the judge evidence floor of 10 characters was too strict for short Chinese. `"三条要点已写入文件"` is 9 characters, so one of three write-task runs degraded.
- **N37 (🟠)**: math tasks try `tool.shell` with sympy, but the default permissions did not allow it; the model was denied and returned an empty answer. This is a harness prerequisite, not a permission bypass.
- **N38 (🟡)**: FA occasionally stops after a title (MS2 37 characters, ML02 109), with `truncated=false`; the model stopped itself, not the output cap.
- **N39 (🟡)**: math scoring is sensitive to formula spelling; LaTeX variants such as `\frac{\pi^2}{6}` need multi-pattern coverage.

rc.4.7 fixes N36, adds an explicit stop signal after tool denial and documents the math-run prerequisite for N37, mitigates N38 with the system prompt, records N39 as a scoring-coverage limitation, and archives the `math-small` / `math-large` papers plus the rc.4.6 report in the public repository.

## N36: separate Chinese and English evidence floors

**Observed.** `parse_verdict` required `chars().count() >= 10` for every item and for the top-level summary. The 9-character Chinese quote above is verbatim answer text, yet it was rejected as "evidence too short"; two judge retries still failed and the turn degraded.

**Fix.** `src/review.rs` now uses `evidence_shape` / `evidence_is_substantive`:

- Chinese: at least **6 CJK characters**;
- English: at least **3 English words**;
- or at least **10 ASCII alphanumeric characters**, so identifiers such as `REVIEW-FINAL`, long paths and single tokens remain valid evidence.

The contiguous quote window drops from 10 to 6 characters; `"总结"`, `"通过"`, `"ok"` and prompt echoes still fail. The judge prompt, review reinjection text and error messages now say "6 CJK characters (3 English words)".

**Verification.**

- `verdict_accepts_short_chinese_evidence`: a 9-character Chinese quote passes.
- `verdict_accepts_three_word_english_evidence`: three English words pass.
- The existing `review_verdict_short_or_prompt_echo_evidence_is_rejected`: `"总结"` and prompt echoes still fail.
- All review-gate integration fixtures pass again; a long identifier such as `REVIEW-FINAL` is still accepted.

## N37: stop signal after a denied tool

**Observed.** ML10 needs trig substitution; FA tried `tool.shell` with sympy, but that run allowed only `tool.fs.write,tool.fs.read`. The shell call was denied, the model did not switch to prose, and the answer scored 0.

**Fix.**

- A `permission_denied` `tool.result` now carries `hint`: `该工具未获授权，不要重复调用同一工具；请用文字完成当前任务，或明确说明需要用户授权。`
- The system prompt now requires a checkable derivation for math/proof tasks and tells the model not to retry the same denied tool.
- The docs state the harness prerequisite: to let FA use sympy, start `serve` / `chat` with `tool.shell` allowed; otherwise score the prose derivation and do not treat "wanted a tool but was denied" as automatic permission escalation.

This is not a security change: `tool.shell` remains dangerous and needs explicit authorization. The code only improves post-denial behavior; it never auto-elevates.

## N38: math-derivation completeness prompt

**Observed.** MS2 returned 37 characters and ML02 109, both with `truncated=false`; the model stopped after a title or a one-line conclusion.

**Fix.** The system prompt now requires math/proof/derivation answers to go from givens/assumptions through each transformation to the conclusion, not stop at a title or final answer. This release deliberately does not add an "auto-continue when the answer is short" hard gate, to avoid forcing an extra round on simple calculations. N38 remains prompt-mitigated and needs a real 4B/7B retest.

## N39: math scoring boundary

**Observed.** The math papers score regex coverage, so formula spelling (`π²/6`, `pi^2/6`, `\frac{\pi^2}{6}`) can miss.

**Handling.**

- ML02 in `math-large` already accepts three forms; other questions keep their multi-pattern rules.
- `exam-papers/README.md` now explains that scoring reflects coverage, not correctness, and that absolute scores are not a math accuracy rate.
- The local runner and historical results remain out of the repository; only paper JSON is published.

## Compatibility

- No new frame, endpoint, event kind, or error code.
- A `permission_denied` `tool.result` adds `hint`; old clients may ignore it.
- Judge evidence length changes from "≥10 characters" to "6 CJK characters / 3 English words / 10 ASCII characters"; `review.verdict` fields are unchanged.
- The system prompt adds a math-derivation requirement; the wire contract is unaffected.

## Not verified

- N36 still needs a real 7B/9B judge on Windows; current evidence is unit, mock and Linux integration.
- The benefit of allowing `tool.shell` on math papers is unmeasured; this round only verifies the denial hint and the prose-derivation prompt.
- Whether N38's prompt mitigation lifts MS2/ML02 above 37/109 characters needs a real-model retest; if not, continuation or stronger sectioning is required.
- N39 remains a scoring-rule limitation, not a product correctness claim.
- English WebUI attachments, TUI feel, high DPI, proxy, network-drive/24h and macOS/arm64 remain untested.
