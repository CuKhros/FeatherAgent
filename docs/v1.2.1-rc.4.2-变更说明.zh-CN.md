# FeatherAgent v1.2.1-rc.4.2 变更说明

2026-11-25 候选版。本补丁修复 rc.4.1 Windows 复测的 N15–N18。真机确认 N10、N12、N13 已修；N11 的纯文本形式已修，但 XML 风格未覆盖。本候选版不替代稳定版。

## N15：XML 风格工具调用从“整轮失败”改为可恢复

rc.4.1 复测中，Qwen/Ollama 的函数式标签风格调用触发了 XML syntax error，整轮以 `chat.finished status=failed` 结束，但 `workspace/notes.txt` 其实已经写成功。

现在有两层处理：

- 上下文解析器接受 `=` 或 `name="..."` 形式的 function 标签，以及 `=` 或 `name="..."` 形式的 parameter 子标签；参数值读到 parameter 结束标签，缺失 function 结束标签也能解析；工具别名按 N11 规则归一化；
- Ollama provider 不再把每个流式 `error` 或 HTTP 500 都直接变成终止错误。若已累计文本里出现 function 标签，先尝试解析；恢复出的调用会进入 `native_calls`，流以 `tool_calls` 结束，而不是 `failed`。解析失败时仍上报原始错误，并保留原有 `tool_format` 纠正与重试预算。

测试：`xml_function_parameter_fallback`、`malformed_xml_function_without_close_is_recovered`；原有纯文本与别名测试继续通过。

## N16：bench RPC 连接跨过 Windows 命名管道创建窗口

rc.4.1 复测中 bench 仍有约 1/2 失败，唯一临时 RPC 目录下的 `featheragent.sock` 报“系统找不到指定的文件”。唯一临时目录已生效；剩余缺口在 `wait_ready`（探测连接一次后断开）与 bench 自己 `Client::connect` 之间。

修改：

- Windows `ipc::connect` 在 3 秒预算内，除 `ERROR_PIPE_BUSY` 外，也重试 `ERROR_FILE_NOT_FOUND(2)` 与 `ERROR_PIPE_NOT_CONNECTED(233)`，用短暂 sleep 代替忙等；
- `bench` 显式创建 `rpc` 目录，并在 `wait_ready` 后对 `Client::connect` 做最多 10 秒有界重试，不再只连接一次；
- `[bench:rpc_connect]` 错误保留 socket 路径与最后一次 OS 错误。

这是有界重试，不是无限等待。Linux bench 行为不变；Windows 仍需真机复测。

## N17：`boot_gate_trusted` 移出常规门禁计数

`boot_gate_trusted` 是环境质量信号。rc.4.1 报告里它为 false、`reliability="low"`，人工把 `gates` 里所有布尔值相加得到 9/10，看起来像版本回归，但实际发布门禁全部通过。

`bench --json` 现在拆分：

- `gates`：只放发布门禁，移除 `boot_gate_trusted`；
- `advisory_gates`：`boot_gate_trusted`、`boot_gate_status`、`reliability`，明确不参与 `passed/total`；
- `metrics`：保留 `boot_gate_trusted` 供诊断。

人类可读输出在门禁对象旁单独打印 `advisory (not counted in gates)`。中英内核同步。N9 的 advisory 语义本身不变：低可信度的启动测量不会把启动门禁判红。

## N18：“简洁”不等于“省略要点”

rc.4.1 的 4B 对比中，FeatherAgent 与裸跑质量同为 15/16，但 FeatherAgent 约快 2.1 倍（49s vs 104s）。剩余质量差距在覆盖面上：系统提示里的“回答简洁”让列举/答题类任务少覆盖“有序/开销”等要点。

系统提示现在明确：

- 默认简洁、工具优先、不要臆造；
- 用户要求列举、比较、穷举或说明全部要点时，覆盖全部要点，不要因简洁而省略。

测试：`system_prompt_distinguishes_brevity_from_coverage`。
